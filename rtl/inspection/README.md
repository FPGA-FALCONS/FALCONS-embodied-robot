# 任意角度导航：独立线段检查组件

`nav_supercover_check.v` 是可例化的同步 RTL 组件，尚未接入生产 `nav_top`，也不在当前上板工程中。它验证两个格中心之间的**整段**，支持任意斜率；不是完整规划器或车辆跟踪器。

## 接口和使用

1. `start_valid/start_ready` 接受一条线段，锁存起终点、`map_revision`。输入是无符号格坐标，16 位端口可显式拒绝越界，合法地图每边 1～256 格。
2. `map_req_valid/map_req_ready` 发出一个 `(map_x,map_y)` 查询，最多一个未完成读；`map_resp_valid/map_blocked` 在**后续**时钟返回结果。`map_blocked` 应查询雷达 cost 与视觉 cost 的 OR，输入地图应已包含车体尺寸和误差膨胀。
3. `result_valid/result_ready` 返回结果，受背压时结果码、版本与计数保持不变。码值：`0=clear, 1=blocked, 2=stale, 3=invalid_endpoint, 4=cancelled`；`checked_cells` 为已接受的查询数，包括遇障时最后一次查询。

只允许把 `result_code==0` **且** `result_revision==当前融合地图版本` 的结果用于该条线段；在消费结果和后续执行前都要复核版本及其他车辆授权条件。完成等待期间地图变更不会改写已经返回的结果，旧版本由消费者拒绝。

在 ISSUE、等待读响应或步进期间检测到版本变化，结果置 stale；取消置 cancelled。若有未完成读，先排空该响应再返回，避免下一条线段误吃旧响应。地图必须最终响应；本组件不把等待超时伪装成 free。系统复位时外部读适配器必须同步复位/冲刷，不能跨复位遗留无标记响应。

查询接受后应返回该次地址的数据；禁止组合零周期应答。读请求及结果在等待时保持；cancel/版本失效可撤回尚未接受的读。地图任何内容变更都必须使版本变化，版本在一个事务及结果使用期间不能回绕/复用。需要多源地图时用统一事务版本，不能用两个版本的 XOR 充当唯一标识。

## 几何和资源边界

使用增量交叉误差递推，只需加减与比较，无乘除法、无路径 RAM。格为闭合单位方格；穿越格顶点必须检查左右两个侧格，禁止从障碍角缝穿过。起点、终点均查图；同格线段也查一次。端点合法时线段在端点矩形内，不会走出地图。

256×256 地图单段最多 766 次读请求；这是几何查询上界，**不是延迟保证**，总耗时包含所有内存等待。综合面积、Fmax、布线与实车间隙均未测。

## 验证

仓库根目录运行（已有 Icarus `iverilog`、`vvp`）：

```text
python host/inspection_reference/verify_rtl.py
```

当前 461 个仿真用例、8,771 次实际接受读：固定随机任意斜率、全图长对角线/反向/近水平与近垂直线、同格、边界、逐个触及格置障碍、三个活动阶段取消/改版本、读响应排空与完成背压。预期格集合来自独立的有理数线段/闭合 AABB 求交，不调用 RTL 的递推算法；脚本保存输入及源码哈希，失败返回非零。
