# HT-10A 手柄接线、参数与验收（2026-10-16）

## 1. 本次约定与实现边界

用户已确认：CH2 右摇杆上下为油门，CH4 左摇杆左右为转向；CH5/SWA 确认，CH6/SWB 模式，**CH7/SWC = select**，**CH8/SWD 闲置不接**。CH1、CH3 不接本轮驾驶/按钮输入。

> ★ **2026-10-16 合并裁定（需求方）：没有"返回"按钮。**
> 因此 **J6.4 / bit3（原记 CH7/SWC"返回"）改作 select**，**J6.6 / bit5（原 CH8/SWD）闲置**。
> 代码侧：`CH_SELECT = 3`、删除了 `CH_BACK` / `BACK_ACTIVE_LOW` / `o_btn_back` 与整条 back 事件链；
> 并且 **bit5 被排除出"信号有效"判定**（`SIG_VALID_MASK = 6'b011111`）——
> 否则该路悬空时 `timed_out` 恒 1，会把 `o_signal_valid` 永久拉低、**整车永不能动**（且只报"无信号"）。

依据：用户本次聊天确认、《HT-10A操作手册.md》、本仓库需求原文及 `doc/ACG720_引脚接线手册_RevI.pdf` 第5页。开关物理档数、脉宽、按下极性和无线失联输出尚无实测记录，下面数值均是可调开发默认值。

沿用上层接口 `o_steer/o_throttle`（signed 12位，-1000..1000）、两档 `o_mode`、**两个单周期按钮事件（select / confirm）**及菜单上下事件。没有增加自动档，也不实现路径点存储或导航。select 事件已生成，但现有导航页未实现，整车顶层暂不消费它（顶层把它显式接进未用汇总）。

> ★ **遥控事件（按钮 / 菜单拨动）的有效性与档位门控集中在 `rc_input` 的 `cursor_ready`**：
> 要求「信号有效 + 模式通道档位**连续 2 帧已确认** + 处于光标档」；
> **整车顶层不再重复门控**（单一真源）—— 要改门控请改 `rc_input`，不要在 `falcons_top.v` 里加第二道条件。

`vendor/verilog-reusable-modules` 与旧模块库均未改。`rtl/rc/rc_input.v` 复用现有单路捕获；`ht10a_input.v` 定义本车输入配置；`rc_drive_guard.v` 管理手动解锁。三者均不包含厂商原语和物理管脚。

## 2. 必须按这张表接：接收机 CH ≠ 转接板 J6 槽位

J6 手册上的 CH1..CH6 是转接板六个输入的标签，不代表必须接收机的 CH1..CH6。

| 接收机信号（先经电平转换） | 功能 | 转接板针号 | 顶层位号 | FPGA管脚 | J1正式Pin |
| --- | --- | --- | --- | --- | --- |
| CH4 | 左摇杆左右 / steering | J6.1 | i_rc_pwm[0] | D19 | 5 |
| CH2 | 右摇杆上下 / throttle | J6.2 | i_rc_pwm[1] | E19 | 6 |
| CH5 / SWA | 确认 confirm | J6.3 | i_rc_pwm[2] | E18 | 3 |
| **CH7 / SWC** | **select**（★ 此位不再是"返回"） | J6.4 | i_rc_pwm[3] | F18 | 4 |
| CH6 / SWB | 手动 / 光标（模式，两档拨杆） | J6.5 | i_rc_pwm[4] | F20 | 1 |
| **CH8 / SWD** | **闲置不接**（已排除出"信号有效"判定） | J6.6 | i_rc_pwm[5] | F19 | 2 |

本次未改变任何 IO_LOC / IO_PORT，只补充约束文件的槽位说明。

> ★ **不要把转向（CH4）接到 J6.4** —— 那一槽位现在是 **select**；接错会表现为"打舵触发选页"。

J6 只有信号；电源从合适的电源接口单独供给。RevI 手册 J9：1=5V，2=3V3，3=GND；手册所列供电余量不是已实测的接收机预算。F-10A 按用户资料为4–9V供电，按实际规格供电；接收机、转换模块、FPGA共地。转换模块的高低压侧按其型号连接，确认送入FPGA的逻辑电平不超过该bank的3.3V规格。未提供转换模块型号，因此本次不能认证其接法/速度/上拉配置。

构建沿用仓库 GW5AT-138B / GW5AT-LV138PG484AC1/I0。用户提供的手柄手册标题写138C，与工程B不一致；下载前以芯片丝印和本车已验证设置为准。不能把B/C版本差异当成通配符。

## 3. 参数在哪里改

本车覆盖值集中在 `rtl/top/falcons_top.v` 的 `u_rc` 例化；默认配置和槽位定义在 `rtl/rc/ht10a_input.v`。通用输入适配层保留 `CH_*` 参数，但它们是零起始的输入槽位索引，而不是接收机通道号。

| 参数 | 默认值 | 标定方法 / 语义 |
| --- | --- | --- |
| STEER_CENTER_US / THROTTLE_CENTER_US | 各1500 | 分别测CH4、CH2的回中值，不能用历史CH1=1499替代 |
| STEER_HALF_RANGE_US / THROTTLE_HALF_RANGE_US | 各500 | 各自中位到端点的量程；当前是对称量程模型，非独立左右端点模型 |
| STEER_DEADZONE_US / THROTTLE_DEADZONE_US | 各25 | 中位±该值内输出0；须小于对应半量程 |
| STEER_REVERSE / THROTTLE_REVERSE | **STEER=1 / THROTTLE=1** | 按实物车辆方向决定，不能凭通道名推定。★ **2026-10-17 两轮上板标定**：第一轮"推杆向前车反而后退"→ `THROTTLE_REVERSE=1`；第二轮"**左右也跟着反了**"→ 再 `STEER_REVERSE=1`。改在顶层 `falcons_top.v` 的 `u_rc` 例化处，**不是** `ht10a_input.v` 默认值；**不要**用 `INV_DIR_VEC` 改。⚠ 转向随油门翻转的原因尚未解释，疑为 A/B 通道与物理左右轮映射不符 —— 详见 `doc\工作记录.md` §26.5 |
| MENU_REVERSE | 0 | 独立调整上下菜单方向；不受油门方向反转参数影响 |
| MIN_PULSE_US / MAX_PULSE_US | 900 / 2100 | 捕获合法高电平宽度，含边界；超出立即撤销该路有效性 |
| TIMEOUT_US | 100000 | 最后一个合法完整脉冲之后100ms失效；非法脉冲不刷新计时 |
| SW_LO_US / SW_HI_US | 1300 / 1700 | 区分低/中/高输入区间，非实测开关档位 |
| SW_HYST_US | 30 | 低档进入<1270、退出>=1330；高档进入>1730、退出<=1670 |
| SW_CONFIRM_FRAMES | 2 | 相同分类连续两个完整有效帧才确认；不是两个时钟周期 |
| MODE_REVERSE | 0 | 0：低档手动，其余光标；1：高档手动，其余光标；失效始终光标 |
| SELECT_ACTIVE_LOW / CONFIRM_ACTIVE_LOW | 各0 | 0为高档按下、1为低档按下；按实物修改。★ 只剩两个按钮参数（`BACK_ACTIVE_LOW` 已随"无返回按钮"删除）；**`SELECT_ACTIVE_LOW` 作用在 bit3（J6.4）** |
| MENU_STEP_TH / MENU_IDLE_TH | 400 / 150 | 超过±400触发一次，必须有一帧输入回到±150才能再触发 |
| rc_drive_guard.ARM_DEADZONE | 100 | 顶层u_rc_guard参数；归一化油门±100内可解锁 |

归一化采用死区扣除、常量Q10比例、正负对称向零截断、±1000限幅；中位/半量程/死区分别独立生效。偏移、乘法、限幅分开流水，避免恢复“组合乘法串进底盘”的长路径。`o_signal_valid` 等待四拍流水就绪后才拉高，防止用启动时的暂态0错误解锁。

原先固定×2.125没有使用HALF_RANGE_US；本轮改成按实际参数计算系数。默认±250us偏移现在对应约±473，而非旧近似值±478。

## 4. 模式、事件与停车行为

- **参与判定的五路**（bit0~bit4；参数字面量 `SIG_VALID_MASK = 6'b011111`）必须全部有合法新鲜输入，信号才有效；缺任何一路都不能开车 —— 不是只接 CH2/CH4 两根线即可。**bit5（J6.6）闲置、已排除出判定**：它悬空不影响开车（原实现要求"六路全有"，会让整车永不能动且只报"无信号"）。
- 上电无脉冲、非法脉宽、超长高电平、任一路超时：两路驾驶量归零，模式回光标，按钮和菜单事件抑制。
- 仅在有效光标模式生成UI事件。复位、断线恢复、从手动进入光标后，按钮必须先实际释放，再按下；启动时保持按下不产生幽灵点击。
- 摇杆必须先观察到回中，才能生成一次菜单拨动。持续压杆不连翻；直接从正端跳到负端不算回中。
- 手动模式且信号有效，油门回中后解锁；之后推油门仍保持解锁。切出手动、丢输入、急停或S1停止后撤销解锁，再次运行须重新回中。
- S1是停机锁存/解除，切出手动清除S1锁存；S4沿用原急停锁存。解除急停时若油门仍偏置，不会自动重新解锁。
- **PWM有效 ≠ 无线在线。** 若关闭发射机后接收机保持合法的旧油门，RTL单凭这些 PWM 通道不能发现无线掉线。必须实测并配置接收机failsafe（例如油门/转向回中、模式转光标），或另接可靠失联信息；没有实测不能写"关遥控一定停车"。**注意"拔掉接收机"与"关闭发射机"是两种不同故障，验收要分别测。**

## 6. 下午实物验收：每步记录实际结果

1. **先断开电机动力或保持驱动禁能**。确认芯片版本、转换模块接法、共地和信号线重排（**参与判定的五路：bit0~bit4；J6.6 空置**）；先下载SRAM。
2. 用串口115200/8N1看原有12列CSV：末四列是 `steer,throttle,mode,sig_ok`。CH4单动只改steer，CH2单动只改throttle，同时移动不串路。LED3指示**参与判定的五路**有效；LED5:4显示0/1模式。
3. 记录CH2/CH4最小、中位、最大实际脉宽（用示波器/逻辑分析仪，或此前已验证的脉宽读取工程）；默认值不是标定结果。检查归一化两端、死区和实车方向，修改顶层参数后重跑测试和构建。
4. 模式置光标，油门上下切高亮；CH5确认切页。上电或切模式时保持确认不应误切页，释放后再按才切页。**CH7（J6.4）现在是 select**：事件已仿真，但导航页未实现，屏幕上不会出现 select 效果；原12列CSV也没有事件列。**CH8（J6.6）闲置、无事件**。
5. **车轮架空**，模式置手动：偏置油门切入不得转，回中解锁，再推杆应持续转；S1停/解除、S4急停/解除、切档和重新回中分别验收。
6. 断一根**参与判定的**信号线（bit0~bit4）→ 信号有效应撤销、驾驶量归零；**断 J6.6（bit5）应无影响**（已被掩码排除）。分别测试关发射机和拔掉接收机，两者不是同一故障。只要关发射机仍保持驱动命令，就先解决failsafe，不能落地。
7. 前述全部完成后才低速下地；电机方向、编码器极性和PID仍按队友的电机验收流程确认，本轮没有实测这些项目。
