## RK独立UVC摄像头准备与验证

日期：2026-10-25。用户要求连接RK、读取免驱UVC摄像头，并准备相关代码。本次只准备相机入口和验证工具，不启动巡检、模型识别或运动。

<a id="report-01--实际设备与接入"></a>
### 实际设备与接入

- RK通过热点发现于 `192.168.83.31`，使用原SSH主机密钥核对连接；本机 `falcons-rk3588` 别名已更新地址。
- USB标识 `0bda:5856`，名称Realtek USB Cam，序列号 `200901010001`，内核驱动 `uvcvideo`。当前通过Bus005、EHCI、480M连接，是USB2高速链路。
- 图像设备稳定路径：`/dev/v4l/by-id/usb-Generic_USB_Cam_200901010001-video-index0`，本次对应 `/dev/video20`。
- `video-index1` 对应 `/dev/video21`，其 **Device Caps只有Metadata Capture，没有Video Capture**。这是同一摄像头的元数据节点，不是第二只摄像头。
- 本次不是双目部署，未验证硬件同步。两只同型号相机若序列号重复，应使用各自by-path标识并重新核对，不能根据video编号或节点数推断相机数量。
- 板端已有OpenCV 4.12.0、v4l2-ctl，沿用现有Python/驱动/模型环境，没有安装或升级软件。

<a id="report-01--新增准备工具"></a>
### 新增准备工具

入口为 `host/ai_coordinator/uvc_prepare.py`，支持：

1. `probe`：只读sysfs、QUERYCAP、格式及控制项，不启动视频流；过滤RK内置ISP/CIF，合并同一节点的by-id/by-path别名，区分图像与元数据节点。
2. `capture`：要求显式稳定设备路径及实测支持的分辨率/帧率/FOURCC，不猜video0。取帧在独立子进程中运行，遇到断开、格式降档、图像尺寸/类型异常或超时即失败。
3. 先完成采集测速，再保存首/中/末三张PNG及SHA256，避免磁盘编码影响间隔统计。记录主机收帧率及间隔，不冒充曝光时间戳。
4. `--fixed-frame-rate`：仅临时修改 `exposure_dynamic_framerate`，先读取原值、设0并核对；无论正常退出、采集错误或超时，都尝试恢复原值并读回。恢复失败明确报错，不报告成功。
5. 成功后输出关闭状态的 `camera.candidate.json` 和 `camera.preconditions.json`，不覆盖正在运行的服务或配置。

现有 `v4l2_camera.py` 保持不变，仍可使用同样的稳定路径和模式。它**不会自动应用准备工具记录的曝光控制项**；因此候选配置不是直接启用就保证30fps的配置。后续正式接入须明确应用/核验前置控制条件，再确认图像时效和资源占用。

<a id="report-01--声明模式与实际帧率"></a>
### 声明模式与实际帧率

摄像头声明MJPG的640×480、1280×720、1920×1080等模式均为30fps。YUYV则随尺寸降速，例如1280×720为8fps、1920×1080为5fps。使用USB2时本次选择MJPG，不把这些声明值当成实测。

| 模式 | 连续采集帧数 | 主机实测 | 判断 |
| --- | ---: | ---: | --- |
| 640×480 MJPG，原动态帧率开 | 150 | 19.97fps | 取帧正常；未达到30fps的80% |
| 1280×720 MJPG，原动态帧率开 | 300 | 20.20fps | 取帧正常；未达到30fps的80% |
| 1920×1080 MJPG，原动态帧率开 | 150 | 19.96fps | 取帧正常；未达到30fps的80% |
| 1280×720 MJPG，临时关闭动态帧率 | 300 | 30.01fps | 初次固定帧率对照通过，控制项已恢复 |

初次720p固定帧率实测主机间隔中位32.03ms、P95为36.04ms、最大51.61ms。是约10秒样本，不等于长时间无丢帧或传感器同步验收。样例图已下载查看，可正常解码，视野中为桌面和地面；当前安装姿态及曝光条件不是最终巡检标定状态。

补齐自动控制恢复后，最终工具再次在RK取300帧，实测29.96fps，原动态帧率1已由工具恢复并读回确认。22项板端相关测试全部通过；本机同组22项中1项Linux专用检查跳过。另直接调用现有 `Camera` worker读取3张真实1280×720图像，证实候选路径/模式可接入现有入口；没有加载检测模型或发送运动。

<a id="report-01--使用方式"></a>
### 使用方式

准备源码部署在独立目录，使用以下入口；输出路径必须全新，避免覆盖历史证据：

```bash
export UVC_ROOT=/home/orangepi/workspace/falcons_uvc_prepare_20261025_v2
export PYTHONPATH="$UVC_ROOT/host:/home/orangepi/workspace/falcons_ai_coordinator_20261024_r1/python"

python3 -m ai_coordinator.uvc_prepare probe --out /tmp/uvc_probe_new.json

python3 -m ai_coordinator.uvc_prepare capture \
  --device /dev/v4l/by-id/usb-Generic_USB_Cam_200901010001-video-index0 \
  --width 1280 --height 720 --fps 30 --fourcc MJPG \
  --frames 300 --timeout 35 --fixed-frame-rate \
  --out /tmp/uvc_720p_new
```

`result.json`给出进程结果、测得帧率及控制恢复状态；`summary.json`保存原始模式/控制信息、协商结果、取帧数和间隔；三张PNG用于检查方向、清晰度及视野。工具默认以测得帧率达到请求值80%作为本次取帧准备的通过条件，不等于运动准入判据。

<a id="report-01--标定与后续边界"></a>
### 标定与后续边界

自动曝光当前为Aperture Priority、动态帧率原值1、连续自动对焦原值1；本次只为帧率对照临时改动态帧率，未固化曝光/焦距。正式地面定位前应完成相机安装，固定并验证对焦状态，在最终分辨率/裁剪/方向下重新标定内参、畸变和车体外参。

所有结果保持 `source_timestamp_verified=false`、`metric_calibration_verified=false`、`stereo_sync_verified=false`。UVC免驱只说明设备可由已有驱动访问，不证明深度、曝光同步、米制定位或安全运动能力。FPGA摄像头不参与此次取帧，也不上传RK。

操作前后比较正在运行的配置、active_release和用户服务文件SHA256，以及服务PID/重启数、相机状态。首次测试中这些项目完全一致：服务PID1647、重启数0、模型就绪；正式服务仍为相机disabled，未切换发布。最终验证和工具源码清单见 [证据目录](../../evidence/rk_uvc_prepare_20261025/README.md)。本次没有修改RTL、构建或烧录FPGA，没有打开底盘控制串口或发送运动指令。

接口依据：[V4L2 QUERYCAP](https://docs.kernel.org/userspace-api/media/v4l/vidioc-querycap.html)、[格式枚举](https://docs.kernel.org/userspace-api/media/v4l/vidioc-enum-fmt.html)、[OpenCV VideoCapture属性](https://docs.opencv.org/4.x/d4/d15/group__videoio__flags__base.html)。节点识别以设备专属Device Caps为准，不误用包含元数据节点在内的整设备Capabilities。

<a id="report-02--开机自启与模型就绪"></a>
### 开机自启与模型就绪

`host/ai_coordinator/start_board.sh`启动现有协调器，复用板端隔离Python目录和本地模型。`install_autostart.py`准备并安装同名用户服务，不额外创建第二个串口所有者。启用用户服务及systemd linger后，无需SSH登录即可在Linux启动后运行。

启动配置位于`ai_module.example.json`的`startup`段：

- 必需模型：现有SenseVoice语音识别、C1b语义理解、Qwen3.5 0.8B聊天、完整Kokoro语音合成。
- 若配置了YOLO，尝试预加载视觉模型；相机未连接不影响模型加载，视觉模型单独失败也不封锁语音与聊天。
- 所有必需模型通过工作进程就绪检查后，向`plughw:CARD=Device,DEV=0`播放一声1175Hz、0.20秒提示音。不打开麦克风，不解析任务，不开启FPGA的AI总开关，不产生运动指令。
- 必需模型失败时不鸣音，保留服务和页面并每5秒重试。扬声器失败不撤销模型就绪状态，在AI未活动时重试提示音，成功后本次服务生命周期内不重复鸣音。
- 模型在AI关闭或切换功能后保留加载状态；取消推理时被终止的工作进程会在空闲后补载，不重播成功提示音。进程退出或服务停止仍会释放资源。
- 模型加载期间页面仍可选择功能，显示加载状态。服务重新启动后直接接受FPGA当前AI开关状态，不要求先关再开；SWB已下拨时仍需先上拨再下拨开始新的录音，旧任务不重放。

`/status`的`startup`字段报告加载阶段、每个模型的加载时间、错误及提示音播放状态。`ready=true`表示必需模型工作进程已加载，不等于运动、视觉或真人语音验收通过。

<a id="report-02--手动接管与下一项任务"></a>
### 手动接管与下一项任务

| 场景 | 页面与总开关 | 任务与恢复 |
|---|---|---|
| AI任意子功能切SWC手动 | 留在当前AI页面，保留总开关、已确认功能和高亮项，菜单继续冻结 | FPGA立即撤销自动驱动并执行原停稳/回中接管；RK取消当前录音、推理、播报和识别，显示已暂停 |
| 手动期间 | 页面和已完成的指令/聊天回复保留 | 遥控交互仍只用于手动驾驶；不开始AI录音或自动任务 |
| 切回光标档，SWB保持下拨 | 不退出、不切回默认功能 | 不恢复旧运动、播报或录音；先上拨再下拨才能开始新录音 |
| 切回光标档后选择功能并SWA确认 | 在本页重新选择/确认 | 取消残留作业，进入所选功能；同一功能也能明确重新确认 |
| 目标识别从手动返回 | 仍在目标识别页，等待新任务 | 不自动恢复旧相机循环；再次SWA确认或完成一段新的目标语音才启动识别 |
| SWA返回、离开AI页、S1/S2、急停、遥控失效或RK断连 | 沿用原显式退出/故障关闭规则 | AI关闭、旧结果失效；故障恢复不自动开启 |

这里的“暂停”保留页面与选择，终止本次尚未完成的作业；不从运动、录音或推理的中间位置继续。聊天仅保留同一AI会话的有限历史，关闭AI会清除历史。

为识别“同一功能再次确认”，AI控制上报`0x50`的controls第5位改为确认翻转位；每次有效SWA功能确认翻转，功能0..2、录音位和高亮项位保持原位置，第7:6位仍须为零。新RK源码与FPGA位流应配套部署。翻转位只表示遥控确认事件，不是运动回执。

## RK相机运行时固定对焦

> 标定/测量沿革保留原始日期与数值；当前运行已使用720p、focus260、去畸变H和近40cm有效凸包，并采用停车后0.3秒等待/三帧定位。本文早期“动态门禁未解除”或旧release记录不作为现行巡检准入，见[H接口](../../../host/ai_coordinator/inspection/HOMOGRAPHY.md)与[巡检指南](../../AI视觉巡检.md)。

本次将Windows标定使用的固定对焦位置接入RK正式原生取帧流程。用户确认45张标定原图均关闭自动对焦并固定focus=260；参数对应1920×1080。该数值是设备对焦位置，不是镜头焦距毫米数。

RK现场已按USB身份重新识别原相机`0bda:5856 / 200901010001`。Linux控制`focus_absolute`范围0..1023、步长1，读回260；`focus_automatic_continuous`读回0。控制值合法且与本轮设置一致，不根据Windows/其他设备量程进行猜测缩放。

<a id="report-03--运行行为"></a>
### 运行行为

正式相机配置为`focus:260, autofocus:false`。在每次打开设备和断线重连时：

1. 按原身份选择相机、协商现有图像模式和帧率。
2. 查询自动对焦与绝对对焦控制，检查是否可写、范围和步长是否接受目标值。
3. 先关闭自动对焦，再设置绝对对焦260，核对两项读回值。
4. 等待1秒让镜头稳定，再启动视频流并丢弃原有预热帧。
5. 每帧输出前重新核对自动对焦仍为0、绝对对焦仍为260；不匹配或ioctl失败则结束当前取帧，由既有相机故障/重连流程处理。

关闭相机不恢复自动对焦。相机掉电或其他程序更改控制后，下次打开仍执行完整设置。未设置focus的旧调用保持兼容；请求固定对焦时，OpenCV后端明确拒绝，不静默忽略锁焦。

帧元数据记录`focus_value=260`、`focus_locked=true`及`focus_verification=v4l2_control_readback_each_frame`。这表示控制寄存器读回，不证明物理画面处处清晰、镜头机械状态正确或完成几何/曝光时间标定。原48字节FVC1帧头不变。
