<a id="阶段三参数确认与运动学换算"></a>
### 阶段三：参数确认与运动学换算
轮半径 19.9 mm（轮宽 26 mm）、轮距 158.6 mm、轴距 170 mm、减速比 30、1024×600 中文界面、HDMI 到显示器、RK3588 走串口、ToF 未做出先留空。

**★ 编码器线数判定（用已有实测反推）**：实测手转车轮一圈 ≈ **61657 计数**（4 倍频后）

| 假设 | 理论计数/车轮转 | 与实测偏差 |
|---|---|---|
| 500 PPR | 60000 | 2.76% |
| **512 PPR** | **61440** | **0.35%** ✅ |

→ 判 **512 线**。连带发现 `car_fpga` 的 `rpm = delta/10` 隐含 60000 计数/转，按 512 线应为 `/10.24`（**2.4% 系统偏差**），本工程统一用 10.24。

**运动学常量**：轮周长 125.0354 mm、每计数 2.035 µm、差速系数 0.66415 rpm/(deg/s) → `DIFF_K_Q10 = 627`、`CENTER_K_Q10 = 3146`。

> ⚠ 2026-10-19 注：上面轮周长按当时假设的 R = 19.9 mm 算；**10-18 实测轮径 64 mm**（C = 201.0619 mm）后已不成立，偏差约 38%。现行值见 `参数总表` 第二节。但两个 K 系数标定的是「摇杆量 → counts/窗口」，**与轮径无关**；真正被轮径影响的是「counts → 毫米」，由 `odom.DS_K_Q10` 承担。

### 阶段四：中文界面基础设施
`tools\gen_font_rom.py` 从 `tools\font_chars.txt`（73 条文案）渲染 **16×16 点阵**，**直接内嵌进 Verilog**（不用 `$readmemh`——避免综合工作目录、外部文件缺失、CR 混入一类问题）。产物 `font_rom.v` / `ui_text_rom.v` / `ui_text_index.vh`。

<a id="阶段五rtl-实现7-个核心文件"></a>
### 阶段五：RTL 实现（7 个核心文件）
| 文件 | 关键设计 |
|---|---|
| `rtl\rc\rc_input.v` | 实例化 6 个单路 `rc_pwm_capture`；归一化用**移位加法**（×2.125 代替通用乘法）；三档模式 + 按钮上升沿 |
| `rtl\motor\chassis_ctrl.v` | 差速分解（左=中心−Δ、右=中心+Δ）+ 4×增量式 PID + `u→(dir,duty)` |
| `rtl\ui\ui_render.v` | 逐像素叠加、无帧缓存；**提前 2 拍取模**（ROM 各 1 拍延迟）；最多 6 个文本段 |
| `rtl\ui\num_text.v` | 慢速状态机逐位减法（不用组合除法） |
| `rtl\ui\dyn_text_ram.v` | 跨域简单双口 BSRAM：sys 写 / pixel 读 |
| `rtl\top\falcons_top.v` | 只做例化连线；急停 > 堵转 > 遥控 > 自动的优先级链 |
| `rtl\common\app_key.v` | 两级同步 + 计时稳定 + 边沿 |

**两条关键设计决策**：
1. **提前 2 拍取模**：字符索引与点阵行各有 1 拍 ROM 延迟，扫描不等人。做法是"始终请求 (x+2) 所在的字组"——数据 2 拍后有效时 x 已推进到 x+2，仍落在同一字组内。**不需要行缓冲、不需要消隐期预取**。
2. **布局强制 16 对齐**：所有文本起点 x 与 y 都是 16 的倍数 → 每个汉字恰好落在一个 16 px 字组内，取模退化成「字组号 + 格内位 + 行号」三件事，**不需要任何除法**。

<a id="阶段六约束首次综合与时序优化"></a>
### 阶段六：约束、首次综合与时序优化
`.cst` 与 `.sdc` 必须成对给，否则工具按默认 100 MHz 估算，会报假违规。

**首次综合 ERROR 0，但 SETUP 违规 25 条、最差 −7.023 ns**。逐步优化（每步都重新综合实测）：

| 步 | 措施 | 结果 |
|---|---|---|
| 1 | 遥控归一化改**移位加法** + `chassis_ctrl` 指令乘法插一级流水 | −7.023 → **−2.589** |
| 2 | 差速/限幅链再插一级流水（切断「中心速度→限幅→差速→PID 输入」） | → **−0.616**（1 条） |
| 3 | 像素域复位改**域内自产**（等 PLL 锁 + 计数释放） | → **−1.412**（1 条，消除复位链） |
| 4 | 加 UI 实时数值（跨域字符 RAM） | 7 条，最差 **−0.353** |
| 5 | 接入 IMU 链路 | 1 条，最差 **−2.003** |

**为什么当时不用 SDC 声明异步**：**先试了正解** —— `set_false_path -to [get_clocks {pixel_clk}]`，但 `pixel_clk` 是 `hdmi_1024x600` 内部 PLL 的派生时钟，**约束解析阶段还不是时钟对象** → `ERROR (TA2004): Cannot get clock with name 'pixel_clk'` 导致综合失败 → 撤回，改用 RTL 手段。**2026-10-21 用 `create_generated_clock` 先自建时钟才解决**（§77）。

**剩余违例的性质**：SETUP 1 + HOLD 9，路径两端是同一信号在两个时钟域的采样（同步器第一级、异步输入采样、动态字符 RAM 跨域读）——**CDC 结构性现象，不构成功能风险**。真实逻辑路径最差 **+0.105 ns**，落在 `speed_pid` 内部（与 `car_fpga` 的 `imu_demo` Fmax 51.11 MHz 同一现象）。

<a id="阶段七ui-实时数值"></a>
### 阶段七：UI 实时数值
按功能设计文档 §5.3：`num_text.v` 7 字段 × 4 字符（100 ms 刷一轮）+ `dyn_text_ram.v` 跨域双口 + `ui_render.v` 扩到"最多 6 个文本段"。数值用亮绿 `7CFC98` 与白色标签区分。

<a id="阶段八仿真4-台--70-项"></a>
### 阶段八：仿真（4 台 / 70 项）
`sim\run_sim.ps1` 一条命令跑完，**每个测试开独立 `vsim` 进程**（`-c` 模式下 `$finish` 会终结整个进程，串在一起只有第一个会执行）。

**★ 仿真抓到 2 个编译与综合都看不出的纯逻辑缺陷**：
1. **差速限幅顺序错**：原来先限中心速度再算差速。`center=5000 / diff=2000` 时左轮只得 **2096**（=4096−2000）而不是 3000 —— 实车表现是"大给定 + 转向时往一侧偏"。改为只对差速量与左右轮各自限幅。
2. **状态栏颜色割裂**：状态栏横跨全宽，左段（x<208）落在菜单条 x 范围内 → 左半边菜单色、右半边状态栏色。改为状态栏优先级高于菜单条。

<a id="阶段九imu-链路接入"></a>
### 阶段九：IMU 链路接入
`imu_top`(u_imu) → `gyro_tilt_comp`(u_tilt) → `yaw_integrate`(u_yaw) → 数据页航向角。SPI 四线 A14/A13/A16/A15（J2）。

**接线没自己猜** —— 直接照 `car_fpga\rtl\top\imu_demo_top.v` 里**已上板验证过**的接法，三条契约写进顶层注释：
1. `gyro_tilt_comp.i_sample_valid` 接 **`o_acc_valid`**（不是 `o_data_valid`：后者只在 RUN 态产生，标定窗口期收不到样本，会让倾斜补偿**永远不生效且不报错**）
2. `gyro_tilt_comp.i_calib_start` 接 `o_calib_busy`
3. `yaw_integrate.i_sample_valid` 接 `o_data_valid`

★ `imu_top.SCK_HALF_DIV` **必须显式写 25**（1 MHz）：源码默认 3（8.33 MHz）实测导致 8 KB 配置加载失败，表现为 `o_err_code = 2`。

<a id="b-powershell--脚本"></a>
### B. PowerShell / 脚本

| 坑 | 现象与处理 |
| --- | --- |
| **数组字面量里拼换行会丢行** | `@( @('a','b'), @('c', 'x' + "`n" + 'y') )` 里第二行会丢 —— 本会话被这个坑咬了 **4 次**（生成器脚本、tb 检查项、tb 统计块）。**改用 here-string** |

<a id="c-verilog--rtl"></a>
### C. Verilog / RTL

| 坑 | 现象与处理 |
| --- | --- |
| **`localparam` 不能在 module 外声明** | `include` 一个只有 `localparam` 的 `.vh` 放在 module 之前 → 解析失败、后续变量全"未定义"。**include 必须在 module 体内** |
| **不能对表达式做位选择** | `(-cur)[15:0]` 非法（ModelSim `vlog-13069`）→ 先算 `absv` 再取位 |
| **位宽写小** | `wire [15:0] flat_us` 要装 6×16 位 → **ModelSim 容忍、Gowin 报 `EX3784` 越界**并把该模块降级成黑盒 |
| **声明顺序** | 变量必须在**使用它的 always 块之前**声明（顶层 `yaw_clear_r` 踩到） |
| 组合 `always` 未给默认值 | 推断出 latch（`EX2420`）→ 在块首赋默认值 |
| 优先级顺序影响视觉 | 状态栏与菜单条 x 范围重叠 → 谁先判断决定配色是否割裂 |

<a id="d-gowin-综合特有"></a>
### D. Gowin 综合特有

| 坑 | 现象与处理 |
| --- | --- |
| 只能容忍语法、不能容忍越界 | 见上 `EX3784`；**仿真通过 ≠ 能综合**（本会话再次验证） |
| 约束里引用 PLL 派生时钟 | `set_false_path -to [get_clocks {pixel_clk}]` 报 `TA2004` 并**导致综合失败** —— 该时钟在约束解析阶段还不存在 |
| 时序报告里的 CDC | 同步器第一级、异步 RAM 读都会被当数据路径分析，报出零点几纳秒的违规；要区分"CDC 结构性"与"真实逻辑路径" |

<a id="e-写-testbench"></a>
### E. 写 testbench

| 坑 | 现象与处理 |
| --- | --- |

<a id="-214-setup违规端点口径的彻底查清本节最有价值的方法论"></a>
#### ★ 21.4 Setup「违规端点」口径的彻底查清（本节最有价值的方法论）
**问题**：报告说 `Setup Violated Endpoints = 4`，但 Setup 路径表 25 条**全为正 slack**（最小 +0.032）。这 4 个端点是谁？

**结论**：这 4 个端点是 **HDMI DVI 发送端 4 个 `OSER10` 原语的异步复位脚**，由 **245 MHz `CLKOUT1` 的下降沿**捕获：

```
u_hdmi/u_dvi_tx/rgb2dvi_inst/u_OSER10_clk/RESET
u_hdmi/u_dvi_tx/rgb2dvi_inst/u_OSER10_b/RESET
u_hdmi/u_dvi_tx/rgb2dvi_inst/u_OSER10_r/RESET
u_hdmi/u_dvi_tx/rgb2dvi_inst/u_OSER10_g/RESET
```

**推理闭合（排他性）**：违规端点必有 slack < 0；若属上升沿集合，必在"全局最差 25 条"里；那 25 条最小 slack 是 +0.032 > 0 → 不在上升沿集合 → 只能在下降沿集合；而 `Falling Endpoints = 4` 恰好 4 个 → 就是这 4 个 OSER10 RESET。∎

**四条独立证据**：① 全文 `[F]` 只出现 8 次，全是 `CLKOUT1:[F]`；② Setup 表 25 条无一个 `[F]`（跨沿检查不在该表）；③ 两次独立布局布线统计**逐项相同**；④ 这 4 个同时是 RECOVERY 8 条的捕获端。

**要不要紧**：**不要紧**。`pixel_pwr_cnt` 是复位释放计数器，只在**上电复位那一次**变化；OSER10 的 `RESET` 是异步复位，语义是"复位何时释放"。物理含义是"复位比理想时刻晚几个 245 MHz 周期"，功能无害。
