# AI巡检演示级停车定位（2026-10-28）

按用户当天修订要求实现最小演示流程：不要求高精度，信任编码器、IMU、地图位姿等传感器数据，不判断这些数据的时效；摄像头延迟仅按不超过0.3秒估计。采用连续三帧，取消当天先前方案的FPGA停稳证明、双模式切换、时钟对齐、位姿插值和运行验收标记门槛。

## 执行流程

1. 继续使用FPGA已有雷达导航，速度码30。
2. 行驶期间识别到置信度至少60%的新目标，RK通过原有CONTROL暂停命令请求停车。
3. 收到FPGA的STOP完成回执后，固定等待0.5秒：覆盖0.3秒摄像头延迟，并留0.2秒静置时间。不根据轮速、陀螺仪或数据时间戳判定停稳。
4. 等待结束时保存当前FPGA地图位姿，开始新一轮采图。采图入口给图像标记轮次，因此等待前仍在推理的结果不参与本轮；不做图像年龄或曝光时间校验，不重启相机或模型。
5. 连续处理本轮三次推理图像（相机持续采集，未推理的中间帧可跳过）。取每个检测框底边中点，使用已部署内参去畸变，再经地面H计算车体坐标，最后用保存的位姿转换到地图坐标。
6. 沿用原有同类、15cm内最近目标关联。新目标连续三帧关联后确认；确认前坐标采用算术平均。三帧完成后一次发布结果、更新视觉障碍层。目标红点、报告和“发现xx”播报沿用原有实现。
7. 收到原有障碍层提交回执后，继续当前去程或返程目标；返程仍允许在最新地图上换路回起点。

已定位目标的画面框使用IoU 0.3匹配，随连续画面更新框位置，避免同一物体持续触发停车。这是简单的画面关联，没有增加跟踪模型。
