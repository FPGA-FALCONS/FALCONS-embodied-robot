# 视觉巡检阶段3B1：独立高速接口

## 范围与边界

本阶段建立 RK → FPGA 的 AIF1 高速容器、16 位同步 Slave FIFO、双向异步 FIFO 及无运动诊断回环。FPGA 原摄像头仍只供原摄像头页，未加入向 RK 传图的逻辑。原三个 AI 功能和独立第四项“视觉巡检”保留。

这不是完整巡检交付：生产顶层暂不接收显示帧或应用高速图层消息，后续阶段接入独立 DDR 帧缓存、地图导出及 RK 任务服务。不能把接口枚举、诊断仿真通过解释为巡检已部署。

按用户最新要求，不合并共享仓库其他导航方案；阶段提交前仅 fetch 核对远程。保持原暂存区的 17 项无关文件不变，不自动推送。

## 原厂运行固件及真实时钟合同

原厂第65章65.3.3明确要求先向FX2的RAM加载`slave_for_adc.iic`，仅连接USB或看到端点不足以完成Slave FIFO初始化。本项目保留原厂镜像和严格校验的加载器，来源、哈希与补丁见[固件记录](../host/ai_coordinator/inspection/firmware/README.md)。仅在运行RAM记录中把唯一IFCONFIG立即数E3改为A3，使用内部30MHz时钟；8051 CPU时钟、端点等其余字节不变。

选择30MHz依据芯片内部时钟模式的18.7ns同步读建立时间，给FPGA时钟树/I/O及板级传播留出余量。不是只把SDC数字改大：主机须收到FPGA独立测得的30MHz频率和特征变换诊断回执，才能发送业务。480Mbps描述USB总线，与IFCLK频率不同。当前PHY每4个接口时钟传一个16位字，上限15MB/s；10fps显示有效载荷约6.85MB/s，实际完整帧吞吐另行实测。

加载器默认只离线审查。显式`--load-volatile`才使用A0暂停8051、分块写入0x0000～0x3fff程序RAM、释放CPUCS；记录越界、重叠、未知原镜像和寄存器写入均拒绝。没有EEPROM操作。掉电后仍从板上原启动固件启动。

RK已完成这一组RAM下载请求，所有请求返回预期长度，原服务仍active、CH340正常。**尚不据此断言Slave FIFO或30MHz已经生效。** A0读回未返回可验证的代码字节，不作为验证依据；v8完整布局布线同钟域通过后已通过SRAM加载（17:47及RK重启后的20:52），USB诊断仍为OUT成功、IN零字节。独立测频未读回，不能宣称链路通过；FPGA Flash未写。

## 物理接口

引脚及FIFO合同取自本机 ACG720 厂商第65/66章例程：16位同步Slave FIFO；FLAGB高表示EP2可读，FLAGC高表示EP6可写；地址00/10分别选择EP2/EP6。本项目使用上述受校验运行固件配置的30MHz IFCLK。引脚已核对原应用无冲突，附加到唯一的应用CST/SDC，未更改J6遥控槽位。

所有物理输出，包括 FD 数据、三态使能、地址、SLRD/SLWR、SLOE、PKTEND、SLCS 均由 IFCLK 域寄存器驱动。先设置地址/方向，再保留一个 FIFO 槽位，再在下一边沿完成读写；读写间插入高阻周转。双向公平轮询，完整512字节包不额外产生零长度包，仅在容器末尾的短包使用 PKTEND。

数据和标志在下降沿采样，避开FX2上升沿更新窗口；预取字再和有效位一起经上升沿交给异步FIFO。RX槽位已预留，上一字的延迟入FIFO早于下一次预留。地址/选择在访问前后至少各稳定两个周期，延迟总线测试验证25ns建立、10ns保持，SDC中对应地址的多周期例外由此限定，不能用于SLRD等单周期选通信号。

外部约束按Infineon 38-08032 Rev.AD表20/23/26/31分别设置，加1.5ns板级余量；输入最小延迟使用-1.5ns，不假设芯片一定延迟2ns才改变数据。标志/数据下降沿采样同时满足建立和保持。没有使用统一12ns来代替读、写、包结束和地址的不同要求。

已核对厂家原理图L13是USB_PA0，与USB_RESET独立；厂家第65章例程将其固定为0。镜像0x0ae7附近以MOV C,PA0读取该脚，非零分支重置EP6等端点，因此新增PA0固定低电平约束，避免未用引脚上拉触发连续清零。该修订包含在v9独立冻结构建中，现场效果待验证。FX2 复位释放和 Gray 指针分别同步，各域间数据只经异步 FIFO 交换。

IFCLK独立计数器在FX2域寄存Gray计数，经系统域两级同步、寄存译码及一秒差分测量频率。系统域还检测时钟停止，撤销PHY/FIFO复位释放，使停钟时输出不持续保持驱动；时钟恢复后按各域重新同步释放。该机制与电机/手动控制无关。

## AIF1 容器

48字节小端头：`magic/version/kind/header_bytes/session/task/epoch/context/sequence/payload_bytes/width/height/stride/view/payload_crc32/header_crc32`。头 CRC 覆盖前44字节，载荷另有 CRC32；所有容器长度为偶数。

| kind | 数据 | 限制 |
| --- | --- | --- |
| 1 DISPLAY | RK 渲染 RGB565LE | 固定816×420、stride1632、685440字节 |
| 2 CONTROL | 完整 MOT1 封装 | 最多408字节，长度是12的整数倍 |
| 3 MAP | 完整雷达占据位平面 | 256×256、8192字节、x方向低位优先 |
| 4 DIAGNOSTIC | 无运动回环 | 最多512字节 |

DISPLAY 写入尚未发布的帧，只有头和载荷均通过校验且 session/task/epoch/context/view 全部仍匹配时才允许提交。断包、超时、校验失败或页面上下文变化均中止。CONTROL/DIAGNOSTIC 先完整缓存和校验，再向下游暴露同步 RAM；半包不会变成已接收消息。

主机保留一个未完成 OUT 容器的偏移，部分写入后继续原容器，不能插入新头。IN 解析器可从垃圾、断包和坏 CRC 恢复，存储有界。`--config ...` 默认只检查描述符；必须显式 `--diagnostic` 才发送有限回环数据，不产生运动命令。

诊断响应保持载荷，将sequence异或`0x46504741`，session字段携带实测IFCLK赫兹数，FPGA重新计算头CRC。主机要求频率处于30MHz±2%，拒绝原样字节回环、0Hz、48MHz或特征不匹配。运行期USBPump每次重连都先用新随机挑战完成该握手，再发送业务容器；CONTROL最多排队8项且只允许一个完整图层事务，DISPLAY仅保留最新待发帧，地图接收队列最多2帧。切换绑定后清除待发旧任务，已经部分发送的容器仍完整发送完，由FPGA上下文校验拒绝陈旧内容。串口安全心跳不在此线程上等待。

## 提前时序检查与修正

首轮整车布局布线发现系统域约43.1MHz、接口域约41.1MHz，后续多轮也未全部收敛，候选均未烧录。早期假设48MHz且统一12ns输出预算，不能作为物理接口合格证明；现已按芯片手册、真实固件配置和独立测频合同修正。

针对实际路径进行了以下分拍：

1. FX2 输出从状态组合译码/BRAM直出改为端口寄存器，消除 RAM → 引脚及复位组合 → 引脚路径。
2. 地图仲裁先寄存客户端和地址，再核对请求仍有效才授权；各客户端 grant 独立，阻断前探几何计算 → 优先级选择 → 规划器 CE 的跨客户端长路径。撤销或改变未接受请求不产生 grant；只对已接受请求计时和锁定响应 owner。
3. 雷达累积器与地图间增加一项弹性写缓冲，保持 ready/valid，不丢观测，隔离扫描选择与路线发布检查。
4. 整车电机堵转监测采用输入快照，将驱动意图、增量和有效脉冲一起延迟一拍；最终 `i_enable & ~o_stall` 仍直接控制 PWM 禁能。手动挡、急停和失联停车不经过此监测流水线。
5. PID计算前统一锁存目标、反馈、增益和有效/使能，增加一拍计算延迟；物理占空比、驱动使能与刹车继续使用实时安全门控。四路PID局部复位分支异步断言、延后两拍释放，降低全局复位扇出路径。测试改为在非采样沿施加反馈，并覆盖不等待流水线的实时禁能。
6. 导航空闲阶段连续锁存候选目标/位姿，接受规划时仍取同一拍的数据，避免长准入条件驱动宽坐标寄存器CE。语音转向仅将已验证[-180,180]的角度/前值用有符号9位保存、差值用10位计算，目标1～360度用无符号9位保存；有符号累计角仍32位，越界输入检查保留。

已撤回效果不佳的全局高扇出复制选项，保留明确的I/O寄存器放置。Gray指针的FX2/sys跨域不用clock groups全部屏蔽，而用双向10ns最大延迟约束，只排除无固定相位的跨域hold检查。v8冻结输入包含新30MHz合同、测频和上述分拍，完整布局布线同钟域setup/hold通过：系统50MHz要求/50.033MHz实际、FX2 30/35.449MHz、像素49/49.180MHz；系统及像素余量较小。原DDR IP跨钟域报告仍单列，不能宣称所有跨钟域路径均已闭合。v8实际使用的122项输入已按综合工程清单逐一核对，位流SHA256为e3828f668204e070fee04ee15630bd562c8a61003f641008df67e1dd6edb9253。追加PA0固定低后v9重新完整构建，不直接沿用v8的时序结论。
