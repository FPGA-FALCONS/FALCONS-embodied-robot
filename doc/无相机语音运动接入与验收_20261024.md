把`voice_motion.example.json`合入`config.voice_motion`，默认关闭。`patrol_target=fpga_preset`表示不依赖相机的FPGA既有路线请求；`ai_search`保留原来的路径点找物巡航及相机时效准入。旧配置未指定时维持`ai_search`兼容行为。两者不能靠一句口令自动猜选地图或路径点；板上没有配置真实路线时不凭空生成路线。

旧候选仅预览。当前正式后端要求 `enabled=true + live_commissioned=true + mode=live + gateway.mode=serial + 显式 /dev/serial/by-id`；仅改一个布尔值仍不会发送。板端默认关闭，现场确认轮子架空/遥控/急停后才授权。

## 与Claude的执行侧分工

Claude负责`ai部分/semantic_nav_20261024/rtl/voice_motion_bridge.v`及仿真；Codex负责本轮协调器入口/软件回归/独立候选。已在总集成协同文件告知范围和以下问题：

1. 已知GitHub基线`ec759b161f378fcf545a836fe8bed63295efe1a2`的`falcons_top`使用`auto_selected_*`，已有导航/雷达自动仲裁。本地旧a3cf基线才把auto接零；不能在旧版顶层直接替换并覆盖队友导航成果。
2. 本轮读取的MOT1桥有前后退定时和yaw转向逻辑，但无串口TX完成/故障回执端口；现有`send_motion.py`读取字节并打印ACK不能替代FPGA真实回执。主机发出不等于FPGA接受、开始或完成。
3. 本轮读取的WATCHDOG_MS默认500ms；方案口述300ms尚未落实为实测证据。需保留RC/急停/障碍/堵转优先、失联停车和重新授权机制，避免退出语音控制后旧巡航重新接管而继续运动。
4. MOT1与FAM1不同，必须统一串口所有权与命令仲裁，不得两个进程争同一串口；还需核对旧PID解析器是否会误读新帧载荷。
5. 当前MOT1转向值为整数度、直行值为毫秒。若要精确米数，需新版本明确毫米字段、距离闭环和有效回告，不能静默复用时间字段。IMU航向符号、跨±180累计、传感器停更、过冲与超时均应独立验收。

Claude留存的`sim/tb_run.log`显示forward/turn/spin/stop/crc/watchdog/manual/patrol仿真PASS；这是其独立仿真记录，尚无生产顶层/位流/实车验收，本轮不重跑或改动该RTL。
