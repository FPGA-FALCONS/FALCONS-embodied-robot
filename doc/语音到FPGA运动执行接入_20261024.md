# 麦克风语音 → FPGA 运动执行接入（MOT1 共享串口）

日期：2026-10-24。范围：SenseVoice 转写或文本 → 协调器规则/限值 →
`MotionBackend` → 与 FAM1 共用的唯一串口 → FPGA `voice_motion_bridge` → 原底盘闭环。

**本文只把软件/仿真/板端部署证据称为已验证。** 没有实车、真人麦克风噪声、轮子架空、
偏航/轮速标定或落地测试证据时，不把任何动作写成“实车通过”。

---

## 1. 执行缺口与本次补齐

旧状态只有两条互不相连的链路：

- 协调器 `motion_intents.py` 只返回 `wire_preview`，`execution_supported=false`；
- 独立 `send_motion.py` 能发 MOT1，但没有接协调器任务生命周期、ASR、停止/取消和共享串口。

本次新增 `host/ai_coordinator/motion_backend.py`，并改造 `gateway.py` 的串口层：

```text
/text ─┐
       ├→ runtime.preset_control → motion_intents（同一套规则/限值）
/audio → SenseVoice → 同一 parse → MotionBackend
                                  │
                                  ├→ 整帧排队（STOP 优先，不能插入半帧）
                                  ├→ 心跳任务 200 ms（可配 50–250 ms）
                                  └→ 共享 Gateway.SerialPort（flock 独占）
                                              │
                                              └→ MOT1 12 字节 → FPGA 桥
```

- **不另开串口**：MOT1 与 FAM1 使用同一个 `SerialPort`。`FAM1/MOT1/PID/独立 sender`
  不能各自持有设备；第二个进程会被 `flock` 拒绝。
- **整帧调度**：`SerialPort` 以 `FrameTicket` 排队，STOP 只排在已部分写出的整帧之后，
  不会把 12 字节 MOT1 插进 FAM1/其他帧的中间。
- **文本和 ASR 同入口**：`submit_text()` 与 `submit_audio()` 最终都进
  `Runtime.preset_control()`，不存在两套解析器。
- **规则优先**：固定运动短语不调用 Qwen；“找螺丝刀”仍返回 `None` 交给原 C1b/视觉链路。
- **计划模式**：`plan_only=true` 只返回预览，不写串口。
- **HOLD/无设备/shadow**：任一条件不满足都不发送；`enabled=true` 本身不等于可执行。

## 2. 配置（板端默认关闭）

唯一串口设备只写在 `gateway.device`，必须是显式 `/dev/serial/by-id/...`。
`voice_motion` 不提供第二个 `device` 字段。

```json
{
  "mode": "live",
  "model_loads_enabled": true,
  "gateway": {
    "mode": "serial",
    "device": "/dev/serial/by-id/usb-REPLACE-ME",
    "allow_motion": false
  },
  "voice_motion": {
    "enabled": true,
    "live_commissioned": true,
    "backend": "mot1_shared_serial",
    "patrol_target": "fpga_preset",
    "speed": 10,
    "heartbeat_s": 0.2,
    "turn_window_s": 8.5,
    "drive_margin_s": 0.3,
    "distance": {
      "calibrated": false,
      "calibrated_speed_mps": null,
      "min_speed_mps": 0.05,
      "max_speed_mps": 0.5,
      "max_distance_m": 2.0,
      "max_duration_s": 5.0
    }
  }
}
```

- `gateway.allow_motion` 只控制 FAM1 任务命令；MOT1 低层运动由
  `voice_motion.enabled + live_commissioned + mode=live + gateway.mode=serial` 共同授权。
- `live_commissioned=true` 必须由现场人员在确认**轮子架空、遥控接管、独立急停可用**后设置，
  不是软件安装器自动打开的开关。
- `speed` 为 MOT1 速度码（1–40）；首次测试建议 10 或更低。
- `heartbeat_s` 必须 ≤0.25 s，给 FPGA 500 ms 看门狗留余量；默认 0.2 s。
- 转向没有主机完成回执，`turn_window_s` 只是主机心跳/停止窗口（默认 8.5 s）；FPGA 自身
  还有 8 s 转角超时。窗口结束只代表主机停止发送并排队 STOP，不代表角度已到达。

### 距离指令（按设定速度估算）

支持0.05–2m；按固定0.3m/s估算，使用速度码229，与巡检配置独立，不要求`calibrated`开关。1m约3.333s，2m约6.667s；超过单帧5s由RK分段，保持心跳，最后发送STOP。STOP、手动接管、急停或断联取消后续分段，不自动恢复。

结果保留目标距离、总时长及分段时长，UI提示“按设定速度估算、到达未验证”，不代表里程计距离闭环。

## 3. 生命周期与停止

1. `preset_control()` 先做规则、否定/复合/越界检查；有效才进后端。
2. 后端检查 `enabled/live_commissioned/backend/gateway serial/device/fd/心跳配置`。
3. 旧动作：取消旧任务、丢弃旧的 `motion` 心跳帧、递增 epoch；迟到回调看到 epoch 不匹配
   不再写串口，不会重启旧动作。
4. 新动作：整帧入队并 flush；`accepted=true` 只表示已交给共享串口，`sent` 只在完整
   12 字节写入 OS 串口缓冲后为真。
5. 心跳任务独立运行，按 `heartbeat_s` 发送 `HEARTBEAT=8`；ASR/视觉/LLM/TTS 不阻塞它。
6. 定时直行窗口 = 帧时长 + `drive_margin_s`；转向窗口 = `turn_window_s`。窗口结束：
   丢弃剩余运动帧，优先排队 `STOP=0`，记录 `host_window_elapsed_no_device_receipt`。
7. 停止/取消（文本、ASR、`POST /stop`、服务关闭）：同步排队 STOP，取消动作任务；
   不等待 ASR/LLM 退出。
8. 串口写失败/断开/FPGA link_lost：取消任务，记录 `failed`；
   能写则尝试 STOP，不能写则明确 `stop_frame_sent=false`。FPGA 500 ms 看门狗是独立兜底。
9. 正常服务退出：`Runtime.close()` 在关闭串口前尝试 STOP；仍不声称物理停车已验证。

**不返回导航控制权**：一旦语音动作或 STOP 被接受，协调器记录
`owns_control=true`，后续 FAM1 找物/巡航任务 admission 返回
`voice_motion_holds_control_until_reset`。生产 RTL 的 `voice_nav_release_ready=0`，
语音所有权保持到整车复位；主机不伪造释放，也不把“继续导航”当成已恢复。

## 4. 真实状态字段

| 字段 | 含义 |
|---|---|
| `motion.valid` / `intent` | 规则和限值通过，意图已解析 |
| `accepted` | 后端准入并已把整帧交给共享串口 |
| `frame_queued` | 帧已进入整帧队列 |
| `frame_bytes_written` / `sent` | 已写入 OS 串口缓冲的字节数；`sent=true` 只代表 12 字节写完 |
| `executed` | **恒为 false**；没有 FPGA 动作级回执 |
| `device_reply_verified` | **恒为 false**；串口收到的 CSV/ASCII 不是 ACK |
| `action_complete_verified` | **恒为 false**；主机计时器/窗口结束不是完成 |
| `stop_frame_sent` | STOP 12 字节是否写完；不是物理停车证明 |
| `physical_stop_verified` | **恒为 false**；没有物理停车回执 |
| `physical_task_completed` | **恒为 false** |

FPGA `voice_motion_bridge` 没有 hello/ACK/完成回执。本轮没有新增私有回执协议，
也没有改 RTL/位流；因此不声称与任何旧固件“回执兼容”。

## 5. 明确未支持

- `patrol_start` 没有接真实航点/导航释放：协调器返回 `patrol_route_not_connected`，
  不发送 MOT1 巡航启动，不声称自动巡航已工作。
- `patrol_stop`/“关闭巡航”走停止路径，发 STOP；不声称恢复了原导航。
- ToF 在生产顶层仍是占位（恒 0），不声称已有实物防撞。
- 没有机械手；“拾取完成”仍是人工确认语义，和运动后端无关。
- 没有编码器距离闭环、没有堵转/完成回执、没有精确角度保证；阶段 2 才做。

## 7. 现场启用/停止/回滚

板端根目录（以实际 `active_release.json` 为准）：

```text
/home/orangepi/workspace/falcons_ai_coordinator_20261024_r1
```

启用前先备份并记录：

```bash
cd /home/orangepi/workspace/falcons_ai_coordinator_20261024_r1
cp -a config.json config.before_voice_motion.json
cp -a active_release.json active.before_voice_motion.json
systemctl --user status falcons-ai-coordinator.service --no-pager
```

确认串口（只读；不要猜设备）：

```bash
ls -l /dev/serial/by-id/
```

编辑 `config.json`（不要用安装器替你打开 live）：

```json
"mode": "live",
"model_loads_enabled": true,
"gateway": {"mode": "serial", "device": "/dev/serial/by-id/实际设备", "allow_motion": false},
"voice_motion": {"enabled": true, "live_commissioned": true, "backend": "mot1_shared_serial", "speed": 10}
```

重启用户服务：

```bash
export XDG_RUNTIME_DIR=/run/user/$(id -u)
systemctl --user restart falcons-ai-coordinator.service
systemctl --user status falcons-ai-coordinator.service --no-pager
```

先只读状态，确认 `voice_motion.readiness_reason` 不是配置错误：

```bash
CODE=$(python3 -c 'import json; print(json.load(open("active_release.json"))["release"])')
python3 "$CODE/host/ai_coordinator/main.py" --config config.json status
```

短动作文本（`plan_only` 先看，不发送）：

```bash
python3 "$CODE/host/ai_coordinator/main.py" --config config.json text --text '前进' --plan-only
python3 "$CODE/host/ai_coordinator/main.py" --config config.json text --text '前进'
python3 "$CODE/host/ai_coordinator/main.py" --config config.json text --text '停止'
```

立即停止/取消（不等待模型）：

```bash
python3 "$CODE/host/ai_coordinator/main.py" --config config.json stop
```

回滚：停止服务，恢复备份的 `config.json`、`active_release.json` 和用户 service
（安装器在 release 内也保存了 `config.previous.json`/`active.previous.json`/
`service.previous.txt`），再启动并检查 `status`：

```bash
systemctl --user stop falcons-ai-coordinator.service
cp -a config.before_voice_motion.json config.json
cp -a active.before_voice_motion.json active_release.json
systemctl --user start falcons-ai-coordinator.service
```

**禁止**：`apt upgrade`、`pip install -U`、替换 NPU/RKNN/系统 Python、写 Flash、
把旧候选位流当成已签收。SRAM 实验位流也不等于实车通过。
