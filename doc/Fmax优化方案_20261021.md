# Fmax 优化方案（2026-10-21）

## 1. 结论与实施顺序

当前优先优化整车中的 IMU 和显示链路，不先改雷达建图或 BFS。最新报告前 25 条 setup 路径中，13 条属于 IMU，2 条属于动态文字读口，1 条属于原非避障控制器，1 条属于显示 RGB，其余 8 条属于 DDR 相关时钟路径。报告只列出最差 25 条，不能据此认定未出现的模块已经全部达标。

建议按下表顺序实现和自检，**第一轮完整布线集中验证前四项**。单项先确认流水边界和功能，再进入下一项；不为每个小改动分别等待一次完整布线。这样得到的是这组修改的整体收益，不冒称各项独立提高了多少 MHz。

| 优先级 / 实现顺序 | 修改对象 | 收益依据与把握 | 主要风险 / 成本 |
| --- | --- | --- | --- |
| P1-1 | `nav_ctrl` 真正使用已存在的 `dot_r/cross_r` | 确定存在被绕过的流水边界；修改很小，局部切链把握最高 | 整机仍被 IMU 卡住，不能单独承诺整体 Fmax 增长 |
| P1-2 | IMU 换算后寄存，再寄存标定判定 | 覆盖当前系统域最差路径及大量标定使能路径；系统域收益潜力最高 | 必须保证同一份采样的数据、判定、累加及完成标志对应 |
| P1-3 | 动态文字先寄存行 / 区域选择，再计算读地址与读 RAM | 明确切开“坐标译码→优先选择→地址算术→RAM”长链 | 像素延迟必须整体对齐，工作量中等 |
| P1-4 | 字模列选择和最终 RGB 链同步分级 | 解决 P1-3 后仍然存在的另一条像素瓶颈 | 不能只寄存 RGB 或位号；须同步图层和显示时序 |
| P2 | 单独试验 PnR 资源复制 | 当前实际命令没有 `-replicate`，数据节点扇出达 145～161；历史独立导航有成功记录 | 全车收益不确定，只做一次受控试验，不进行参数遍历 |
| P3 | 更深层次端点、导航坐标显示换算等 | 前四项完成后，依据新的最差路径决定 | 当前没有足够证据值得优先动 |

“把握高”指确实能缩短目标组合链，不表示全设计布线后的频率必然增长。先争取系统 50 MHz、像素 49 MHz 均满足，再考虑余量；可把最差同域 slack ≥ +0.5 ns 作为后续目标，不作为本方案的收益保证。

## 3. 关键路径与具体改法

### 3.1 P1-1：接回已经声明的投影流水

位置：`rtl/nav/nav_ctrl.v`，约 342～349、583～595 行。

现有结构：

```text
乘法 → s_dot/s_cross → 移位 / 绝对值 → 常数乘法 → 比较 → cut_ok_r
          └→ dot_r/cross_r（M_A1 写入，但判据没有读取）
```

代码虽然在 `M_A1` 锁存 `dot_r/cross_r`，`dot_s/cross_s` 仍取自组合的 `s_dot/s_cross`，因此投影计算没有被真正隔离。最新路径 14 为 DSP 输出到 `cut_ok_r.D`，slack −2.090 ns。

优先让后面的移位、绝对值与转角判据读取 `dot_r/cross_r`，沿用现有 `M_A1 → M_A2` 节拍。核对 `dx_r/dy_r/sp_dx/sp_dy` 在这些拍之间稳定，保持符号、32 位截断、右移、比较及 `TAN_CUT_Q10` 语义。正常情况下不需要增加状态或外部接口；综合后可能真正保留此前被优化掉的寄存器，不能把“源码已有寄存器”理解成资源一定不增长。

如果剩余“常数乘法→比较”仍偏长，可利用后续 `M_V1/M_V2` 阶段分开寄存阈值与比较结果，保证 `M_A5` 消费时已就绪，不先扩展状态机。

验证：原非避障 L1/L2 回归；直行、阈值两侧、负点积、正负叉积、缺少下一目标、暂停 / 故障。重点确认一次测量过程中判据来自同一组端点。不得通过删除原非避障调试或改变转角策略改善时序。

### 3.2 P1-2：切开 IMU 的算术与标定控制

位置：`vendor/verilog-reusable-modules/modules/imu660ra/rtl/imu_top.v`，约 309～378、666～742 行。

当前链路：

```text
rx_buf → ×25000、右移 → 减去均值 → 绝对值 / 求和 / 阈值
       → 是否计入样本 → 计数 / 标定完成判断 → CE、状态及后续显示换算
```

最差路径 9 为 `rx_buf[11] → n4483_s/A[3]`，slack −2.648 ns，终点是顶层 DSP 输入，不是普通数据寄存器。路径 15～18 到 `calib_cnt.CE` 为 −2.056～−2.047 ns，后续多条到 `calib_sum_y.CE` 为 −2.040 ns。标定控制末级数据扇出 145，单段连线延迟 2.740 ns；最差链的连线总延迟约 12.33 ns。

应完整处理这组共享控制依赖：

1. 在采样数据完整后，先算并锁存三轴换算结果；寄存器放在换算乘法之后。
2. 用这份寄存后的样本计算是否静止、是否接收、是否到达种子 / 完成计数边界，并锁存判定。
3. 下一拍使用同一份样本和判定更新计数、累加、均值、零偏及状态。让大范围 CE 的来源成为局部寄存输出，避免从原始采样一路组合推导。
4. 复核最差 DSP 端点的状态 / 显示用途及综合重定时；顶层有 `imu_state_dbg*100+imu_err_code` 的显示换算。必要时在慢速显示通路锁存状态快照，但单独处理显示不能代替标定 CE 的优化。

优先争取 2～4 个内部周期完成样本处理；该周期数是设计预算，实际以实现为准。对约 1 kHz 采样很短，但必须明确 `acc_valid/data_valid` 的对应关系及延迟。标定超时计数继续按原来的时间尺度运行，不能因流水改变接受样本数、超时判据或最终零偏。

需要补足真正执行标定流程的自检：第一份样本、16 份种子均值边界、拒收运动样本、512 份完成边界、超时、复位、正负极值，以及加速度 / 陀螺有效脉冲。现有 IMU 算术测试不足以单独证明这些状态行为等价。依模块库维护要求运行应用全回归。

不重复“只给 raw 输入加寄存器”的旧试验：它没有切断后面的标定决策链。也不先压缩累加位宽或删除静止筛选。

### 3.3 P1-3：动态文字读址流水

位置：`rtl/ui/ui_render.v`，约 597～754 行；`rtl/ui/dyn_text_ram.v`。

路径 11：`vcount → u_dyn_text/o_rdata.D`，slack −2.482 ns。数据链约 22.841 ns，其中连线 11.111 ns、组合单元 11.386 ns、C2Q 0.344 ns。RAM 地址位扇出达到 160，有一段连线延迟 2.049 ns。

```text
vcount / pixel_y → 行译码 → 区域优先选择 sm_sel
                → sm_off / 读址加减 → LUTRAM 选择树 → o_rdata
```

在行 / 区域选择后形成明确的寄存边界，将“选哪段文字”和“计算字符地址、读取 RAM”分开。只保存后续会用到的选择结果及元数据，避免给整组候选描述符增加大批寄存器。保留原优先顺序、页面行为和参数语义。

现有小 RAM 已有同步读输出语义，问题是其前面仍串接了太多逻辑。强制 64×8 动态文字 RAM 使用 BSRAM 曾在本工程造成负收益，不作为首选。

### 3.4 P1-4：同步修复列选择到 RGB 的路径

位置：`rtl/ui/ui_render.v`，约 502～580、773～774、1075～1095 行；`vendor/verilog-reusable-modules/modules/hdmi_1024x600/rtl/disp_driver.v`。

路径 19：`Disp_DE.Q → Disp_Blue[7].D`，slack −2.046 ns。DE 数据扇出 161，首段连线 2.161 ns。实际跨过坐标门控、24 像素格列号计算、字模位选择以及图层选择，并非仅仅“最后 RGB 多路选择太慢”。

```text
DE → H_Addr → x+2 → /24 → 格内列号 → 字模位选择 → 图层混合 → RGB
```

结合 P1-3 设计统一的像素阶段，寄存恰当阶段的列号 / 位选择与图层控制，再输出 RGB。现有文字 ROM、动态 RAM、字模 ROM 的读延迟，以及 `x+2` 预读约定必须一起核对。只改地址延迟、位号或 `+2` 常量，都不足以证明画面相位正确。

若引入额外像素拍，文字、数值小数点、地图 / 路线、标记、摄像头背景、DE / HS / VS 均须在集成处对齐；帧切换与取图请求保持对应像素关系，双缓冲交换仍在正确帧边界。对外分辨率、时钟和页面布局不变。

先画一张逐拍表，列清“当前像素坐标、预读坐标、字符、字模行、列号、图层、RGB、同步信号”。仿真检查每行首尾、文字段边界、行切换、消隐区、页面切换、双缓冲交换，并比较六页实际 RTL 渲染图；以像素相位为准，不能只看测试通过数。

现有 `/24` 后乘 24 已使用移位相加，不再作为新优化重复提出。此前纯组合列号替换和独立列计数器试验有负收益或相位问题，不优先重试。

## 4. 为什么第一轮要覆盖四类路径

基于当前已列出的路径，假设其他路径和布线完全不变：

- 只修 IMU，仍有系统域 `cut_ok_r` 的 −2.090 ns，频率仍约受限在 45.27 MHz。
- 只修动态文字 RAM，仍有像素 RGB 的 −2.046 ns，频率仍约受限在 44.54 MHz。
- 只修 `nav_ctrl`，最差 IMU 和像素路径均原样存在。

这些是依据现有周期与 slack 做的瓶颈估算，不是优化后的频率预测。它们说明逐个微改后跑整轮布线，很可能花时间只观察到瓶颈轮换。

前四项是四个明确的路径族，并不是对全工程做大重构。分别保留可审查的差异和自检结果，首次布线验证组合结果；若退化，优先按“系统域两项 / 像素域两项”定位，不直接展开大量参数组合。

## 5. P2：资源复制只做一次受控试验

最新 `impl/pnr/cmd.do` 使用 `-timing`、place option 3、route option 2，没有 `-replicate`；`scripts/build_common.tcl` 也未显式启用 `replicate_resources`。不能把历史独立导航工程中“已启用复制”的状态套到本工程。

在结构优化完成且有一份完整对照结果后，可单独尝试 `set_option -replicate_resources 1`，核实实际 PnR 命令确实生效。仅改布线选项时，应复用同一份正确的综合网表；同时核对 app 和 vendor 源码都与该网表一致，不能只依赖脚本当前对 app 时间戳的检查。后续实施已发现，根目录 `build_pnr.tcl` 在新 Tcl 会话中仍会重新触发综合，不能仅凭入口名或注释认定已跳过；实况见[验证记录](Fmax优化验证_20261021.md)。

历史独立导航曾由 53.895 提升到 58.507 MHz，说明值得作为候选，但全车有不同扇出、DSP / RAM 分布和时钟域，不能承诺同幅度收益。当前高扇出证据使它值得一次测试，但结果确定性低于真实切开组合级，因此排在 P1 之后。

同网表、同约束、同其他选项对比系统 / 像素最差 slack、TNS、违例数、FF 及资源。若仅一个时钟变好、另一个显著退化，不仅凭最高单项 MHz 保留。禁止把数据复制思路用于自行复制时钟。

## 6. 控制验证成本

1. **先留基线**：保存本次源码标识、工具版本、SDC / CST、选项、综合网表与报告指纹，避免新构建覆盖唯一证据。
2. **先查已有数据**：需要更多路径时，先确认 IDE 时序分析器能否加载现有结果定向查询，不重新布线。已有 `tools/sta_timing_probe.tcl` 明确记录 `gw_sh` 不支持直接调用 `report_timing/get_pins`；该脚本实际会重新完整构建，本轮不拿它当廉价报告导出工具。
3. **逐项自检、检查语义**：按 P1-1～P1-4 处理，相关自检通过后再推进；不是每项都跑一次 PnR。
4. **综合作筛选**：确认预期的寄存边界真的存在，未被旁路 / 优化；检查新 DSP 输入输出寄存、CE、位宽和资源变化。综合不能替代实际布线 Fmax，但可提前淘汰没有实现预期结构的版本。
5. **第一轮完整验证**：四项完成后运行应用全回归和完整综合 / 布线；若此时无法证明像素相位正确，先修复测试，不消耗长布线。
6. **按结果再决定第二轮**：优先处理新报告中仍阻碍 50 / 49 MHz 的具体路径。只有结构已经改善而连线仍占主导时，进行 P2 单次复制试验；达标且余量可接受则停止试验。

每轮统一记录：源码 / 网表标识、改动范围、测试项数及关键周期、综合资源、物理资源、两个同域最差 slack / TNS / 违例数 / Fmax、全局 setup / hold、构建时间。内部增加延迟时记录新增周期；不把功能测试的运行耗时当作硬件计算周期。

## 7. 暂不投入的方向与独立问题

- 不先给地图读口加流水。历史独立导航仅增加约 0.042 MHz，还增加每次读取延迟，已撤回；当前最差路径也没有指向它。
- 不先做全局位宽压缩、状态机编码替换、强制 RAM 资源或布局区域约束；当前证据不足，容易改变其他路径的映射。
- 不重复已经实现的 ×24 移位相加、坐标换算流水等优化；旧报告中的提升不能重复记账。
- 不靠降低时钟、添加未经证明的 multicycle / false path 或删除原有功能达标。
- DDR 的相关时钟 setup / hold 另行核对生成时钟、相位和 IP 所需约束。前 8 条 setup 最差达到 −4.247 ns，不能未经核对就称其“工具误报”或“IP 自动保证”。这项是全工程收敛的独立问题，并非上述系统 / 像素 Fmax 的直接瓶颈。

本次仅完成报告与 RTL 的只读审查及方案整理，没有修改 RTL、约束或构建选项，没有运行新的综合、布局布线或下载。
