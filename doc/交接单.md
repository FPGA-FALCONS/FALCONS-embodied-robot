## 六、摄像头画面花屏：已解决（2026-10-24）

**结论**：排线信号完整性问题，与 RTL / 引脚分配无关。排线 = **1 根地 + 11 根信号（PCLK + D0–D7 + VSYNC + HREF）+ 30 cm** → 信号:地 = 11:1，回流挤一根地，地弹 0.5–1 V；9 根数据线并排 30 cm，串扰几百 mV；叠加后超出 LVCMOS33 的 1.3 V 噪声容限。**换 10 cm 级短杜邦线后画面正常**。

**三轮软件尝试全部无效、已回退**：① 降 PCLK（`ov5640_init_table_rgb.v` 的 `0x3824` 04→08、`0x3108` 02→01）；② IODELAY 加 1.2 ns（`ov5640_capture.v` 8 根数据线各串 `C_STATIC_DLY=96`）；③ 引脚重排（`falcons.cst` 按高云官方表：PCLK=B1 / D0=J2 / VSYNC=B2 / HREF=A1 / D1–D7 全变）。

**已排除、不要再试**：`0x4740` 采样沿（OV5640 手册 page 93 表 6-6：Bit[5] 0=Active low / 1=Active high，默认 `0x20`；工程正是 `0x20`，对应上升沿采样，`DVP_Capture.v` 用 `posedge PCLK` **正确**）、引脚分配 / 时钟网络、IODELAY、PCLK 降频、DDR3 时序（Fmax 89.9 MHz / TNS 0，且扭转外部排线能改变现象，板内 DDR3 不可能受其影响）。

**硬件改进**：缩短 ≤15 cm、补地 ≥4 根（每 2–3 根信号夹一根）、信号串阻 22–33 Ω（靠近 FPGA 端）。

## 七、时序：已收敛，不要再动

`e5f5950` 两域 Fmax **50.056 / 49.462**、同域违例 **0/0**、TNS 全 0，已达标。

**四条已试过并失败的优化**（详见 `时序违例分析_20261021.md`、工作记录 §74~§77）：

| 编号 | 改哪里 | 实测 |
|---|---|---|
| A1 | `imu_top.v` `calib_sum` 48→32 位 | imu slack −0.107 → **−1.023**，连 `nav_free`/`odom` 7 条一起恶化 |
| B1' | `ui_render.v` 除法拆移位（零 DSP） | pixel 最差 −0.081 → **−1.004**，LUT 反多 74 个 |
| 步 1 | `ui_render.v` pixel 位宽 12→6 | Setup 84 → **154**、Hold 2605 → **3721** |
| 方案 A | `ui_render.v` `lg_col` 解耦 | 目标路径消失，但 `vcount → o_rdata` −0.052 → **−0.594**，两域 Fmax 一起降 |

★ **pixel 域属于「多条近临界路径并存」**（正 slack 邻居只差 +0.052~+0.110），**单点优化必被下一条接替；要动就得成组动**。
★ **教训**：不要从逻辑结构推断瓶颈（综合器能把常数除法压得很浅，手写分解换来一串 LUT 级联）；**P&R 对布图扰动极敏感，未改动的模块也会被推过线**。
★ **纪律**：一次只改一处、每步单独综合；判断有效性前先确认两版输入逐字节相同；改完必须说清「哪些条消失了」而不只是总数下降。

## 八、整车语音运动（2026-10-24 现场验收）

主机侧 `host/ai_coordinator` 已能把**单条语音指令**变成 MOT1 帧，经 CH340 串口发给 FPGA，并在主机窗口结束时写 STOP。链路：USB 麦克风 → ASR（SenseVoiceSmall INT8）→ 语义解析 `preset_control` → 动作窗口 → MOT1 12 字节帧 → FPGA。

- 板端根 `~/workspace/falcons_ai_coordinator_20261024_r1`，active release `releases/fullstack_20261024_181624_c7ae91`；进程为 user 单元 `falcons-ai-coordinator.service`，操作前需 `export XDG_RUNTIME_DIR=/run/user/$(id -u)`。
- 串口 `/dev/serial/by-id/usb-1a86_USB_Serial-if00-port0`（CH340）；麦克风 `plughw:CARD=MIC,DEV=0`；录音提示音播放 `plughw:CARD=Device,DEV=0`（USB 音响）。**按卡名寻址**，插拔导致 card 编号变化不影响配置。
- **五条指令已验收**（车轮架空）：前进 / 后退 / 停 / 左转 / 右转 均按预期发帧并停车，方向由用户现场目视确认；录音窗口 3 秒，开始/结束各有提示音。
- 只接受**单一、立即**的运动指令：两条连说、句子里夹带解释、静音都会拒绝且**不发帧**；`POST /text` 命中 preset_control 时同步返回，`POST /capture`、`POST /audio` 才走 job 队列（要轮询 `/jobs/<id>`）。
- **口径红线**：`stop_frame_sent`、`executed`、`tx_frames` 只证明主机写入了串口，**不是 FPGA 或电机的物理完成回执**；`gateway.state=awaiting_firmware_hello` 是 FAM1 状态，不伪造 hello、不把 FPGA 的 CSV 当 MOT1 ACK。"方向正确"只来自现场目视。
- 提示音只做操作提示（`recording_cue.py`，配置 `microphone.cue`），不授权动作、不判定完成；播放失败只记审计，不影响采集。
- 完整现场记录与逐轮数据见 [`evidence/voice_motion_execution_20261024/现场只读检查_195220.md`](evidence/voice_motion_execution_20261024/现场只读检查_195220.md)。
