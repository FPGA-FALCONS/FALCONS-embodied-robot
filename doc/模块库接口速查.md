## 1. `motor_tb6612` —— 四路直流电机驱动 + 编码器测速 + 堵转保护

### 1.1 一句话用途

面向 **TB6612FNG** 类双/四路电机驱动板的完整电机控制模块包，提供「给占空比 → 电机转 → 读编码器 → 算转速 → 卡住时自动保护」的全链路，纯定点、无浮点、无厂商 IP。

### 1.2 包内文件清单

| 类别 | 文件 |
| --- | --- |
| `rtl\` | `motor_pwm.v`（原子：单路 TB6612 三线驱动）、`quad_decoder.v`（原子：正交解码）、`speed_measure.v`（原子：定窗口测速 M 法）、`stall_detect.v`（原子：堵转检测与保护）、`motor_unit.v`（封装：单路完整）、`motor_top.v`（集成：多路 + STBY 门控） |

### 1.3 ★ 顶层模块端口表

**`motor_unit`（单路完整，源码 `rtl/motor_unit.v`）**

| --- | --- | --- | --- |
| `i_clock` / `i_reset_n` | input | 1 / 1 | 系统时钟 / 异步低电平复位 |
| `i_enable` | input | 1 | 1 = 允许驱动；0 = 停止（按 `i_brake` 决定滑行/刹车） |
| `i_dir` | input | 1 | 0 = 正转，1 = 反转 |

| `o_delta` | output | `signed [31:0]` | 窗口转速增量（有符号，单位 = 计数 / `WINDOW_MS`） |
| `o_delta_valid` | output | 1 | 窗口结束脉冲 |

### 1.4 ★ 参数表

**`motor_unit` / `motor_top` 公共参数**

| 参数名 | 默认值 | 含义（改它会怎样） |
| --- | --- | --- |
| `CLK_FREQ_HZ` | `50_000_000` | 系统时钟频率。换时钟只需改它 |
| `PWM_BITS` | `11` | PWM 计数器位宽 → 周期 `2^N` 拍 → **24.41 kHz** @50 MHz。改它会同时改 PWM 频率（公式 `CLK_FREQ_HZ / 2^PWM_BITS`）且必须保持"周期是 2 的幂" |
| `FILTER_BITS` | `3` | 编码器去毛刺长度取 2 的幂的指数（3 → 连续 8 拍一致才认可）。改小会放宽最高可测频率，改大会更容易滤掉毛刺 |
| `WINDOW_MS` | `10` | 测速窗口（ms），**也是堵转判定窗口的时基**（10 → 100 Hz 出数）。改它会同时改变 `o_delta` 数值与转速换算系数，两者同步、结果一致 |
| `INV_DIR` / `INV_DIR_VEC` | `0` / `4'b0000` | **电机方向取反**（每路一位） |
| `ENC_INV_DIR` / `ENC_INV_DIR_VEC` | `0` / `4'b0000` | **编码器计数方向取反**（每路一位） |
| `STALL_STARTUP_WINDOWS` | `30` | 启动宽限（窗口数）→ 30×10 ms = **300 ms** |
| `STALL_WINDOWS` | `20` | 判定窗口数 → 20×10 ms = **200 ms** |
| `STALL_DUTY_TH` | `200` | 占空比阈值，低于此值不判定（≈10% of 2048） |
| `STALL_MOVE_TH` | `300` | 净位移阈值（计数），≈1.8° @60000 计数/转 |

**原子模块独有参数**

| 模块 | 参数名 | 默认值 | 含义 |
| --- | --- | --- | --- |
| `motor_pwm` | `CLK_FREQ_HZ` / `PWM_BITS` / `INV_DIR` | `50_000_000` / `11` / `0` | `INV_DIR` = 1 则反转方向语义（不改接线就反过来） |
| `quad_decoder` | `CLK_FREQ_HZ` / `COUNT_BITS` / `FILTER_BITS` / `INV_DIR` | `50_000_000` / `32` / `3` / `0` | `COUNT_BITS` = 位置计数位宽；`INV_DIR` = 1 交换计数方向；`FILTER_BITS` 最小 1，设 0 会被当成 1（即 2 拍确认） |
| `speed_measure` | `CLK_FREQ_HZ` / `WINDOW_MS` / `COUNT_BITS` | `50_000_000` / `10` / `32` | `COUNT_BITS` **须与 `quad_decoder` 一致** |
| `stall_detect` | `STARTUP_WINDOWS` / `STALL_WINDOWS` / `DUTY_TH` / `MOVE_TH` | `30` / `20` / `200` / `300` | 同 `motor_unit` 的 `STALL_*`，模块内**不带 `STALL_` 前缀** |

**关键换算**

| 量 | 公式 |
| --- | --- |
| PWM 频率 | `CLK_FREQ_HZ / 2^PWM_BITS` |
| 占空比 | `i_duty / 2^PWM_BITS`（`i_duty = 2^(PWM_BITS-1)` 就是精确 50%） |
| 车轮转过的圈数 | `o_count / COUNT_PER_REV`，其中 `COUNT_PER_REV = PPR × 4 × 减速比` |
| 转速 | `rpm = o_delta × 60000 / (COUNT_PER_REV × WINDOW_MS)`；500 PPR + 减速比 30 → `COUNT_PER_REV = 60000`，退化为 **`rpm = o_delta / WINDOW_MS`**（当前即 `rpm = o_delta / 10`） |

### 1.5 时钟与频率要求

- **单时钟域**，纯 RTL，无厂商 IP。
- 系统时钟默认 **50 MHz**（实板为 ACG720 / GW5AT-138B，50 MHz）。
- 时序约束只需一条 `create_clock`；ACG720 实测 **Fmax ≈ 110 MHz**，资源约 **2800 LUT / 3%**。
- 编码器输入是异步信号，模块内部已做两级同步 + 数字去毛刺，**不需要**用户再加同步器。

### 1.6 依赖的其他包

**无。** 纯 RTL、单时钟域，不依赖任何其他包或厂商 IP。

### 1.7 验证 / 上板状态

- 仿真：**5 个测试平台全部 PASS，`Errors: 0 / Warnings: 0`**。
- 实板：已在 **ACG720 + WHEELTEC D24A（2×TB6612FNG）+ MG513P30_12V + GMR 500PPR** 上完成验证：四路驱动、编码器测速与极性统一、堵转保护（锁存停机）、上电不窜车；手转车轮一圈 `o_count` 变化本车实测 **61657**（预期 60000）。
- 已知局限（README 第六节原文要点）：测速是 M 法（低速量化误差大，13PPR 低速精度差，需 M/T 法或加大 `WINDOW_MS`）；堵转判据依赖编码器（编码器故障/断线会误报堵转）；驱动器电流保护不在本包内（MG513 堵转 3.2 A = TB6612 峰值 3.2 A，保护动作前的 200 ms 内仍承受峰值电流）；`motor_top` 路数固定 4（需改 `generate` 上界）；无位置/速度闭环（PID 需上层实现）；无 STBY 软启动（阶跃使能，启动浪涌接近堵转值）。

### 1.8 ★ README 明确写出的坑与注意事项

1. **极性标定的顺序不能反**：必须先校电机方向（`INV_DIR_VEC`）再校编码器符号（`ENC_INV_DIR_VEC`）。因为**反电机会同时翻转转向和计数符号**，若先校符号再改方向，符号标定会作废、得重来。
2. **`INV_DIR_VEC` 与 `ENC_INV_DIR_VEC` 是两个正交参数，不可互相替代**：反编码器只翻计数符号（转向不变）；反电机翻转向也翻符号；两个都反 = 回到原状。左右电机镜像安装时两侧计数符号天然相反，必须反其中一侧。
3. **默认参数下必须自己标定**："本包不写死任何标定值"，默认 `INV_DIR_VEC = 4'b0000` / `ENC_INV_DIR_VEC = 4'b0000`。README 给出的参考值（WHEELTEC D24A、左右镜像安装、6PIN 排线一体连接）是 `ENC_INV_DIR_VEC = 4'b1010`（**左侧不动、右侧反相**），**明确说明这不是默认值**。换车、换电机、换驱动板、重插排线后必须重新标定。
4. **堵转判据用「净位移」而不是「转速为 0」**：60000 计数/转时 1° = 167 计数，堵转振动与低速正常转动的单窗口 `delta` 在同一量级（±167 vs ≈150），单窗口阈值取小则漏报、取大则误报，**无解**。因此判据是"累加 `delta` 得净位移，连续 200 ms 内净位移不足 300 计数（≈1.8°）即判堵转"。
5. **堵转后锁存停机，不自动重试**：堵转通常意味着"车被卡住了"，继续给功率只会持续加热驱动芯片；自动重试会反复冲击峰值电流。需显式给 `i_stall_clear` 才恢复。
6. **带载启动要加大宽限**：地面行驶时建议把 `STALL_STARTUP_WINDOWS` 调到 **50（500 ms）**，否则容易"一启动就报堵转"。
7. **`WINDOW_MS` 与堵转窗口参数联动**：堵转参数以"测速窗口"为单位，若把 `WINDOW_MS` 改成 20，则 20 个窗口变成 400 ms，需同步调整。
8. **`motor_top` 路数固定为 4**（`generate` 里的常量）。需要 2 路或 6 路时改那一处循环上界，或直接例化 `motor_unit` 若干次。
9. **上电安全三层防护缺一不可**：① `.cst` 里给电机控制引脚（13 根电机输出）加 `PULL_MODE=DOWN`；② STBY 到 GND 加 **10 kΩ 下拉**；③ **驱动板 STBY 跳线帽必须拔掉**（否则永久使能，失去软件急停）。RTL 复位期间强制 `IN1=IN2=0`、`PWM=0`。
10. **STBY 与刹车语义不同**：清零 `i_enable` 且 `i_brake=1` → 短路刹车（有保持力）；清零 `i_enable`（STBY 自动变 0）→ 整片待机（电机自由滑行）。
11. **电源与接地**：电机电源独立于 FPGA 供电；**不要**用驱动板的稳压输出给 FPGA 供电；FPGA 地与驱动板 GND 单点相连（星形接地）。`J5 pin2` 是**唯一的跨板共地针**，必须接。
12. **电平余量"贴边"**：驱动板逻辑侧若是 5 V，3.3 V 直驱属"贴边"（TB6612 的 VIH = 0.7×VCC）。本项目 D24A 实测可用；若出现电机不转/时转时不转，加 **`74HCT245`（HCT 而非 LVC）** 提升到 5 V。GPIO0 bank 跳线须保持 3.3 V。
13. **PWM=L 期间 TB6612 是"短路刹车"**（drive/brake 模式），响应快但发热。若电机偏热，可改成"PWM 固定高、用 `IN1` 打 PWM"的 drive/coast 接法。
14. **排线方向**：母头面对插孔的方向与公针有**镜像**，插反会整排错位——**综合能过、上板全错**。按 Pin 号核对两端并确认 Pin1。
15. **编码器去毛刺限制最高可测频率**：8 拍 @50 MHz = 160 ns，要求信号半周期 > 160 ns（上限约 3 MHz），远高于任何编码器输出。**不要用 RC 硬件滤波代替**数字滤波（RC 会拖慢边沿、反而更容易误判）。
16. **两位同时跳变（如 00→11）不计数**：宁可漏一步也不把方向判反。
17. **`speed_measure` 必须接同一个清零信号**：上层若清零编码器位置而测速模块还留着旧基准值，下一个窗口会算出巨大假增量；因此 `i_clear` 要与 `quad_decoder` 的清零信号同源。
18. **约束文件只含电机/编码器引脚**；按键、LED、串口等属板载资源，按所用工程自行添加（参考 ACG720 时钟 `Y18`、串口 `M15`、LED `M22/N22/L21/K21/K22/J22/H22/M21`）。
19. **命名规范**：后缀 **`_VEC` = 多路向量**（`motor_top`），**无后缀 = 单路标量**（`motor_unit` / `motor_pwm`）。

## 2. `imu660ra` —— IMU660RA（BMI270）六轴驱动

### 2.1 一句话用途

`imu660ra` 驱动逐飞 IMU660RA 模块（内部芯片为 Bosch **BMI270**），通过 SPI 完成初始化并周期性读取六轴数据，对外直接输出换算好的物理量。

### 2.3 ★ 顶层模块端口表

**`imu_top`（源码 `rtl/imu_top.v`）**

| 端口名 | 方向 | 位宽 | 含义与单位（时钟域） |
| --- | --- | --- | --- |
| `i_clock` | input | 1 | 系统时钟，默认按 50 MHz 设计 |

### 2.5 时钟与频率要求

- **单时钟域**（`i_clock`，默认按 50 MHz 设计），纯 RTL，无厂商 IP 依赖。
- SPI Mode0（CPOL=0, CPHA=0）、MSB first，**SCK 由寄存器翻转产生**，不是内部时钟，因此不产生第二时钟域。
- `i_imu_miso` 相对系统时钟是异步的，但 SCK 远慢于系统时钟（每个 SCK 半周期有多个系统时钟），模块**在 SCK 上升沿对应的系统时钟周期采样，不需要额外两级同步器**。**若把 SPI 速率提高到系统时钟的 1/8 以上，需重新评估此处。**
- 实测：**杜邦线连接下 SCK 建议 1~5 MHz**；8.33 MHz 会导致 8 KB 配置加载失败。
- 时序约束只需一条 `create_clock`（见 `constraints/imu660ra.sdc`）。

### 2.8 ★ README 明确写出的坑与注意事项

1. **SPI 速率不要贪高**：实测杜邦线连接下 **8.33 MHz 会导致初始化失败**——`CHIP_ID` 只传 24 bit 侥幸通过，而 8 KB 配置要传 **65536 bit**，只要 1 个 bit 出错，`INTERNAL_STATUS` 就不会返回 `0x01`。默认 1 MHz 稳定；提速按 1 → 2 → 4 MHz 逐步试，**每次都要重新确认 `o_init_done` 是否拉高**。
2. **`SCK/MOSI/CS` 建议加 4.7 kΩ 上拉**；`MISO` 已在约束中配内部上拉。
3. **初始化顺序有意调整**：逐飞原码是"先 `PWR_CTRL` 使能、再配量程/ODR"，本模块改为**先配量程/ODR，最后写 `PWR_CTRL` 使能**，规避"传感器使能状态下配置寄存器写入被忽略"的风险。
4. **零偏只在本模块扣一次**：`CALIB_APPLY=1` 且 `calib_done=1` 时，`o_gyro_*` 已经是扣除零偏后的值。下游姿态模块应把它**当作已去零偏**，不要重复扣除。**双重扣除**会表现为"姿态往反方向慢慢转"，极难定位。
5. **`o_data_valid` 与 `o_acc_valid` 语义不同，不要混用**：`o_data_valid` **只在 RUN 态产生**（标定期间陀螺输出尚未更新，仍是复位值，给出 valid 会让下游把无效角速度当成有效数据）；`o_acc_valid` **在标定态与 RUN 态都产生**（标定期读的同样是 `0x0C` 起 12 字节，**加速度数据完全有效**）。**若下游需要在标定窗口内采加速度样本（最典型是安装倾斜标定，如 `gyro_tilt_comp`），必须用 `o_acc_valid`。用 `o_data_valid` 会在标定期一个样本都收不到，而且不报错。**
6. **标定期间不要碰车模**：上电后约 **0.6 秒**内保持静止，否则会判为标定失败（LED 显示 `C`）。
7. **为什么必须有"绝对门禁"**：**匀速转动时陀螺读数恒定、抖动为 0**——只靠抖动判据会看到"完美静止"，把转动角速度当成零偏写进去（例如以 50 °/s 匀速转动时 bias 被写成 50 °/s），而且 `calib_done=1`、**没有任何报错**，之后姿态持续漂移，比"标定失败"危险得多。**边界上的固有限制**：单靠陀螺，物理上无法区分"零偏 8 °/s"和"实际以 8 °/s 匀速转动"（惯性原理），最实际的防护是**上电后不要碰车模**。
8. **标定失败时不会写入错误值**：`o_calib_fail=1`，`bias` 保持 0，`CALIB_APPLY` 自动失效（因 `calib_done=0`），输出退回未扣除的原始换算值；数据读取照常工作。调参建议：先确认上电时确实静止；仍失败则把 `CALIB_DEV_TH` 调大（噪声大）或 `CALIB_ABS_LIMIT` 调大（零偏大）。
9. **`SA0/SDO` 在 SPI 模式下就是 MISO**，不要把它当 I2C 地址选择脚去接高/低。
10. **SCL 与 SDA 不要接反**：对调后 SPI 完全不通，症状很像"模块坏了"。
11. **J2 供的是 5 V**（模块板载 LDO）；须确认 **GPIO0 bank 跳线为 3.3 V**。
12. **推荐把 `o_state_dbg` / `o_err_code` / `o_calib_busy` / `o_calib_fail` 接到 LED 或 GAO**：仅用"成功/失败"两个指示灯无法区分**通信问题 / 配置问题 / 标定问题**（实测 `led[7:4]=0010` 直接把问题锁定在 `INTERNAL_STATUS` 校验）。LED 建议接法：`o_calib_busy` → `0xB`，`o_calib_fail` → `0xC`，`o_err_code` → `1`/`2`，其余看 `o_state_dbg[3:0]`（`14`=RUN）。
13. **SPI 占用**：1 kHz 采样下每帧 14 字节 ≈ 112 µs（1 MHz 时），占周期 11%，余量充足（理论上限约 8.9 kHz）。
14. **不用 `$readmemh`**：8192 字节数据已内嵌在 `bmi270_cfg_rom.v`，消除了对外部文件与综合工作目录的依赖；修改配置数据后要运行 `python tools/gen_cfg_rom.py` 重新生成。
15. **综合后核对 ROM 的坑**：本模块会被实现为 `pROM` 原语（8 位宽会拆成 4 个 `BIT_WIDTH=2` 的 pROM，每个 `INIT_RAM` 参数装 128 个 2 位数据、低位对应低地址）。**不能**直接按"每 2 个 hex 字符 = 1 字节"读 `INIT_RAM`，必须按位宽还原。
16. **加速度合成模值是判断加速度计是否正常的最佳判据**：`√(ax²+ay²+az²) ≈ 1000` mg，**不论怎么摆放都成立**。

### 3.7 验证 / 上板状态

- 单元测试 `gyro_tilt_comp_tb`：**9 个用例**——① `[0,0,1000]` 水平 → k = 1.0（65536）直通；② `[600,0,800]` 倾斜 36.87° → k = **1.25（81920）**；③ `[259,0,966]` 倾斜 15°（验证非整除取整）；④ `[0,600,800]` 横向分量在 y 轴；⑤ `[600,0,-800]` 倒置 → k = **−1.25**；⑥ `[1000,0,500]` 倾斜 63° → 限幅 2.0 并置 `tilt_fail`；⑦ 只给 100 个样本 → 样本不足**不补偿**并置 `tilt_fail`；⑧ 计算期间 `o_calib_busy` 正确拉起/释放；⑨ 交替样本的求平均功能。
- 集成测试 `tilt_integration_tb`：**3 个用例**（`[600,0,800]` → 81920；`[0,0,1000]` → 65536；`[600,0,−800]` → −81920），把 `imu_top` + `bmi270_model` + `gyro_tilt_comp` 按**真实连接方式**接起来。
- 上板：库根 README 明确"这三者的完整上板链路（六轴 + 倾斜补偿 + 偏航角 + 串口 CSV 输出）已在 ACG720 实板验证通过"。
- 精度：开方取整带来约 **0.1%** 的增益误差，对应"转 90° 差 0.09°"。

### 3.8 ★ README 明确写出的坑与注意事项

1. **★ `i_sample_valid` 必须接 `imu660ra` 的 `o_acc_valid`，绝对不能用 `o_data_valid`**：`imu660ra` 的 `o_data_valid` **只在 RUN 态产生**（标定期间陀螺输出尚未更新）。若把 `i_sample_valid` 接到 `o_data_valid`，**标定窗口内一个样本都采不到**，增益会永远停在 1.0（`o_tilt_fail=1`）——**而单元测试完全发现不了它**。这个缺陷最终由 `sim/tilt_integration_tb.v` 的集成测试捕获（已验证：把连接改回 `o_data_valid` 时该测试立即报 5 个错误）。
2. **跨模块的握手/时序契约必须用集成测试覆盖，单元测试无法替代。**
3. **`i_calib_start` 接上游的"标定进行中"信号**（`imu660ra` 的 `o_calib_busy`）；累加由 `i_calib_start` 门控，独立于状态机。
4. **`k` 自动带符号**（IMU 倒置安装时 `a_z < 0` → `k < 0` → 输出符号被自动翻回），**不需要安装方向配置位**。
5. **标定发生在「上电那一刻」，补的是标定时的那个姿态**：正确用法是让 IMU **保持目标倾斜姿态**上电、静止等标定结束、之后开始运动；**无效用法**是上电时水平放着、标定完再倾斜着用（`k` 仍是 1.0，补偿无从谈起）。这是设计使然。
6. **只补偿固定倾斜**：载体动态侧倾/俯仰时真实倾斜在变，而模块还在用旧值 → 残差与「姿态变化量 × 角速度」同阶。旋转轴明显偏离竖直时本补偿也不适用。
7. **不解决 yaw 的长期漂移**——重力对偏航无约束，这是 `yaw_integrate` 层面的原理性限制。
8. **倾斜 > 60° 时增益被限幅到 2.0**，补偿不完整且 `o_tilt_fail=1`。
9. **标定前 `o_gyro_z` 直通**（`k` 复位值为 65536），所以本模块不需要"未就绪"的处理，直接串在链路上即可。
10. **样本不足会放弃补偿**（`k` 保持 1.0）并置 `o_tilt_fail`——例如零偏标定超时时。
11. **输入单位必须是 int16 mg 与 int32 0.01 °/s**；`k` 的推导依赖 `a_z / |a_B|` 这个纯比值，**与加速度单位无关**，**但陀螺的单位必须与下游积分模块一致**。
12. **倾斜标定与零偏标定发生在同一姿态下**，所以零偏扣除不受影响。

## 4. `yaw_integrate` —— 偏航角积分

### 4.1 一句话用途

把陀螺 Z 轴角速度积分成偏航角。纯定点、**零乘法器**、无浮点，输出 ±180° 回绕角。

### 4.2 包内文件清单

| 类别 | 文件 |
| --- | --- |
| `rtl\` | `yaw_integrate.v`（单文件，无子模块） |
| `sim\` | `yaw_integrate_tb.v`（**11 个用例**）、`run_test.do` |
| `constraints\` | 无 |
| `examples\` | 无 |

### 4.3 ★ 顶层模块端口表（`yaw_integrate`，源码 `rtl/yaw_integrate.v`）

| 端口名 | 方向 | 位宽 | 含义与单位 |
| --- | --- | --- | --- |
| `i_clock` | input | 1 | 系统时钟，默认按 50 MHz 设计 |
| `i_reset_n` | input | 1 | 异步低电平复位（异步复位、同步释放） |
| `i_gyro_z` | input | `signed [31:0]` | Z 轴角速度，**int32，单位 0.01 °/s**，应为**已扣零偏**的值 |
| `i_sample_valid` | input | 1 | 样本更新脉冲（一周期宽），锁存 `i_gyro_z` |
| `i_enable` | input | 1 | 1 = 正常积分；0 = **冻结**且 yaw 强制保持 0 |
| `i_clear` | input | 1 | 清零脉冲（电平或单周期脉冲均可），**优先级高于 `i_enable`** |
| `o_yaw` | output | `signed [31:0]` | 偏航角，**int32，单位 0.01°**，范围 `[-18000, +18000)` |
| `o_yaw_valid` | output | 1 | 跟随 `i_enable`（打一拍），指示 `o_yaw` 有效 |
| `o_deadzone_hit` | output | 1 | 当前样本是否被静止死区归零（调阈值时观察用） |
| `o_gz_eff` | output | `signed [31:0]` | 死区处理后的角速度，0.01 °/s（调试观察用） |

接口风格为"寄存器直出 + 单周期 valid"：`o_yaw` 一直挂在总线上，随时可读。

### 4.4 ★ 参数表

| 参数名 | 默认值 | 含义（改它会怎样） |
| --- | --- | --- |
| `CLK_FREQ_HZ` | `50_000_000` | 系统时钟频率，用于计算分频系数 |
| `INT_RATE_HZ` | `1024` | 积分节拍频率。**必须取 2 的幂**，否则定点增量不再等于 `gz`（见 4.8 第 1 条） |
| `DEADZONE_EN` | `1` | 1 = 启用静止死区；设 0 则忠实积分一切角速度，代价是静止时 yaw 会缓慢漂移 |
| `DEADZONE_TH` | `30` | 死区阈值，单位 0.01 °/s（30 = 0.3 °/s）。**严格小于才归零**，等于阈值时不归零 |

**数据格式**

| 量 | 类型 | 单位 | 范围 |
| --- | --- | --- | --- |
| 输入 `i_gyro_z` | `int32` | 0.01 °/s | ±200000（±2000 dps） |
| 输出 `o_yaw` | `int32` | 0.01 ° | `[-18000, +18000)`，即 ±180.00° |

### 4.5 时钟与频率要求

- **单文件、纯 RTL、单时钟域**，无厂商 IP、无其他模块依赖。
- 系统时钟默认 **50 MHz**（`CLK_FREQ_HZ`）。
- **积分节拍 `INT_RATE_HZ` 取 1024 Hz**（不是 1000 Hz）：`50 MHz / 1024 = 48828.125`，取分频系数 **48828** 得实际节拍 **1024.0026 Hz**（误差 **2.6 ppm**，可忽略）。
- **时钟域数量：1**。时序约束只需一条 `create_clock`。
- **与上游采样节拍完全解耦**：`i_sample_valid` 只负责把最新样本锁存进 `gz_hold`，积分按本模块自己的等间隔节拍走；若采样与积分同拍，用组合直通的新值（不延迟一拍）。

### 4.6 依赖的其他包

**无。** "本模块不依赖其他任何模块"，只吃「角速度 + 样本脉冲 + 使能 + 清零」四个信号，可接到任何角速度源上。

### 4.7 验证 / 上板状态

- 仿真 `yaw_integrate_tb` 覆盖 **11 个用例**：① `i_enable=0` 冻结时 yaw 恒为 0；② 静止不漂；③ 90 °/s 分 4 段积分到 90.00°；④ 转满 +180° 正确回绕为 −180°；⑤ −270° 等价于 +90°；⑥ 0.2 °/s（< 阈值）被死区吞掉；⑦ 0.3 °/s（== 阈值）**不**被吞掉（边界语义）；⑧ 负向死区与负向越过阈值；⑨ 样本锁存（ZOH）；⑩ `i_clear` 立即清零；⑪ 冻结后解冻从 0 重新积分。测试通过 `dut.int_tick` 直接按**积分节拍**计数，期望值都是节拍数的精确倍数，**不存在舍入歧义**。
- **上板验证判据**（配合 `imu660ra`）：静止 60 秒 → yaw 漂移 < 5°（500 个 0.01° 单位）；绕竖直轴转 90° → `o_yaw` ≈ ±9000，误差 < 5%；按清零键 → yaw 立刻变 0。
- 典型漂移量级：若标定后残余偏置 0.02 °/s，则**每分钟漂 1.2°**。

### 4.8 ★ README 明确写出的坑与注意事项

1. **`INT_RATE_HZ` 必须是 2 的幂**（1024 / 512 / 256 均可）。若改用 1000 Hz，`dt` 不是 2 的幂，每节拍就得做 `gz × 65.536` 这样的定点乘法——既占 DSP 又引入截断误差。这是模块的核心设计前提，**改了它定点增量恒等式就不成立**。
2. **不要重复扣零偏**：上游 `imu660ra` 的 `o_gyro_z` 在 `CALIB_APPLY=1` 且 `calib_done=1` 时**已经扣过零偏**，本模块不再做任何零偏处理。
3. **死区阈值"严格小于才归零"**，等于阈值时不归零（`DEADZONE_TH = 30` 时 0.3 °/s 不会被吞掉）。
4. **只归零、不扣除阈值**：扣除阈值会给慢速转动引入恒定偏差（真实 0.3 °/s 的转动会被完全抹掉），而"归零"的行为更容易预测和调试。代价是**比阈值更慢的匀速转动会被完全吞掉**。
5. **死区阈值怎么定**：观察静止时 `gz` 的波动范围，取波动上限。对四驱小车这类应用，正常转向远快于 1 °/s，阈值放到 100（1 °/s）也不影响使用。
6. **`i_enable = 0` 会把 `acc` 强制为 0 且不积分**，回到 1 后从 0 重新开始。典型接法是接上游的"零偏标定已完成"，使 **yaw 的零点正好对应"载体静止、标定结束"那一刻**。
7. **`i_clear` 优先级高于 `i_enable`**，可接按键（"按一下归零"）或软复位。
8. **上游 ODR 低于采样节拍不会破坏积分正确性**：这等价于**零阶保持（ZOH）积分**，5 个节拍合起来正好是 `ω × 5 ms`，结果正确，只多了半个 ODR 周期（2.5 ms）的相位滞后。**修改上游的采样率不会破坏本模块的积分正确性。**
9. **无圈数信息**：输出回绕在 ±180°，转满一圈后无法区分圈数（±180° 与 +180° 是同一个角度）。若下游要做闭环，需自行处理跨边界时的 ±360° 跳变。
10. **要求旋转轴竖直**：本模块积分的是**本体 Z 轴**角速度，IMU 倾斜时会引入 `cos α` 标度误差，**需配合 `gyro_tilt_comp` 模块补偿**。
11. **yaw 长期漂移不可消除**：重力对偏航**没有任何约束**，纯 6 轴方案 yaw 不可观测，漂移是**原理性**的，需磁力计等外部观测。
12. **无在线零偏重估**：依赖上游的开机标定；温漂会以缓慢漂移的形式体现。
13. **输入若不是"0.01 °/s"的 int32，需要先换算到该单位**，否则定点增量恒等式不成立。
14. **回绕的数学保证**：折回只需一次加减——单节拍最大增量是满量程 2000 °/s 对应的 200000 u（≈195°），加减一次必然回界。

### 5.5 时钟与频率要求

- **单时钟域**：`i_clock` 同时驱动 UART 位时序与 FIFO。默认 **50 MHz**（示例 `uart_echo_top` 用 50 MHz，`.sdc` 约束 20 ns 周期，与 RTL 的 `CLK_FREQ_HZ=50_000_000` 一致）。
- 无派生时钟，`CLKS_PER_BIT` 由时钟与波特率整数算出。
- 异步串口输入内部先经两级寄存器同步。
- **时钟域数量：1。**

### 5.6 依赖的其他包

- `uart_byte_tx` / `uart_byte_rx`：**无依赖**（自包含）。
- **`uart_tx_queue` 与 `uart_rx_queue` 依赖 `sync_fifo`**（内部例化 `sync_fifo #(.DATA_WIDTH(8), .ADDR_WIDTH(FIFO_DEPTH_LOG2))`）。把队列加入工程时**必须同时把公共 `sync_fifo.v` 加入工程**。

### 5.7 验证 / 上板状态

- 仿真：`uart_queue_loopback_tb`（UART 收发队列回环测试）；库内原有用例在 M10 示例回归中也被重新执行（**8E1，复位后立即发送**），均通过——"UART 回环源文件没有改动"。
- `RECOVERY_EN=1` 模式：M10 示例中执行了**启动恢复测试**（`uart_rx_recovery_tb` 覆盖 480 个启动位相、波特率 ±1%、连续 256 种字节及单 error break 恢复）。

### 5.8 ★ 文档明确写出的坑与注意事项

1. **队列必须同时加入 `sync_fifo.v`**：库根 README 明确"只需要单字节收发时，可以直接使用 `uart_byte_tx` 或 `uart_byte_rx`；需要连续收发或临时缓存数据时，优先使用 `uart_tx_queue` 和 `uart_rx_queue`，**并同时把公共 `sync_fifo.v` 加入工程**"。
2. **`RECOVERY_EN` 的语义**（`THIRD_PARTY_NOTICES.md` 明确记录的本地修改）：默认 0 保留既有起收和帧错误处理；设为 1 时在复位/帧错误后**等待连续 1.5 位高电平并以下降沿起收**。接口及原有参数保留。
3. **valid/ready 握手必须保持**：`i_tx_valid` / `i_rx_ready` 等握手信号在完成握手前必须保持；RTL 文件头的示例代码给出了标准的"收到 request → 置 valid → `valid && ready` 时清 valid"写法。
4. **`o_rx_error` 是单周期脉冲**，覆盖校验、停止位或输出溢出错误，需要上层自己锁存（示例 `uart_echo_top` 就是锁存到 LED、复位清除）。
5. **示例的管脚和时钟约束适用于 ACX720/GW5AT-138B**；移植到其他开发板时需要替换 `.cst` 并按实际输入频率修改 `.sdc` 和 `CLK_FREQ_HZ`。
6. **示例约束在包外**：`uart` 包内没有 `constraints\`，约束只存在于 `examples\` 下，且仅供该示例的顶层使用。
7. **ModelSim 脚本限制**（库根 README 的全局警告）：`sim\run_test.do` 用的是 `vsim work.xxx / run -all / quit -sim` 的**内建写法，只适用于 ModelSim GUI 的 Transcript**。在 `-c` 命令行模式下，测试平台里的 `$finish` 会**终结整个 vsim 进程**，**不能**把多个测试串在同一个 do 脚本里跑（那样只有第一个会执行，后面静默跳过、且不报错）。命令行下请给每个测试开独立进程：`vsim -c -do "run -all; quit -f" work.<测试平台名>`。

## 6. `sync_fifo` —— 单时钟同步 FIFO

> ⚠️ **该包没有 `README.md`**。本节内容来自 RTL 文件头注释（`rtl/sync_fifo.v` 第 1~49 行）与库根 `README.md`。

### 6.1 一句话用途

单时钟同步 FIFO 模块，用于在同一个时钟域内缓存数据，协调数据生产者和消费者速度不一致的问题。

### 6.2 包内文件清单

| 类别 | 文件 |
| --- | --- |
| `rtl\` | `sync_fifo.v` |
| `sim\` | `sync_fifo_tb.v`（FIFO 写满、读空和数据顺序测试）、`run_test.do`（ModelSim 自动编译与运行脚本） |
| `constraints\` | 无 |
| `examples\` | 无 |

### 6.3 ★ 顶层模块端口表（`sync_fifo`，源码 `rtl/sync_fifo.v`）

| 端口名 | 方向 | 位宽 | 含义 |
| --- | --- | --- | --- |
| `i_clock` | input | 1 | 读写**共用**时钟 |
| `i_reset_n` | input | 1 | 异步低电平复位 |
| `i_write_data` | input | `[DATA_WIDTH-1:0]` | 准备写入的数据 |
| `i_write_valid` | input | 1 | 写入数据有效 |
| `o_write_ready` | output | 1 | FIFO 还有空间，可以写入 |
| `o_read_data` | output | `[DATA_WIDTH-1:0]` | 当前队首数据 |
| `o_read_valid` | output | 1 | 队首数据有效，FIFO 非空 |
| `i_read_ready` | input | 1 | 下游准备取走队首数据 |

**写入条件**：`i_write_valid && o_write_ready`；**读出条件**：`o_read_valid && i_read_ready`。

### 6.4 ★ 参数表

| 参数名 | 默认值 | 含义（改它会怎样） |
| --- | --- | --- |
| `DATA_WIDTH` | `8` | 每个数据的位宽 |
| `ADDR_WIDTH` | `4` | 地址位宽；**FIFO 深度 = 2^ADDR_WIDTH**，例如 4 表示 16 项（源码 `localparam DEPTH = (1 << ADDR_WIDTH)`） |

### 6.5 时钟与频率要求

- **单时钟**：`i_clock` 为读写共用时钟，`i_reset_n` 异步低电平复位。
- 无具体频率要求（纯逻辑，不依赖频率参数）。
- **时钟域数量：1。**
- 库根 README 明确："**该模块的读写两侧必须使用同一个时钟。跨时钟域传输应使用异步 FIFO。**"

### 6.6 依赖的其他包

**无。** 该包是最底层公共模块，被 `uart`（`uart_tx_queue` / `uart_rx_queue`）与 `imu660ra` 的示例引用。

### 6.7 验证 / 上板状态

- 仿真：库根 README 列出 `sync_fifo/sim/sync_fifo_tb.v` 为"FIFO 写满、读空和数据顺序测试"，`run_test.do` 为 ModelSim 自动编译与运行脚本。
- 上板：**库根 README 未记录本包独立的上板验证**（它只作为其他包/示例的内部依赖被间接使用）。
- 已知限制：单时钟域；跨时钟域必须改用异步 FIFO。

### 6.8 ★ 文档明确写出的坑与注意事项

1. **读写两侧必须使用同一个时钟**；**跨时钟域传输应使用异步 FIFO**（库根 README 原文）。
2. **写握手必须保持 valid 到握手完成**：RTL 头注释的示例写法是 `wr_valid` 必须保持到 `wr_valid && wr_ready` 成立，然后才清零。
3. **读握手同理**：`rd_ready` 拉高、`rd_valid && rd_ready` 成立才算完成一次读取。
4. **满时若同拍有读，仍允许写入**：源码 `assign o_write_ready = !fifo_full || do_read;`——FIFO 满时，如果同一个时钟周期也会读出一个数据，仍允许同时写入。
5. **`o_read_data` 是组合直出 `mem[read_ptr]`**（不是寄存器输出），消费方应在读握手完成的那一拍锁存它。
6. **深度由 `ADDR_WIDTH` 决定**：`ADDR_WIDTH = 4` → 深度 16；这个参数在 `uart` 队列里对应 `FIFO_DEPTH_LOG2`（同样注释为"4 表示可缓存 16 字节"）。
7. **该包无包级 README、无约束文件、无示例**——引用它时只需把 `rtl/sync_fifo.v` 加入工程。

### 7.4 ★ 参数表

| 参数名 | 默认值 | 含义（改它会怎样） |
| --- | --- | --- |
| `CLK_HZ` | `50000000` | 系统时钟频率。**必须为正整数 MHz**；50 MHz 分辨率为 20 ns |
| `MIN_PULSE_US` / `MAX_PULSE_US` | `900` / `2100` | 合法脉宽窗，按原始时钟计数比较 |
| `TIMEOUT_US` | `100000` | 无合法更新超过 **100 ms** 后失效 |
| `CH1_MIN_US` / `CH2_MIN_US` | `1000` / `1000` | 该逻辑通道负端点 |
| `CH1_CENTER_US` / `CH2_CENTER_US` | `1500` / `1500` | 该逻辑通道中位 |
| `CH1_MAX_US` / `CH2_MAX_US` | `2000` / `2000` | 该逻辑通道正端点 |

**参数契约（RTL 文件头与 README 原文）**：

- `CLK_HZ` 是 1,000,000 Hz 的正整数倍。
- `1 <= MIN_PULSE_US <= MAX_PULSE_US <= 65535`，`TIMEOUT_US > MAX_PULSE_US`。
- `MAX_PULSE_US * (CLK_HZ / 1000000) + 1` 与 `TIMEOUT_US * (CLK_HZ / 1000000)` 须在正的 32 位整数范围内（计数器不会溢出）。
- 每通道标定必须满足 `MIN < CENTER < MAX`（全在 1..65535），且 `0 <= DEADZONE_US < min(CENTER_US-MIN_US, MAX_US-CENTER_US)`。
- 端点之间按**死区外距离线性映射**；合法窗内、超出标定端点的脉宽限幅到 ±1000。**两路独立标定。**

- **单个时钟域，无派生时钟**（RTL 文件头原文："All logic uses clk; no derived clock."）。

### 7.8 ★ README 明确写出的坑与注意事项

1. **不要把有符号命令接成无符号量**；各个输出总线在上层声明时也应带 `signed`。
2. **默认值是初始参考，不是已完成的 HT-10A/F-10A 标定**（RTL 文件头也写："Initial calibration values are assumptions for software testing, not measured HT-10A values."）。
3. **实测的 ±1 μs 偏差是真实存在的，模块不修正它**：实测曾出现遥控器指令 1500/1000、显示 1499/999 μs；模块保留测量值，**没有人为统一加 1**。捕获输出按整数 μs 向下取整；未测量原始波形，因此尚不能把偏差归因于某一个原因。默认死区为 ±25 μs。
4. **`pulse_valid` 是保持状态、`pulse_update` 是一拍事件**，两者语义不同；`pulse_width_us` 在失效后**仍保留最后一次合法值**——RTL 文件头明确："use `pulse_valid`, **never `pulse_width_us` alone**, to authorize a command."（**绝不能只看宽值就认定命令有效**）。
5. **复位后先观察低电平，再接受完整上升沿**，避免把半个脉冲识别为命令。
6. **非法脉冲不会刷新超时计时**；计数器饱和，**卡高不会回绕成合法脉宽**。过短、过长、卡高、失联均会使有效状态清零。
7. **`timed_out` 在复位后从未收到脉冲时也为 1**（包括完全没有信号的情况）。
8. **任一路无效时两路命令均输出 0**（立即归零）。
9. **物理通道由主工程接线决定，不需要修改模块**：当前默认对应物理 CH1、CH2；也可以把接收机 CH4 接到逻辑 `rc_ch1`、CH2 接到逻辑 `rc_ch2`，实现左摇杆左右转向、右摇杆上下油门。HT-10A 通道映射仍以当前设置和实测为准。增加 CH3、CH4 等通道时可独立实例化 `rc_pwm_capture`，**不需要复制其 RTL**。
10. **F-10A 模拟舵机模式与数字舵机模式的参数不同**：模拟舵机模式可用 50 Hz、1000–2000 μs；数字舵机模式可能使用 **330 Hz、500–2500 μs**，此时应相应设置 `.MIN_PULSE_US(500)`、`.MAX_PULSE_US(2500)`，并重新填写各轴实际标定值。
11. **约束文件的使用前提**：`constraints/rc_receiver.sdc` **仅在本模块独立作为顶层且端口名为 `clk` 时可直接使用**；集成到主工程时使用主工程的时钟与 GPIO 约束。
12. **★ 组合归一化路径必须做时序检查**：归一化函数含组合乘除运算，加入系统后**必须检查输出命令路径的综合和布局布线时序**；捕获/数码管演示的 Fmax **不能代替**该路径的时序签核。
13. **电平与供电由板级设计负责**：F-10A 标称供电 4–9 V；目前 3.3 V 低压试接成功只是实验结果，尚未测 PWM 高电平。**GPIO 输入同步不会保护过压**，按 FPGA IO 电压确认兼容或使用电平转换。
14. **★ 无法识别射频失联**：接收机射频失联后可能继续输出合法的保持/失控保护 PWM；模块**无法仅靠脉宽和超时识别这种无线失联**，`signal_valid` 不等于射频在线。整车仍需**独立急停、接收机失控保护测试与安全仲裁**。
15. **生产 RTL 是 Verilog-2001，但测试平台因使用 `$fatal` 按 SystemVerilog 编译**（Icarus 用 `-g2012`）。

### 8.5 时钟与频率要求

- **独立读取接口（`m10_radar`）默认 50 MHz**（`constraints/m10_radar.sdc`，约束周期 20 ns），与 HDMI 无关。
- **显示核心（`m10_point_cloud_core`）使用 49 MHz**（示例中即 HDMI 像素时钟），其 `clk` **必须与视频坐标/控制所在时钟一致**。
- **单时钟**：UART 引脚及按键输入在各自入口同步；**不自动跨域传送点流**——若消费端使用另一个时钟，应在输出处加入**异步 FIFO**。
- 示例的时钟链：**PLL 从 Y18 的 50 MHz 输入生成 49 MHz 像素时钟和 245 MHz 串行时钟**。UART、解析、坐标、位图和视频逻辑使用**同一 49 MHz 时钟**；DVI 使用独立复位释放链，末级通过 CST 布置在 `R36C2[0][A]`。显示总周期 1312×622，刷新率约 **60.0443 Hz**。
- **厂商 IP 需求**：读取和点云 RTL **不包含器件专用 PLL/DVI IP**；ACG720 示例的 49/245 MHz PLL、加密 DVI 和管脚映射属于 GW5AT-138B。
- **约束不能同时加载**：`constraints/m10_radar.sdc` 是独立读取默认 50 MHz 的模板，**ACG720 HDMI 示例使用自身完整约束，不同时加载这份 50 MHz 模板**。

### 8.8 ★ README 明确写出的坑与注意事项

**协议与数据**

1. **本协议没有 checksum/CRC**：90…99 是 10 字节时间扩展，**不是 checksum**；只有完整长度、帧尾及角度范围检查通过才提交点，这些检查**无法识别仍满足格式的内容损坏**。
2. **固定 102 字节，不支持 92 字节**：所附早期资料的 92 字节帧曾导致持续 TAIL；早期资料帧尾位于 90/91，真实 102 字节包在 90…99 增加时间字段、帧尾位于 100/101。**不提供兼容分支**。
3. **填充与强度处理顺序**：原始 `FFFF` 保留；**若原始索引 39 为 `FFFF`，或索引 40 的原始高字节 ≥ `F5`，则索引 40 也按 `FFFF` 处理**；其他距离清除 bit15 强度标志——**不能先清 bit15 再识别 `FFFF`**；距离 0 仍计入 N，只在显示阶段过滤。
4. **固定按 42 分配角度会把 40/41 点包的末端有效角压低约 0.70°/0.35°**（所以要用 `floor(i*1500/N)` 的动态 N）。
5. **不能通过删槽重新排列角度**：每个提交包输出 **42 个槽**，包括零距离及填充；消费方按用途过滤 0/`FFFF`。
6. **背压时角度、距离和索引保持不变**；`point_valid && point_ready` 时消费一个槽。
7. **原始字节输出没有 ready 输入**：消费方**须及时接收每个 `rx_valid` 脉冲**。
8. **双包缓存满时丢弃新整包，不覆盖待消费数据**；**UART 数据流无法用 ready 信号暂停**，长时间背压仍会丢包并记录 OVERFLOW。`packet_valid` **只表示成功入队，不表示这一包已由下游消费**。
9. **错误原因编码**：0 = 无错误、1 = UART、2 = TAIL、3 = ANGLE、4 = TIMEOUT、5 = OVERFLOW。有效包**不会清除历史错误**。
10. **不要把两个错误计数相加**：`bad_packet_count` **包含** UART 错误及溢出事件，与 `uart_error_count` **有重叠**。
11. **复位落在连续数据中间时可能丢弃启动的不完整包并记录历史 UART 错误**；判断当前链路应**同时观察**有效包和错误计数是否继续增加。
12. **持续低电平 break 只记录一次停止位错误**，然后等待恢复；正常收包允许只有一个停止位的连续字节。
13. **连续 A5 以及错尾处的 A5 保留为下一帧头候选**。
14. **本次雷达实测 719 包全部为 102 字节**，每包 40 或 41 个测量，`FFFF` 均为尾部填充；第 41 槽有 469 个非零距离及 31 个零值，**不能把它误当作固定保留字段**。

**显示与缩放**

15. **绘图区为中心 `(512,300)` 的 512×512 位图**，0° 向上、90° 向右、顺时针增加。
16. **位图与清屏代价**：两幅位图每 bank 为 8192×32 bit，使用**同步 RAM 读及读改写**；清屏为 8192 拍，49 MHz 下约 **167 µs**；视频帧起点交换前后台。
17. **缩放请求在 `frame_start` 生效**，只清极坐标流水和双位图；**读取模块、包队列、诊断和视频时序继续运行**。缩放期间仍持续接收。
18. **档位定义**：0…3 为 10/20/40/80 mm/像素，半径量程 2.5/5/10/20 m；**复位默认档位 2**（40 mm/像素、10 m）。
19. **RGB 与 HS/VS/DE 始终延迟三拍**（包括同步位图读）；17 行垂直后沿提供约 455 µs 消隐，足够清除两幅旧位图。
20. **显示量程不能扩大雷达自身的有效测距范围**。
21. **长按只触发一次，上下限保持，同时按下忽略**；两个按键经两级同步和消抖。
22. **诊断数字以十六进制显示**。

**移植与工程**

23. **`sin_lut.vh` 是包含文件，不能作为独立 Verilog 编译单元**；须把本模块 `rtl/` 加入 include 路径。
24. **显示核心需要 RAM 推断和乘法运算支持**，移植后应检查 RAM/DSP 映射及 RGB 与视频控制的流水对齐。
25. **换器件要重生成 IP 并重做约束**：49/245 MHz PLL、加密 DVI 和管脚映射属于 GW5AT-138B；换分辨率时还需调整固定显示时序和绘图区布局。完整构建应检查 setup、hold、recovery、removal 和 TNS，**尤其保留 HDMI 串行器复位时序检查**。
26. **`constraints/m10_radar.sdc` 与示例的 HDMI `.sdc` 不应同时加载**；嵌入其他顶层时须按端口/实例名称合并并检查约束，修改时钟时同步调整周期。
27. **`tools/build.ps1` 校验位流生成时间，并检查 setup、hold、recovery、removal、TNS 和 49/245 MHz PLL 时钟；仅出现 `.fs` 文件不能代替时序检查通过。** 仓库不预存 `.fs`。
28. **接线（RevI 028 修正版）**：M10 TX（J3.4）→ **C14（J1.24）**；M10 RX（J3.3）**留空**；**A15 为 RevI J2.6 的 IMU CS（J1.38），不能连接雷达**。**027 及更早已打板版本把 J3.3 连到 C14**，使用前需核对实物并纠正为"第 4 针 TX 接 C14、第 3 针 RX 留空"，**不能直接按 028 接口插接**。
29. **供电**：M10 要求稳定 **4.75～5.25 V、约 400 mA，最大 450 mA**；手册原全板 **5 V / 50 mA** 预算**不涵盖此负载**。**J3.1 与 J1.30 的 5 V 是直连**，独立供电时须隔离雷达 VCC 与这条直通路径，两套电源**仅共地**，**不能把两个独立 5 V 输出直接并接**。GPIO0 bank 为 3.3 V，TX 电平须适配 FPGA 输入（5 V 需电平转换）。
30. **板载 USB-UART 的 J21 已有桥接芯片驱动，不能将雷达 TX 并接到该线上；M15 是镜像输出，也不能与雷达 TX 并接。** 镜像串口参数为 **921600 8N1 无流控**。
31. **S0 复位会恢复默认比例并清诊断**；历史错误保持到 S0 复位，正常收包不会清除。
32. **`packet_valid` 语义提醒（再次强调）**：它只表示整包通过检查并成功入队，为单周期脉冲。

### 9.5 时钟与频率要求

- **输入**：50 MHz（`clk_50m`）。

### 9.8 ★ README 明确写出的坑与注意事项

1. **`disp_parameter_cfg.vh` 由 `disp_driver.v` 包含，不要再作为独立 Verilog 源添加**（否则重复定义）。
2. **把 `rtl/` 内的 `.v` 文件加入 Gowin 工程**即可（`.vh` 不算独立源）。
3. **该头文件固定为实测 MPI7002 1024×600 时序**：总周期 1312×622，像素时钟 49 MHz——换分辨率必须改头文件并重做时序。
4. **像素源应在 `pixel_req` 有效时提供当前像素**；同步 BRAM 可按 `pixel_x/y` 寻址。
5. **异步摄像头数据必须先经过异步 FIFO 或 DDR 帧缓存**才能进本模块。
6. **`frame_sync` 是"原始显示 VS 电平"**（不是反相、不是脉冲），完整示例用它同步 DDR 读帧；`frame_start` 才是每帧一个周期的脉冲。两者不要混用。
7. **`video_active` 与 `pixel_req` 一致**（同一电平），选一个用即可。
8. **`pixel_x/y` 在有效区外输出 0**，用作 BRAM 地址时要注意边界。
9. **`display_pll.v` 与加密的 `dvi_tx.v` 面向 GW5AT-LV138PG484AC1/I0**；移植到其他器件时需要重生成这两个 IP。
10. **ACG720 管脚见 `constraints/acg720_hdmi.cst`**；第三方代码与 Gowin IP 的许可注意事项见 `THIRD_PARTY_NOTICES.md`。
11. **DVI 复位链有时序要求**（来自 `m10_radar/docs/hardware_notes.md`）：`dvi_tx.v` 使用独立的像素时钟复位释放链，比主逻辑延后两拍，末级约束在 `R36C2[0][A]`；**245 MHz OSER10 在两个边沿检查复位恢复，最短半周期 2.041 ns，该内部路径必须保留时序检查**。换工具或修改设计后核对综合网名及约束是否仍匹配。

- 已知限制：本包**不含 DDR3/HDMI 逻辑**；示例 IP 面向 GW5AT-138B，移植需重生成；`init_error` 后需重新拉低 `reset_n` 才能再初始化。

### 10.8 ★ README 明确写出的坑与注意事项

1. **初始化失败会停止重试并置位 `init_error`**：摄像头未插入、SDA 被拉死或持续返回 NACK 时，模块**停止重复初始化、释放 SCCB/I²C 总线**并置位 `init_error`；**重新拉低 `reset_n` 可再次初始化**。`init_error` 锁存为高，保持到外部复位。
2. **`CAMERA_PWDN_LEVEL` 默认值 0 与 BY_OV5640_V1.1 实测连接一致**；改错会导致摄像头不进工作态。
3. **`camera_rst_n` / `camera_pwdn` 由 `cfg_clk` 寄存器驱动**（避免组合比较器直连外部控制脚）——不要在顶层再加组合逻辑。
4. **模块不生成 XCLK**：BY_OV5640_V1.1 自带 24 MHz 晶振，直插 ACG720 时不需要 FPGA 提供 XCLK。若换用无晶振的摄像头模组，本模块无法提供。
5. **必须把 `rtl/` 内全部 Verilog 文件加入工程**（含第三方 5 个文件）。
6. **约束文件的使用前提**：**若将本模块直接作为顶层或顶层沿用相同端口名**，可加入 `constraints/acg720_by_ov5640_direct.cst` 和 `constraints/ov5640_capture.sdc`；**嵌入其他顶层时应按顶层端口名合并约束**。
7. **PCLK 与系统时钟异步**：连续显示时**必须**使用异步 FIFO 或 DDR 帧缓存跨时钟域，不能直接跨域使用。
8. **`frame_sync` 是"采样后 VSYNC 的反相"**，且**启动时丢弃前 10 帧**；用它做帧同步时要考虑这个丢弃行为。
9. **`capture_clear` 在首个 VSYNC 到来前为高**，用于清空外部采集 FIFO——若外部 FIFO 没接这个信号，可能残留上一帧数据。
10. **`pixel_x` / `pixel_y` 从 1 开始**（不是从 0），做地址计算时注意 ±1 偏移。
11. **`pixel_clk` 是 `camera_pclk` 的直接转发**，接收端**用其上升沿采样** `pixel_valid` / `pixel_rgb565`。
12. **IP 与许可**：`examples/.../ip/` 下的 DDR3、PLL、FIFO 均为 Gowin EDA 生成文件，面向 `GW5AT-LV138PG484AC1/I0`，**移植到其他器件时应使用目标器件对应版本的 Gowin EDA 重新生成**；`DVP_Capture.v`、`camera_init.v`、`i2c_bit_shift.v`、`i2c_control.v`、`ov5640_init_table_rgb.v` 来自武汉芯路恒科技有限公司（小梅哥）ACG720 官方示例工程，**本仓库没有发现随源文件提供的明确开源许可证，因此不能仅凭 `THIRD_PARTY_NOTICES.md` 推定获得了再分发或商业使用授权**。

## 跨包集成要点

### A. IMU → 倾斜补偿 → 偏航积分（库根 README 的"三者的配合"）

```text
imu660ra.o_gyro_z  ──┐
                     ├──▶ gyro_tilt_comp ──▶ yaw_integrate ──▶ o_yaw
imu660ra.o_acc_xyz ──┘          ▲   ▲
                                │   └──── imu660ra.o_calib_busy
                                └──────── imu660ra.o_acc_valid
```

| 连接 | 上游信号 | 下游端口 | 说明（原文要点） |
| --- | --- | --- | --- |
| 角速度 | `imu660ra.o_gyro_z` | `gyro_tilt_comp.i_gyro_z` | 单位 int32、0.01 °/s |
| 加速度 | `imu660ra.o_acc_x/y/z` | `gyro_tilt_comp.i_acc_x/y/z` | 单位 int16、mg |
| **★ 样本脉冲** | **`imu660ra.o_acc_valid`** | `gyro_tilt_comp.i_sample_valid` | **必须接 `o_acc_valid`，不是 `o_data_valid`**——`o_data_valid` 只在 RUN 态产生，标定窗口内一个样本都采不到，增益永远停在 1.0 且**不报错** |
| 标定窗口 | `imu660ra.o_calib_busy` | `gyro_tilt_comp.i_calib_start` | 高有效，**下降沿触发计算**；复用零偏标定的静止窗口 |
| 补偿后角速度 | `gyro_tilt_comp.o_gyro_z` | `yaw_integrate.i_gyro_z` | 单位保持 0.01 °/s |
| 积分样本脉冲 | `imu660ra.o_data_valid` | `yaw_integrate.i_sample_valid` | `yaw_integrate` README 的例化示例明确用它（与 `gyro_tilt_comp` 的要求不同，勿混） |
| 积分使能 | 标定完成信号（如 `imu660ra.o_calib_done`） | `yaw_integrate.i_enable` | 使 **yaw 的零点正好对应"载体静止、标定结束"那一刻** |
| 清零 | 按键 / 软复位 | `yaw_integrate.i_clear` | 优先级高于 `i_enable` |

**三条硬约束**：

1. **`gyro_tilt_comp.i_sample_valid` 必须接 `imu660ra.o_acc_valid`，不是 `o_data_valid`**（库根 README 与两个包 README 三处重复强调）。这个跨模块契约的缺陷**只能由集成测试 `tilt_integration_tb` 捕获**（改回 `o_data_valid` 时该测试立即报 5 个错误），单元测试无法替代。
2. **零偏只扣一次**：`imu660ra` 在 `CALIB_APPLY=1` 且 `calib_done=1` 时已在 `o_gyro_*` 中扣除零偏；下游姿态模块必须把它**当作已去零偏**，不要重复扣除，否则表现为"姿态往反方向慢慢转"，极难定位。
3. **单位契约必须一致**：陀螺链路统一 int32 / 0.01 °/s，加速度统一 int16 / mg；`gyro_tilt_comp` 的 `k` 只依赖比值（与加速度单位无关），但**陀螺单位必须与下游积分模块一致**。

### B. `uart` ↔ `sync_fifo`

- `uart_tx_queue` / `uart_rx_queue` **内部例化 `sync_fifo`**（`DATA_WIDTH=8`、`ADDR_WIDTH=FIFO_DEPTH_LOG2`），**加入工程时必须同时把公共 `sync_fifo/rtl/sync_fifo.v` 加入**。
- `imu660ra` 示例工程引用清单即体现了这条依赖：`uart/rtl/uart_tx_queue.v` + `uart/rtl/uart_byte_tx.v` + `sync_fifo/rtl/sync_fifo.v` 三者一起加。
- **`sync_fifo` 只用于同时钟域**；跨时钟域必须换异步 FIFO——这也意味着 `m10_radar` 的点流若跨到另一个时钟域，要自行加异步 FIFO。

### C. `m10_radar` ↔ `uart` ↔ `hdmi_1024x600`

- **读取模块依赖公共 `uart/rtl/uart_byte_rx.v`，且接收器必须支持 `RECOVERY_EN` 参数**。`m10_radar` 显式实例化为 `.CLK_FREQ_HZ(CLK_FREQ_HZ), .BAUD_RATE(460800), .DATA_BITS(8), .PARITY_EN(0), .RECOVERY_EN(1)`；**公共 UART 的 `RECOVERY_EN=0` 默认行为供原有工程使用**（即：直接用旧 `uart_byte_rx.v` 副本会缺少恢复能力，且编译期就少了这个参数）。
- **显示核心额外依赖 `uart/rtl/uart_byte_tx.v`**，以 **921600 8N1** 镜像所有解码字节。
- **示例显示依赖 `hdmi_1024x600`** 的 `display_pll.v`、`disp_driver.v`、`dvi_tx.v` 及显示时序头文件；**独立读取不需要 PLL 或 DVI IP**。
- **时钟一致性**：`m10_point_cloud_core` 的 `clk` 必须与外部视频坐标/控制信号同一时钟（示例是 49 MHz 像素时钟）；PLL 从 50 MHz 生成 49/245 MHz。
- **不要在雷达 TX 上并接其他负载**：板载 USB-UART 的 J21 已由桥接芯片驱动，不能并接；M15 是镜像输出，也不能与雷达 TX 并接。
- **示例直接引用公共模块，不另存一套 `vendor` 副本**。

### D. `ov5640_capture` ↔ `hdmi_1024x600`

- 摄像头 PCLK 与显示时钟异步：**必须用异步 FIFO 或 DDR 帧缓存**跨域。`examples/acg720_ddr3_hdmi/` 是已验证的 DDR3 方案（OV5640 RGB565 → DDR3 → 49 MHz 像素域读出并转 RGB888）。
- 组合方式：`ov5640_capture` 输出 `pixel_clk` / `pixel_valid` / `pixel_rgb565` 写入帧缓存；`hdmi_1024x600` 在 `pixel_req` 有效时按 `pixel_x/y` 提供 RGB888。
- 两个示例工程的示例 README 都声明"与已经上板验证的工程保持相同的寄存器表、DDR3 控制、显示时序和管脚映射"。

### E. `motor_tb6612` 的内部依赖链（包内）

```text
motor_top          多路集成 + STBY
   └─ motor_unit   单路完整（驱动 + 解码 + 测速 + 保护）
        ├─ motor_pwm
        ├─ quad_decoder
        ├─ speed_measure
        └─ stall_detect
```

- **分层而非合并**：下层不依赖上层，可单独取用；**换驱动芯片只改 `motor_pwm`，换编码器类型只改 `quad_decoder`**。
- 包内跨模块契约（`delta` / `delta_valid` / 使能通路）由 `motor_unit` 收敛，避免在顶层接错。
- 与其他包**无依赖**。

### F. 全局注意事项（跨包通用）

1. **ModelSim 脚本只能用 GUI Transcript**：库根 README 警告，这些 `do` 脚本用 `vsim work.xxx / run -all / quit -sim` 内建写法，**`-c`（命令行）模式下测试平台里的 `$finish` 会终结整个 vsim 进程**，**不能把多个测试串在同一个 do 脚本里**（那样只有第一个会执行，后面静默跳过、且不报错）。命令行下请给每个测试开独立进程：`vsim -c -do "run -all; quit -f" work.<测试平台名>`。`motor_tb6612` 用 `run_motor.ps1`、`m10_radar` 用 `tools/run_sim.ps1`、`rc_pwm_receiver` 用 `run_test.ps1`，都是为此准备的独立进程脚本。
2. **约束文件不要重复加载**：`m10_radar/constraints/m10_radar.sdc`（独立读取 50 MHz 模板）与 `examples/acg720_m10_hdmi/constraints/*.sdc`（示例完整约束）**不应同时加载**；`rc_pwm_receiver` 的 `.sdc` 只在"本模块独立作为顶层且端口名为 `clk`"时可直接用；`ov5640_capture` 的约束只在"本模块直接作顶层或沿用相同端口名"时可直接加入。**嵌入其他顶层时应按顶层端口名合并约束。**
3. **换器件必须重生成厂商 IP**：`hdmi_1024x600` 的 `display_pll.v` + 加密 `dvi_tx.v`、`ov5640_capture/examples/.../ip/` 下的 DDR3/PLL/FIFO，全部面向 `GW5AT-LV138PG484AC1/I0`；移植时应使用目标器件对应版本的 Gowin EDA 重新生成，并重做管脚与时钟约束（`THIRD_PARTY_NOTICES.md`）。
4. **换系统时钟频率要同步改三处**：`CLK_FREQ_HZ` 类参数、`.sdc` 周期、以及依赖该频率的派生量（如 `m10_radar` 的字节间超时、`rc_pwm_receiver` 的 `CLK_HZ` 与计数参数、`ov5640_capture` 的 `SYS_CLOCK`）。
5. **第三方代码许可仍需确认**：`DVP_Capture.v`、`camera_init.v`、`i2c_bit_shift.v`、`i2c_control.v`、`ov5640_init_table_rgb.v`、`disp_driver.v`、`disp_parameter_cfg.vh` 来自武汉芯路恒（小梅哥）ACG720 官方示例；**仓库没有发现随源文件提供的明确开源许可证**，不能推定获得再分发或商业使用授权。
6. **本仓库对公共 `uart` 的本地修改**：`uart_byte_rx.v` 增加可选 `RECOVERY_EN` 参数（默认 0 保留既有行为；设 1 时复位/帧错误后等连续 1.5 位高电平再以下降沿起收），M10 读取模块显式启用该模式，接口及原有参数保留。
7. **命名风格差异**：`imu660ra` / `gyro_tilt_comp` / `yaw_integrate` / `motor_tb6612` / `uart` / `sync_fifo` 使用 `i_` / `o_` 前缀；`m10_radar` 系列使用 `clk` / `reset_n` / `point_*` 无前缀；`rc_pwm_receiver` 使用 `clk` / `rst_n` 无前缀；`hdmi_1024x600` / `ov5640_capture` 顶层既无前缀又混用第三方大写命名（`ClkDisp`、`Disp_HS`）。**写实例化时按端口名原文连接，不要按风格推测。**
