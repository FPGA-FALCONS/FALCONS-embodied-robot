## 开机自启与模型就绪

`host/ai_coordinator/start_board.sh`启动现有协调器，复用板端隔离Python目录和本地模型。`install_autostart.py`准备并安装同名用户服务，不额外创建第二个串口所有者。启用用户服务及systemd linger后，无需SSH登录即可在Linux启动后运行。

启动配置位于`ai_module.example.json`的`startup`段：

- 必需模型：现有SenseVoice语音识别、C1b语义理解、Qwen3.5 0.8B聊天、完整Kokoro语音合成。
- 若配置了YOLO，尝试预加载视觉模型；相机未连接不影响模型加载，视觉模型单独失败也不封锁语音与聊天。
- 所有必需模型通过工作进程就绪检查后，向`plughw:CARD=Device,DEV=0`播放一声1175Hz、0.20秒提示音。不打开麦克风，不解析任务，不开启FPGA的AI总开关，不产生运动指令。
- 必需模型失败时不鸣音，保留服务和页面并每5秒重试。扬声器失败不撤销模型就绪状态，在AI未活动时重试提示音，成功后本次服务生命周期内不重复鸣音。
- 模型在AI关闭或切换功能后保留加载状态；取消推理时被终止的工作进程会在空闲后补载，不重播成功提示音。进程退出或服务停止仍会释放资源。
- 模型加载期间页面仍可选择功能，显示加载状态。服务重新启动后直接接受FPGA当前AI开关状态，不要求先关再开；SWB已下拨时仍需先上拨再下拨开始新的录音，旧任务不重放。

`/status`的`startup`字段报告加载阶段、每个模型的加载时间、错误及提示音播放状态。`ready=true`表示必需模型工作进程已加载，不等于运动、视觉或真人语音验收通过。

## 板端安装方式（已部署，保留操作步骤）

先将包含新源码的发布包放到独立release目录，保留现有模型、配置与旧release。包必须包含新增的`.sh`启动脚本和原RKLLM适配器源码；发布工具已补齐这些类型。

```bash
config=/home/orangepi/workspace/falcons_ai_coordinator_20261024_r1/config.json
release=/home/orangepi/workspace/falcons_ai_interactive_20261024/releases/新发布目录

# 第一次以该账户配置无登录自启时，需要系统允许linger。
sudo loginctl enable-linger orangepi

# 先生成可审阅配置和用户服务，不改当前服务。
python3 "$release/host/ai_coordinator/install_autostart.py" --config "$config"

# 核对autostart_prepared/config.json及service.txt后安装。
python3 "$release/host/ai_coordinator/install_autostart.py" --config "$config" --apply

loginctl show-user orangepi -p Linger
systemctl --user is-enabled falcons-ai-coordinator.service
systemctl --user status falcons-ai-coordinator.service
curl --noproxy '*' http://127.0.0.1:18765/status
```

安装脚本先校验发布源码清单，备份旧配置、服务及发布来源记录；安装失败恢复原配置、服务、发布来源及启用/运行状态。保留原运动速度、标定、相机开关和模型路径，只启用启动加载。用户服务内存上限设为6G，用于多个模型驻留；RK实际峰值内存、NPU并存及断电冷启动仍需板端验证，不安装或升级Python、NPU驱动及模型SDK。

RK服务自启与FPGA Flash固化是两件事。本次FPGA已通过SRAM加载，未写Flash。

## 摄像头180°翻转

应用`rtl/cam/cam_overlay.v`同时启用原驱动的`IMAGE_FLIP_EN`与`IMAGE_MIRROR_EN`，由OV5640输出上下、左右均反向的源画面。UI菜单不参与翻转，分辨率、RGB565格式、DDR顺序读写和菜单遮挡范围保持原样；后续使用同一DVP源的图像也具有新方向。

`camera_rotation_tb`比较253个初始化表项，方向配置由`0x3820=0x40 / 0x3821=0x07`变为`0x3820=0x47 / 0x3821=0x00`，其余表项不变。RGB表改用静态ROM初始化，修复常量`always @*`在纯RTL仿真中不触发的问题，保留表内容和同步读延迟。该检查不替代摄像头实物方向验收。

## 手动接管与下一项任务

| 场景 | 页面与总开关 | 任务与恢复 |
|---|---|---|
| AI任意子功能切SWC手动 | 留在当前AI页面，保留总开关、已确认功能和高亮项，菜单继续冻结 | FPGA立即撤销自动驱动并执行原停稳/回中接管；RK取消当前录音、推理、播报和识别，显示已暂停 |
| 手动期间 | 页面和已完成的指令/聊天回复保留 | 遥控交互仍只用于手动驾驶；不开始AI录音或自动任务 |
| 切回光标档，SWB保持下拨 | 不退出、不切回默认功能 | 不恢复旧运动、播报或录音；先上拨再下拨才能开始新录音 |
| 切回光标档后选择功能并SWA确认 | 在本页重新选择/确认 | 取消残留作业，进入所选功能；同一功能也能明确重新确认 |
| 目标识别从手动返回 | 仍在目标识别页，等待新任务 | 不自动恢复旧相机循环；再次SWA确认或完成一段新的目标语音才启动识别 |
| SWA返回、离开AI页、S1/S2、急停、遥控失效或RK断连 | 沿用原显式退出/故障关闭规则 | AI关闭、旧结果失效；故障恢复不自动开启 |

这里的“暂停”保留页面与选择，终止本次尚未完成的作业；不从运动、录音或推理的中间位置继续。聊天仅保留同一AI会话的有限历史，关闭AI会清除历史。

为识别“同一功能再次确认”，AI控制上报`0x50`的controls第5位改为确认翻转位；每次有效SWA功能确认翻转，功能0..2、录音位和高亮项位保持原位置，第7:6位仍须为零。新RK源码与FPGA位流应配套部署。翻转位只表示遥控确认事件，不是运动回执。

## 验证与后续现场项目

本地回归及构建证据见`doc/evidence/ai_boot_pause_20261025/`。Windows无法执行的Linux串口/sysfs项目单列跳过，不能写成板端通过。

本地软件174项测试中164项通过、10项Linux专属检查跳过；恢复连接后RK板端174项全部通过。44项应用仿真通过。新位流40217085字节，SHA256为`715d7ac16969dd2ba1fe95917f0ccbea5a716eabde134f85f620955e1ec5221e`，原同钟域时序通过：系统50.090MHz、像素49.697MHz，所列时钟建立/保持违规端点均为零。生成IP跨钟域路径仍按原工程单独核对，不是全部路径签核；位流已通过SRAM加载。

系统重启实测：服务在本次启动约11.29秒自动启动，ASR/C1b/Qwen/Kokoro/YOLO在约61.96秒全部就绪，早于本次SSH登录的102.93秒；就绪提示音在登录前播放且本次启动仅一次。交互后服务无重启，内存约5.21GiB，cgroup无内存上限触发或OOM记录；模型与控制链路仍就绪。

用户确认：重启后听到单声提示音；摄像头画面旋转180°且菜单正常；聊天页切手动保留AI总开关和当前功能、停止播报并显示暂停，回光标档后能新录音且旧任务不自动续跑。日志另有34条“手动且AI总开关仍开”快照、2次手动暂停和7次新录音事件。

尚未单独验证：整机断电冷启动、真实安装失败回滚、目标识别实物链路、其他子功能现场暂停，以及运动中制动距离/摇杆接管。上述结果不扩大为这些项目的验收。
