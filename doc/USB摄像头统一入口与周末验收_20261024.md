## 已实现的连接

`USB/UVC → 独立camera worker → 最新帧PNG → 现有Vision预处理/检测接口 → 协调器 → FPGA任务/状态协议`。

`FX2 → FIMG v1/v2或显式FIMG v2接收 → 同一视觉/协调器接口`继续兼容。一次选择一个图像源；没有把两只相机当作已同步、已标定的双目系统。摄像头1280/1920等原始尺寸会沿用现有letterbox转入v17的640×640输入；高分辨率不等于提升了网络输入尺寸，小目标增益仍需实拍验证。

入口`host/ai_coordinator/camera_sources.py`按`camera.backend`选择`fx2`或`v4l2`；省略backend保留旧FX2行为。配置模板`camera.v4l2.example.json`中的设备、分辨率、fps和fourcc为空，默认关闭。不能整份替换板端配置；只在真实探测后合入`camera`，保留麦克风、模型路径与HOLD。

UVC入口要求显式`/dev/v4l/by-id/...`或`/dev/v4l/by-path/...`，验证其对应USB与uvcvideo驱动，避免默认video0误开ISP或另一个节点。核对协商后的尺寸、帧率和FOURCC以及每帧BGR类型/形状，拒绝静默降档。单独线程持续取帧，只保留最新帧；实际推理速率由模型决定，不承诺30次/秒推理。首次10秒没有有效帧或已交付图像超过1秒不再更新会报错；断开/读错会报错并退出本次相机任务，状态标记unavailable，检查设备后重新启动服务。

HOLD下即使camera.enabled=true也不创建相机worker，不打开相机、不加载视觉模型。状态新增`camera_backend`、`camera_state`、`camera_configured`；`fpga_camera_configured`保留且仅在FX2入口配置时为真。

## 到货后顺序

1. 先用Claude的独立工具探测，保存`probe.json`和稳定设备链接；检查目标节点确实是Video Capture，确认1080p30/MJPG是否列在实际模式中。设备不支持时选择其真实支持的模式。USB2下1080p30原始YUYV需要约124.4MB/s，超过USB2理论60MB/s；此模式需要压缩或降低尺寸/帧率。USB3接口不代表相机本身支持USB3。
2. 独立取帧至少120帧，报告实际完整帧数、主机收到的FPS、断流、解码错误和清晰度；将原始证据留存。设置fps的返回值或属性值不能代替实测。
3. 确认供电/复位/watchdog等板子稳定性问题后，使用候选入口在shadow下做真实相机→v17→协调器验证。先只做相机取帧，再单独启用视觉模型；不跳过稳定性排查直接开始模型长跑。
4. 用真实螺丝刀、胶带、AD钙奶、营养快线，在预期距离、角度、照明与电机状态下验证检出。不要拿代码stub通过率当检测率，也不要因为版本号更高就替换v17基线。
5. 补单次真人`/capture`正例、音箱播报与麦克风互斥、真实FPGA任务回执和距离停车，再验巡航→发现→暂停→靠近→停车→人工取走确认→恢复路径点。

## 尚不能放开的环节

OpenCV此处只提供主机收帧时刻和主机计数，`source_timestamp_verified=false`、`sequence_origin=host_frame_counter`。持续读取可减少积压，但没有测量传感器/USB/解码的总延迟，无法证明图像采集时刻。现有运行时仍拒绝据此启动live找物/巡航。后续需验证驱动采集时间戳与时钟域、实际图像年龄/延迟、相机标定及真实执行能力；不通过修改false或取消时效检查绕开验收。

当前没有机械拾取硬件，“拾取”仍指停车后等待人工确认。软件主体已有广泛回归；比赛全栈完成仍需真实相机、单次语音任务、板子稳定和实车执行证据。
