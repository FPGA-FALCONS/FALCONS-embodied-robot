## 四、界面与遥控操作

### 界面（1024×600，中文）

- 左侧菜单条（宽 208 px，深蓝底），4 个菜单项，**当前项蓝底亮黄字**：
  `摄像头画面` / `雷达建图展示` / `车身运行数据显示` / `路径点导航`
- 底部状态栏（深灰底）按优先级显示一个状态词：
  **急停** > **无信号** > **请回中位** > **手动**（模式=手动）> **自动**（模式=自动）> **请选择模式**（模式=光标档）
  - `请回中位`（2026-10-15 加）：**没在运行 + 遥控信号正常 + 油门不在中位死区内** → 提醒你把油门杆回中位才能按 S1 启动
- 内容区：
  - 页 0/1/3：显示占位提示（`摄像头未接入` / `雷达未接入` / `导航未实现`）
  - 页 2（车身运行数据）：4 行中文标签 + **实时数值（亮绿色，每 100 ms 刷新）**
    - `航向角`：IMU 未接入 → 显示"无任务"
    - `中心速度`：左/右侧**目标**轮速（rpm）
    - `编码器`：四路**实际**轮速（rpm）＝ A 左前 / B 右前 / C 左后 / D 右后
    - `状态`：与状态栏同一个状态词
    - 数值格式：符号 + 3 位数字（右对齐），如 ` 300`、`- 45`

### 遥控（6 通道，映射见 `rtl\rc\rc_input.v` 参数）

> **当前状态**：代码与仿真已完成（`rc_input_tb` **20 项 PASS**：归一化 / 死区 / 三档模式 / 按钮脉冲 / 丢信号 /
> 方向取反参数——取反用一个独立对照实例验证，`STEER_REVERSE=THROTTLE_REVERSE=1` 时两路模拟量符号相反而模式与按钮不受影响）。
> ⚠ 但**通道角色映射是按功能设计文档的语义假设的，必须按你的实际接线核对**（核对方法见下表与
> `doc\参数总表与待定清单.md` 第九节第 2 条）。核对完把 `rtl\top\falcons_top.v` 里 `rc_input` 例化的
> `CH_*` 参数改成实际值即可，不用动逻辑。

| 通道 | 引脚 | 角色 | 判据 |
| --- | --- | --- | --- |
| CH1（J6.1） | D19 | **转向** | 1000…2000 µs ↔ −1000…+1000，中位 1500，死区 ±25 µs |
| CH2（J6.2） | E19 | **油门** | 同上（前为正） |
| CH3（J6.3） | E18 | 确认 | 脉宽 > 1700 µs 视为"按下"，产生单周期脉冲 |
| CH4（J6.4） | F18 | 返回 | 同上 |
| CH5（J6.5） | F20 | **模式开关** | <1300 µs → 手动接管；1300–1700 → 屏幕光标；>1700 → 自动 |
| CH6（J6.6） | F19 | select | >1700 µs 视为按下 |

**开机自检**：上电后 LED3 应亮（遥控信号有效）、LED7 心跳闪烁、屏幕出现菜单。
若 LED3 不亮 → 接收机没通电/没对码/接错通道。

**开车步骤**：模式开关打到**手动接管**（LED5:4 = 00）→ **把油门杆回到中位**（状态栏不再显示 `请回中位`）
→ 按 S1（LED6 亮）→ 推油门。未按 S1 底盘不会动（这是设计）。按 S4 随时急停。

> ★ **启动门禁（2026-10-15 加，`ARM_THROTTLE_DEADZONE = 100`）**
> 按 S1 启动需要同时满足：**油门在中位死区内**（`|throttle| ≤ 100`，即归一化 ±1000 的 10%）**且遥控信号有效**。
> 目的：防止"上电时油门杆恰好停在半位，一按 S1 车就窜出去"。
>
> | 现象 | 说明 / 怎么办 |
> | --- | --- |
> | 油门没回中位时按 S1 不启动，状态栏显示 `请回中位` | 正常 —— 这是门禁在起作用，把杆回中位即可 |
> | **想停车时按 S1 停不下来** | **不会发生**：停止任何时候都允许，不受门禁限制 |
> | 杆已回中却启动不了 | 接收机中位有偏差 → 调大 `rtl\top\falcons_top.v` 的 `ARM_THROTTLE_DEADZONE` |
> | 轻轻碰一下就能启动 | 调小该值 |
>
> **切菜单 / 切页（2026-10-16 更正为需求原文的交互）**：
> - **模式开关打到"屏幕光标"档**（LED5:4 = 01）后，**油门摇杆向上拨 = 上一项，向下拨 = 下一项**
>   —— 这是需求原文 §17 规定的交互"使用摇杆上下拨动来切换选项"（此前误做成遥控按键切页，已改正）。
> - 拨到位后**必须把杆放回中位**才能再拨一次（`MENU_STEP_TH = 400` / `MENU_IDLE_TH = 150`）：
>   杆停在端点不会连续翻页，这是有意的。
> - 手动接管档下摇杆是**开车**，不参与菜单（需求原文 §13：摇杆操作屏幕只在光标档）。
> - **板载 S3 保留为"无遥控时的备用翻页"**；遥控 `select` / `confirm` **不再参与切页**
>   —— 按 §33 它们属于路径点导航页（切辅助菜单项 / 确认路径点），该页尚未实现。

### 接线（J2 接口，SPI Mode0 四线）

| 信号 | 引脚 | J2 排针 |
| --- | --- | --- |
| `o_imu_sck` | **A14** | J2 SCL |
| `o_imu_mosi` | **A13** | J2 SDA |
| `i_imu_miso` | **A16** | J2 SDO/SA0 |

> ⚠ **A15 是 J2.6 = IMU CS**，J1 与 J2 同网络 —— 所以雷达 RX 只能用 **C14**。供电 J2.1 = 5 V。

### ★ 三条接线契约（写死在 `rtl\top\falcons_top.v` 注释里）

1. `gyro_tilt_comp.i_sample_valid` 必须接 `imu_top.o_acc_valid`，**不是** `o_data_valid`
   —— `o_data_valid` 只在 RUN 态产生，标定窗口期内一个样本都收不到，会让倾斜补偿
   **永远不生效且不报错**（`car_fpga` 踩过的坑）。
2. `gyro_tilt_comp.i_calib_start` 接 `imu_top.o_calib_busy`。
3. `yaw_integrate.i_sample_valid` 接 `imu_top.o_data_valid`。

`imu_top` 的 **`SCK_HALF_DIV` 显式写 25**（1 MHz）：源码默认 3（8.33 MHz）实测会导致
8 KB 配置加载失败，表现为 `o_err_code = 2`，极易误判成"模块坏了"。

### 上电后的现象判据

| 观察 | 含义 |
| --- | --- |
| 数据页 `航向角` 显示数字（亮绿，整数度） | 初始化 + 零偏标定 + 倾斜补偿都已跑通 |
| 转动车体航向角随之变化 | 陀螺积分正常 |
| 静止时缓慢漂移 | **正常**：纯 6 轴 yaw 不可观测，原理性限制；调 `DEADZONE_TH`（默认 0.3°/s）压小 |
| 按 S2 | 编码器计数 + 航向角**同时清零** |
| 航向角恒 0 / 不动 | 查 SPI 四线（SCK/MOSI 是否接反）与 `o_err_code`（1=通信 2=配置 C=标定 D=倾斜） |

### ★ 时序：**SETUP 同域 0 违规**；负 slack 全部在跨时钟域与上电复位路径上

判据用**布线后的路径表**（`impl\pnr\falcons_tr_content.html`）。四张表共 110 条路径
= Setup 25 + Hold 25 + Recovery 25 + Removal 35，其中负 slack **37 条**：

| 分析类型 | 违规条数 | 最差 slack | 性质 |
| --- | --- | --- | --- |
| **SETUP** | **0** | **+0.259 ns**（`u_tilt/gain_r_0` → `mult_306`） | **同域逻辑全部满足**（含 `u_motor` 测速窗、`u_chassis` PID 比较） |
| HOLD | 12 | −1.026 ns | sys→pixel 两级同步器**第一级**（`page_s/estop_s/arm_s/mode_s/sig_s` → `*_ps1`）+ 动态字符 RAM 跨域读 |
| RECOVERY | 25 | −4.456 ns | `u_reset_sync/key_stable` → `u_hdmi/…/u_OSER10_*/RESET`（**上电复位路径**） |
| REMOVAL | 0 | — | — |
| 同域最紧 | — | **+0.247 ns** | `u_motor` 测速窗口计数器与 `u_rc` freshness_cycles 的自反馈 |

**口径说明（重要，避免误读）**：报告头部的 `Numbers of Setup Violated Endpoints = 98` / `Hold = 12`
与上面的路径表**不一致** —— 后者是**违规端点数**（一条 2 位总线的两位各算一个、RAM 每一位各算一个），
且疑似布局阶段的中间统计。**以布线后的路径表为准**（负 slack 与四张表的条数精确吻合）。

**怎么看待这些违规**：

- **HOLD 的 12 条是 CDC 的结构性现象，不构成功能风险** —— 同步器第一级本就允许亚稳态，第二级再采样。
  本轮为此做了一次**物理改善**：跨域源先在 sys 域打一拍（原来 `arm_hint`（含 12 位比较器）与
  `rc_signal_ok`（6 路 `timed_out` 相或）是**组合逻辑**，组合深度直接算进 slack），
  最差从 **−2.473 ns 降到 −0.998 ns**。
- **RECOVERY 的 25 条是上电复位路径**，只在复位释放瞬间起作用；`car_fpga` 阶段同结构实测 HDMI 显示正常。
  本轮**如实记录、不动 vendor 模块**；要严格处理的正解是给复位网络加专用约束或做同步复位释放，
  而不是 `set_false_path` 掩盖。

**结论：这是 CDC 的结构性现象，不构成功能风险** —— 同步器的第一级本来就允许亚稳态，第二级再采样。
处理过程中我**先尝试了正解**（在 `.sdc` 里 `set_false_path -to [get_clocks {pixel_clk}]`），
但 `pixel_clk` 是 `hdmi_1024x600` 内部 PLL 的派生时钟，**约束解析阶段还不是时钟对象**，
写了会直接 `ERROR (TA2004): Cannot get clock with name 'pixel_clk'` 导致综合失败，
所以撤回并把复位链改成"像素域内自产"（消掉了原先 −0.616 ns 的那条）。

> 优化记录（每一步都实测）：
> 最初 SETUP 违规 **25 条，最差 −7.023 ns** → ①遥控归一化改移位加法（×2.125 代替通用乘法）
> → ②`chassis_ctrl` 指令乘法插流水 → ③差速/限幅插流水 → ④像素域复位改域内自产
> → ⑤**跨域源在 sys 域打一拍**（2026-10-15）
> → 最终 SETUP **同域 0 违规**（最差 +0.259 ns），剩下的是 HOLD 12 + RECOVERY 25。

### ★ 仿真抓出来的真缺陷（都已修）

1. **差速限幅顺序错**：`chassis_ctrl` 原来先把中心速度限幅再算差速。自动模式给
   `center=5000 / diff=2000` 时左轮只得 2096（= 4096−2000）而不是 3000，表现为
   "大给定 + 转向时车往一侧偏"。改为只对差速量与左右轮各自限幅。
2. **状态栏颜色割裂**：状态栏横跨全宽，其左段（x<208）落在菜单条的 x 范围内，
   结果左半边是菜单色、右半边是状态栏色。改为状态栏优先级高于菜单条。
3. **数值格式化语法错误**：`(-cur)[15:0]` 这种"对表达式做位选择"在 Verilog 里非法
   （ModelSim 报 vlog-13069），改成先算 `absv` 再取位。
4. **注释与实现不符，把测试台带偏**（2026-10-15）：`speed_report` 的 `i_force` 端口注释写
   "单周期：立即插播一行"，实际实现是 `S_IDLE: if (report_tick || i_force)` —— **保持高电平会连续上报**。
   按注释给了长脉冲后，每次触发都多发一行残留，检查到的永远是上一次触发的那一行
   （实测行长 39/42/42/42，四项全错，看起来像"12 列格式写错了"，实际是 RTL 注释误导测试台）。
   **教训：注释也是接口契约的一部分，发现不符要立刻改注释，而不是只在测试台里绕过去。**

### 写 tb 时踩的 5 个坑（供后续加测试时参考）

| # | 坑 | 现象 / 教训 |
| --- | --- | --- |
| 1 | `fork` 的多个并行进程给**同一个 `reg [5:0]` 的不同位**赋值 | ModelSim 下互相覆盖，表现为"所有通道脉宽恒为 0"，而单通道调试台完全正常 → 改成每路一个独立 reg 再拼接 |
| 2 | 脉冲结束后立刻判定 | `rc_pwm_capture` 在下降沿后还要数拍才更新 `pulse_width_us`/`pulse_valid`，帧间隔要留 ≥10 拍 |
| 3 | `#8000` 当 8 ms 用 | timescale 是 1ns，`#8000` = 8 µs；超时测试必须写 `#6_000_000` |
| 4 | ModelSim 输出中文变 `?` | 检查名一律用 ASCII，判定只靠 `pass`/`FAIL` 与数值 |
| 5 | 把"选中项"当"未选中"来测 | 第 1 个菜单项默认选中，文字是亮黄 `FFE066` 而非灰 `E5E7EB` |
| 6 | **仿真清单漏依赖** | `vlog` 逐文件独立编译、不做模块解析 → 少列依赖时**编译全过**，`vsim` 加载才报 `Module 'xxx' is not defined` / `Error loading design`。`speed_report` 的依赖是**两层**：`→ uart_tx_queue → { uart_byte_tx, sync_fifo }`，补一层不够 |
| 7 | **复位后 DUT 自发的一行** | `speed_report` 的 `tick_cnt` 复位为 0，而 `report_tick = (tick_cnt == 0)` → 复位一释放就上报一行（既定行为）。tb 不先丢弃它，之后每次检查都读到上一次的行，表现为**整体滞后一行** |
| 8 | UART 接收进程里"边采边等下降沿" | 字符数据位里也有 1→0 跳变（如 `,`=0x2C 第 3→4 位）→ 必然错位。正确写法：等起始沿 → 连续采 8 位（窗口内不响应任何边沿）→ 回到起点 |

## 八、上板测试顺序建议（第一次跑按这个顺序走）

> 原则：**每一步都要有一个"能不能继续往下走"的判据**，别一步跳到"摇杆开车"。
> 全程 **车轮悬空**（车架空）、**D24A 驱动板 STBY 跳线帽已拔**，落地试跑放到最后一步。

| 步 | 做什么 | 看什么 / 判据 | 不对时先查 |
| --- | --- | --- | --- |
| **0** | 只烧 **SRAM**（`-Action Sram`），不急着固化 | LED7 心跳（约 0.34 s 翻转）、LED3 遥控信号有效、屏幕出现四页菜单、串口有 CSV 输出 | 没心跳 → 位流没下进去；LED3 不亮 → 接收机没通电/没对码/接错通道；无 CSV → 串口波特率或 TX 引脚（M15） |
| **1** | **核对 6 路通道映射与行程**：逐个拨摇杆/开关，看串口 CSV 的 `steer` / `throttle` / `mode` 列 | 摇杆推到两端应到 ±1000 附近；回中位清零；开关三档 → `mode` = 0/1/2；按钮 → 只在该列出现跳变 | 通道号对不上 → 改 `falcons_top.v` 里 `rc_input` 例化的 `CH_*`；方向反了 → 改 `STEER_REVERSE` / `THROTTLE_REVERSE` |
| **2** | **车轮悬空按 S1**，看四轮转向与 `tgt` vs `act` | 推油门四轮**同向**、转速随杆位变化；`tgt` 与 `act` 符号一致 | 某个轮反向 → `INV_DIR_VEC`；实测与目标符号相反 → `ENC_INV_DIR_VEC`；一按就报堵转 → 确认已改成 50 窗口 |
| **3** | **串口 `P/I/D` 在线整定速度环** | 给固定杆位，`tgt` 稳定、`act` 跟上且不振荡；稳态误差 ≤5% | 见 `doc\参数总表与待定清单.md` 第九节第 5 条 |
| **4** | **落地低速试跑 + 保护验证** | 低速直行不跑偏；人为堵住一个轮 → ~200 ms 内停机并锁存（LED2）；**拔掉接收机** → 100 ms 内摇杆归零停车 | 停车时间不对 → 看 `TIMEOUT_US`；堵转不报 → 看 `STALL_*` 阈值 |
| **5** | 功能都正常后再 **固化到 Flash**（`-Action Program`） | 断电 → 拔下载器 → 重新上电 → 现象与 SRAM 一致 | 上电不工作 → 确认烧的是 `impl\pnr\falcons.fs` 且时间晚于最后一次改 RTL |

> ⚠ 第 2 步之前**不要让车落地**；第 4 步之前**不要给大油门**。
> ⚠ 上电后等 **约 3 秒**再动车：IMU 的零偏标定（`CALIB_TIMEOUT_MS = 3000`）要求这段时间静止，
> 标定失败不影响遥控开车，但航向角会漂。
