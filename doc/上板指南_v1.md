# 整车上板与基础操作

核对：2026-10-28。本文件名保留供已有链接使用，内容按当前整车功能维护。功能与最近部署见[交接单](交接单.md)，AI操作见[AI交互](AI模块页面与遥控交互_20261024.md)和[巡检指南](AI视觉巡检.md)。

## 先核对版本和接线

- 主工程顶层`falcons_top`、GW5AT-138B；整车约束为`constr/falcons.cst`及配套SDC。独立LED/ToF例程不是整车位流，器件和引脚需按该目标分别核对。
- J6六路按[HT10A表](HT10A接线与验收.md)接CH4/2/5/7/6/8，全部参与有效判定。电源、共地、电机/编码器及IMU按厂商手册和现有约束确认。
- 雷达RX接C14；ToF独立包已存在，但整车`tof_estop`仍为0，不把它当成当前已接保护。
- FPGA相机只本地显示；RK相机直接接RK。控制串口与FX2高速口、JTAG下载线分别连接，不互相替代。
- 核对位流对应源码、约束、时序报告及SHA。SRAM重上电后失效，不能只看仓库HEAD或文件名断言板上版本。

## 构建与加载

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File sim/run_sim.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build.ps1
python tools/check_pin_constraints.py
powershell -NoProfile -ExecutionPolicy Bypass -File tools/program_flash.ps1 -Action Cables
powershell -NoProfile -ExecutionPolicy Bypass -File tools/program_flash.ps1 -Action Sram -Fs '<本次核对后的.fs>'
```

脚本和工具参数见[tools说明](../tools/README.md)。普通联调使用SRAM Program，掉电后失效；需要脱机启动时，在SRAM验证后按用户要求固化Flash，最近状态见[巡检验证记录](AI巡检验证记录.md)。GUI占用下载器时先关闭再用CLI。

首次或换硬件验证保持车轮架空，先确认遥控接管和独立急停，再验证各轮方向与停车。下载成功只表示配置完成，不表示IMU校准、遥控有效或电机方向已验收。

## 按键与LED

| 按键 | 管脚 | 作用 |
| --- | --- | --- |
| S0 | F15 | 系统复位 |
| S1 | A20 | 停机/暂停；AI页会撤销AI |
| S2 | B20 | 编码器/航位与航向相关清零、清堵转；巡检旧坐标任务失效 |
| S3 | A21 | 备用页面操作，正常使用遥控菜单 |
| S4 | B21 | 急停锁存切换 |

LED0为底盘运行，LED1急停锁存，LED2任一路堵转，LED3六路遥控有效，LED5:4模式（00手动/01光标），LED6使能，LED7心跳。具体状态以顶层信号和实际位流为准。

## 基础界面

上电默认数据页。光标挡摇杆移动左侧高亮、SWA确认切页，菜单包含数据、摄像头、雷达、避障导航、非避障导航、参数整定、AI七项。

- 数据页显示航向、四轮rpm、角速度、中心速度、航位；中心速度按0.01m/s、航位按0.01m格式化。
- 摄像头页显示FPGA OV5640画面，已在本地旋转180°，菜单不随画面旋转。
- 雷达页显示FPGA地图。基础避障导航的选点/暂停/取消见[操作指南](避障导航操作指南.md)，AI多点巡检使用独立点表。
- 参数页14项，CH2上下选行、CH4左右调值，SWA下拨恢复当前行默认，上拨退出编辑态而保留当前页。菜单在编辑时变暗，退出恢复。参数掉电回默认，完整默认值见[参数总表](参数总表与待定清单.md)。
- 手动挡立即撤销自动，经过本地停车/回中守卫后由摇杆驱动；回光标不自动继续原任务。

## 上板检查顺序

1. 加载已核对SRAM，观察数据/菜单与心跳，等IMU初始化和校准完成。
2. 验证六路PWM有效、方向和SWC接管；摇杆回中后分别观察各轮目标、实际轮速及停止。
3. 检查原相机、雷达、参数编辑与基础导航；RK断连时这些功能仍应可用。
4. AI先查模型和设备状态，再测聊天/独立识别/巡检视图。新多点自动任务只有人工确认才开始，当前待测范围见[验证记录](AI巡检验证记录.md)。
5. 保存本次源码/位流指纹、供电、接线与真实反馈。软件测试、模块单测、整车时序和现场结果分开记录。

## 常见定位入口

| 现象 | 优先检查 |
| --- | --- |
| 一直无信号/不能解锁 | 六路是否全接、CH映射、档位、回中及超时；只接两个摇杆不够 |
| 堵转后不能运行 | 驱动动力电、STBY、编码器及堵转锁存；确认原因再清除 |
| 单轮实际快速转动而转速为0 | 先比较该轮串口反馈，再检查编码器供电、共地及两相输入；不能用保留上次转速掩盖无反馈 |
| 相机花屏 | 使用已验证的短接线和共地；旧长排线问题见历史[物理接口核验](摄像头物理接口核验_20261024.md) |
| 改代码但板上无变化 | 核对实际构建输入、下载文件和SHA；确认是否掉电回到Flash |
| AI模型ready但无画面/声音 | 分别检查UVC、FX2、音频身份；模型加载和外设实测不是同一结论 |
| 断连后旧任务不继续 | 这是现行交互；新会话/新定位需重新确认，不自动恢复 |

只排查手柄时使用[独立LED测试](手柄LED上板测试.md)，避免在诊断顶层套用整车按键含义。

## 左前轮转动但转速为0的排查

本车左前轮是通道A/bit0，两相分别进入D15（`i_enc_a[0]`）、C15（`i_enc_b[0]`）。采集链为两级同步、8拍滤波、正交计数、10ms窗口差分、rpm换算；屏幕与现有UART CSV第二列都使用`rpm0_disp`。停用电机不停止编码器采集。

2026-10-28用户反馈手动行驶时左前轮快速转动但屏幕显示0。源码检查未发现左前轮专属的采集门控或显示清零；四路真实模块仿真在每10ms分别输入10000/5000/2000/1000个有效跳变时均正常。仅保留左前轮一相跳变时，计数正反抵消、窗口转速接近0，可复现症状；这提示检查相线、接插件及编码器输出，但尚未证明实车故障原因。

现场先将车轮架空、油门回中并用S1停机，手转左前轮，对比屏幕与UART反馈。本轮实车手转30秒收到1492条有效反馈，其中1336条非零、−44～62rpm，全程占空比及运行使能为0，证明此次手转时采集可用；不能据此排除通电转动时的间歇问题。若故障出现时串口也为0，继续用示波器或逻辑分析仪核对D15/C15是否都有正常电平和错相跳变；若串口有转速而屏幕为0，排查显示链。更换接线时断开动力电，逐段检查编码器端和FPGA端信号。真实故障尚未捕获，不能以仿真或手转通过代替修复结论。数据见[本轮证据](evidence/encoder_cruise_confidence_20261028/VALIDATION.json)。
