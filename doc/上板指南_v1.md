## 二、上电前逐条检查（依据功能设计文档 §2.5 接线纪律）

| # | 检查项 | 为什么 |
| --- | --- | --- |
| 1 | **灰排线按 Pin 号核对两端，确认 Pin1** | 母头与公针是镜像的；插反 = 整排错位，综合完全查不出来 |
| 2 | **雷达 RX 接 C14（J3.3），绝不接 A15** | A15 = J2.6 = IMU `CS`，J1 与 J2 同网络，两个输出挂一起会"对打" |
| 3 | 电机 13 根输出 + STBY 的 10 kΩ 下拉，**拔掉驱动板 STBY 跳线帽** | 三层防护保证上电不窜车 |
| 4 | 地线单点汇合（J5 pin2），星形接地 | 避免地环路，电机电流不进 FPGA 地 |
| 5 | **GPIO0 bank 跳线必须 3.3 V** | 所有外设都是 3.3 V 电平 |
| 6 | 遥控接收机接 **J6**（D19 E19 E18 F18 F20 F19）；**实际只用 5 路**（2 摇杆 + 确认 + select + 模式拨杆），**J6.6/F19（bit5）闲置** | 与 `constr\falcons.cst` 一一对应；**接线以 `doc\HT10A接线与验收.md` §2 为唯一真源**（接收机 CH ≠ J6 槽位标签）；bit5 已由 `SIG_VALID_MASK = 6'b011111` 排除在"信号有效"判定外，插不插都不影响开车 |
| 7 | HDMI 接显示器，屏幕分辨率先调到能收 1024×600 | 板载 HDMI 口即插即用 |

## 三、按键与 LED

### 板载按键（低有效）

| 按键 | 引脚 | 功能 |
| --- | --- | --- |
| **S0** | F15 | 系统复位 |
| **S1** | A20 | **停机锁存**（切换）：接管档内按一次停住、再按解除；切出接管档自动清 |
| **S2** | B20 | 编码器计数清零 + 堵转锁存清除 + 航向角清零 |
| **S3** | A21 | **备用翻页**（无遥控时用；同时移动"高亮项"与"已确认页"，避免两者不一致） |
| **S4** | B21 | **急停**（锁存切换）：按一次急停并停机，再按一次解除 |

### LED（高电平点亮）

| LED | 含义 |
| --- | --- |
| LED0 | 底盘正在输出（`chassis_running`） |
| LED1 | 急停锁存中 |
| LED2 | 任一路电机堵转 |
| LED3 | 遥控信号有效（**参与判定的 bit0~bit4** 都在刷新；**J6.6/bit5 闲置、已由 `SIG_VALID_MASK = 6'b011111` 排除，不参与判定**） |
| LED5:4 | 当前遥控模式（**两档**）：`00` 手动接管 / `01` 屏幕光标 |
| LED6 | 底盘使能（接管档 + 油门在中位 + 信号有效 + 非急停 + 未按 S1 停机锁存） |
| LED7 | 心跳（约 0.34 s 翻转一次，说明时钟在跑） |

> **没有独立的"返回"按钮** —— §33 里的"返回"是导航页**辅助菜单的一个菜单项**。
> 硬件保留 J6 整排 6 路，**J6.6 / F19（bit5）闲置**（J6.4 / F18 是 **select**）。

> **当前状态**：代码与仿真已完成（`ht10a_input_tb` **83 项** + `rc_input_tb` **32 项 PASS**：归一化 / 死区 / **两档模式** / 按钮（select+confirm） / 丢信号（含超时后模式退回光标档） / **摇杆拨动菜单** /
> **信号有效性掩码** / 方向取反参数——取反用一个独立对照实例验证，`STEER_REVERSE=THROTTLE_REVERSE=1` 时两路模拟量符号相反而模式与按钮不受影响）。
> ★ **槽位角色映射已由需求方确认，不再是"按设计文档假设"**：接线真源是 `doc\HT10A接线与验收.md` §2，
> 标定参数表见其 §3。槽位定义与默认参数在 `rtl\rc\ht10a_input.v`，本车取值由 `rtl\top\falcons_top.v`
> 的 `u_rc` 例化给出（`CH_*` 是**零起始的 J6 槽位索引**，**不是接收机通道号**）——
> 要改映射就改这两处，不用动逻辑。
> ⚠ 仍需实测的是**行程 / 中位 / 极性**（脉宽、开关档位与按下极性目前都是可调开发默认值，见 HT10A 文档 §6 验收表）。

| J6 槽位 | 接收机 | 引脚 | 角色 | 判据 |
| --- | --- | --- | --- | --- |
| J6.1（`i_rc_pwm[0]`） | CH4 | D19 | **转向**（左摇杆左右） | 1000…2000 µs ↔ −1000…+1000，中位 1500，死区 ±25 µs |
| J6.2（`i_rc_pwm[1]`） | CH2 | E19 | **油门**（右摇杆上下） | 同上（前为正）；另一用途：菜单上下拨动（阈值 `MENU_STEP_TH`=400） |
| J6.3（`i_rc_pwm[2]`） | CH5 / SWA | E18 | **确认按钮** | 脉宽 > 1700 µs 视为"按下"，产生单周期脉冲 |
| J6.4（`i_rc_pwm[3]`） | CH7 / SWC | F18 | **select 按钮**（★ 原记"返回"位，已裁定**没有返回按钮**） | >1700 µs 视为按下（导航页辅助菜单换项；该页尚未实现） |
| J6.5（`i_rc_pwm[4]`） | CH6 / SWB | F20 | **模式拨杆** | **两档**：<1300 µs → 手动接管；其余（含中位与高位）→ 屏幕光标 |
| J6.6（`i_rc_pwm[5]`） | CH8 / SWD | F19 | **闲置不接** | 不参与"信号有效"判定（`SIG_VALID_MASK = 6'b011111`，**bit5 = 0**），插不插线都不影响开车 |

> ★ **接线只以 `doc\HT10A接线与验收.md` §2 为准**（上表是摘要）。转接板 J6 的丝印 CH1..CH6
> **不代表接收机通道号**，两者是两回事。

**开机自检**：上电后 LED3 应亮（遥控信号有效）、LED7 心跳闪烁、屏幕出现菜单。
若 LED3 不亮 → 接收机没通电/没对码/接错通道。

**开车步骤（2026-10-16 改）**：模式拨杆打到**手动接管**（LED5:4 = 00）→ **把油门杆回到中位**
（状态栏不再显示 `请回中位`）→ LED6 亮（底盘已使能）→ 推油门。
**不再需要先按 S1**；S1 现在是"停机锁存"。按 S4 随时急停。

> ★ **启动门禁 / 解锁守卫（2026-10-15 加；2026-10-16 合并后由 `rtl\rc\rc_drive_guard.v` 承担：`ARM_DEADZONE = 100`）**
> 底盘使能（`run_en`）的条件：**手动接管档 + 遥控信号有效 + 油门曾回到中位死区内**
> （`|throttle| ≤ 100`，即归一化 ±1000 的 10%）→ **解锁一次后保持**（之后推油门不会失能）。
> 目的：防止"上电时油门杆恰好停在半位，一切到接管档车就窜出去"。
> **撤销解锁**：切出接管档、丢信号、急停（S4 / ToF）、按 S1 停机锁存 —— 之后再运行要**重新回中**。
>
> | 现象 | 说明 / 怎么办 |
> | --- | --- |
> | 油门没回中位时切到"手动接管"档、底盘不使能，状态栏显示 `请回中位` | 正常 —— 这是门禁在起作用，把杆回中位即可 |
> | 想停车 | 按 S1（**停机锁存**，接管档内有效；再按解除）或按 S4（急停锁存）；把模式拨回**光标档**也会立刻停（`run_en=0`） |
> | 杆已回中却启动不了 | 接收机中位有偏差 → 调大 `rtl\rc\rc_drive_guard.v` 的 `ARM_DEADZONE`（顶层 `u_rc_guard` 例化给值） |
> | 轻轻碰一下就能启动 | 调小该值 |
>
> **★ 开车方式（2026-10-16 按需求方要求改过）**：**把模式开关打到"手动接管"档**（<1300 µs）
> 且**油门摇杆在中位**，底盘就处于使能状态 —— **不再需要先按 S1**（需求原文 §13：
> "当模式开关选择接管车辆控制时，通过遥控器直接控制车辆行走以及转向"）。
> - 油门不在中位时切到接管档**不会动**（状态栏显示 `请回中位`），把杆回中即可
> - **S1 现在是"停机锁存"**：按一次停住、再按一次解除；切出接管档会自动清掉
> - **S4 仍是急停锁存**（最高优先级），解除也要按 S4
> - ★ **模式只有两档**（手动接管 / 屏幕光标），原来的"自动"档已按需求方要求删除
>
> **切菜单 / 切页（两段式，2026-10-16 需求方明确）**：
> - **模式开关打到"屏幕光标"档**后，**油门摇杆向上拨 = 高亮上一项，向下拨 = 高亮下一项**
>   —— 需求原文 §17"使用摇杆上下拨动来切换选项"。
> - **★ 摇杆只移动高亮，必须按遥控的"确认"键才会真正切页**（需求方 2026-10-16 明确）。
>   也就是说：菜单高亮（`menu_sel`）与内容区显示（`page`）是**两个独立状态**，确认键把它们同步。
> - 拨到位后**必须把杆放回中位**才能再拨一次（`MENU_STEP_TH = 400` / `MENU_IDLE_TH = 150`）：
>   杆停在端点不会连续翻页，这是有意的。
> - 手动接管档下摇杆是**开车**，不参与菜单（需求原文 §13：摇杆操作屏幕只在光标档）。
> - **板载 S3 保留为"无遥控时的备用翻页"**；遥控 `select` / `confirm` **不再参与菜单拨动**
>   —— 按 §33 它们属于路径点导航页（切辅助菜单项 / 确认路径点），该页尚未实现。
> - ★ **接管档下按"确认"也切不了页**（需求方 2026-10-16 明确："接管档手柄不做遥控车辆之外的
>   任何交互"）—— `rc_confirm` 与摇杆拨动都限定在光标档。

## 四之二、IMU 链路（已接入：imu660ra → 倾斜补偿 → 偏航角积分）

### 接线（J2 接口，SPI Mode0 四线）

| 信号 | 引脚 | J2 排针 |
| --- | --- | --- |
| `o_imu_sck` | **A14** | J2 SCL |
| `o_imu_mosi` | **A13** | J2 SDA |
| `i_imu_miso` | **A16** | J2 SDO/SA0 |
| `o_imu_cs_n` | **A15** | J2 CS |

> ⚠ **A15 是 J2.6 = IMU CS**，J1 与 J2 同网络 —— 所以雷达 RX 只能用 **C14**。供电 J2.1 = 5 V。

### ★ 三条接线契约（写死在 `rtl\top\falcons_top.v` 注释里）

1. `gyro_tilt_comp.i_sample_valid` 必须接 `imu_top.o_acc_valid`，**不是** `o_data_valid`
   —— `o_data_valid` 只在 RUN 态产生，标定窗口期内一个样本都收不到，会让倾斜补偿
   **永远不生效且不报错**（`car_fpga` 踩过的坑）。
2. `gyro_tilt_comp.i_calib_start` 接 `imu_top.o_calib_busy`。
3. `yaw_integrate.i_sample_valid` 接 `imu_top.o_data_valid`。

`imu_top` 的 **`SCK_HALF_DIV` 显式写 25**（1 MHz）：源码默认 3（8.33 MHz）实测会导致
8 KB 配置加载失败，表现为 `o_err_code = 2`，极易误判成"模块坏了"。

### 上电后的现象判据

| 观察 | 含义 |
| --- | --- |
| 数据页 `航向角` 显示数字（亮绿，整数度） | 初始化 + 零偏标定 + 倾斜补偿都已跑通 |
| 转动车体航向角随之变化 | 陀螺积分正常 |
| 静止时缓慢漂移 | **正常**：纯 6 轴 yaw 不可观测，原理性限制；调 `DEADZONE_TH`（默认 0.3°/s）压小 |
| 按 S2 | 编码器计数 + 航向角**同时清零** |
| 航向角恒 0 / 不动 | 查 SPI 四线（SCK/MOSI 是否接反）与 `o_err_code`（1=通信 2=配置 C=标定 D=倾斜） |

### IMU 参数（都在 `falcons_top.v` 的例化里）

| 参数 | 值 | 说明 |
| --- | --- | --- |
| `SCK_HALF_DIV` | **25**（1 MHz） | 杜邦线必须；稳定后可试 1→2→4 MHz，每次确认 `o_init_done` |
| `SAMPLE_DIV` | 50000（1 kHz） | 陀螺 ODR 200 Hz，1 kHz 读取等价零阶保持 |
| `CALIB_DEV_TH` | 100（1°/s） | 抖动判据；标定失败就调大 |
| `INT_RATE_HZ` | 1024 | 2 的幂 → 每拍零乘法 |
| `DEADZONE_TH` | 30（0.3°/s） | 静止死区 |
| 显示换算 | 整数度 | `yaw_deg = (yaw_raw × 10486) >>> 20` |

  **当前** HOLD 最差为 **−1.026 ns** —— 见上面 **2026-10-16 20:51:52** 那份报告）。
- **RECOVERY 的 8 条是复位释放路径**（改接 `pixel_rst_n` 之后由 **25 条降到 8 条**），只在复位释放瞬间起作用；

  **仍可做的两件事**：① 把复位释放搬进 245 MHz 域（要改 vendor 模块内部）；
  ② 给复位网络加**有理由的**时序例外（复位释放不是数据路径，且 release 由 `pll_lock` 门控保证足够久），
  并在文档里写清依据 —— 这两条都**不是** `set_false_path` 式的无脑掩盖。

**结论：这是 CDC 的结构性现象，不构成功能风险** —— 同步器的第一级本来就允许亚稳态，第二级再采样。

### 写 tb 时踩的坑（共 8 条，供后续加测试时参考）

| # | 坑 | 现象 / 教训 |
| --- | --- | --- |
| 1 | `fork` 的多个并行进程给**同一个 `reg [5:0]` 的不同位**赋值 | ModelSim 下互相覆盖，表现为"所有通道脉宽恒为 0"，而单通道调试台完全正常 → 改成每路一个独立 reg 再拼接 |
| 2 | 脉冲结束后立刻判定 | `rc_pwm_capture` 在下降沿后还要数拍才更新 `pulse_width_us`/`pulse_valid`，帧间隔要留 ≥10 拍 |
| 3 | `#8000` 当 8 ms 用 | timescale 是 1ns，`#8000` = 8 µs；超时测试必须写 `#6_000_000` |
| 4 | ModelSim 输出中文变 `?` | 检查名一律用 ASCII，判定只靠 `pass`/`FAIL` 与数值 |
| 5 | 把"选中项"当"未选中"来测 | 第 1 个菜单项默认选中，文字是亮黄 `FFE066` 而非灰 `E5E7EB` |
| 6 | **仿真清单漏依赖** | `vlog` 逐文件独立编译、不做模块解析 → 少列依赖时**编译全过**，`vsim` 加载才报 `Module 'xxx' is not defined` / `Error loading design`。`speed_report` 的依赖是**两层**：`→ uart_tx_queue → { uart_byte_tx, sync_fifo }`，补一层不够 |
| 7 | **复位后 DUT 自发的一行** | `speed_report` 的 `tick_cnt` 复位为 0，而 `report_tick = (tick_cnt == 0)` → 复位一释放就上报一行（既定行为）。tb 不先丢弃它，之后每次检查都读到上一次的行，表现为**整体滞后一行** |
| 8 | UART 接收进程里"边采边等下降沿" | 字符数据位里也有 1→0 跳变（如 `,`=0x2C 第 3→4 位）→ 必然错位。正确写法：等起始沿 → 连续采 8 位（窗口内不响应任何边沿）→ 回到起点 |

## 八、上板测试顺序建议（第一次跑按这个顺序走）

> 原则：**每一步都要有一个"能不能继续往下走"的判据**，别一步跳到"摇杆开车"。
> 全程 **车轮悬空**（车架空）、**D24A 驱动板 STBY 跳线帽已拔**，落地试跑放到最后一步。

| 步 | 做什么 | 看什么 / 判据 | 不对时先查 |
| --- | --- | --- | --- |
| **0** | 只烧 **SRAM**（`-Action Sram`），不急着固化 | LED7 心跳（约 0.34 s 翻转）、LED3 遥控信号有效、屏幕出现四页菜单、串口有 CSV 输出 | 没心跳 → 位流没下进去；LED3 不亮 → 接收机没通电/没对码/接错通道；无 CSV → 串口波特率或 TX 引脚（M15） |
| **1** | **核对槽位映射与行程**（实际 5 路 + 1 路闲置）：逐个拨摇杆/开关，看串口 CSV 的 `steer` / `throttle` / `mode` 列 | 摇杆推到两端应到 ±1000 附近；回中位清零；拨杆两档 → `mode` = 0/1；**J6.6（F19 / bit5）无跳变是正常的**（闲置未接，已由掩码排除在判定外）。★ **按钮要另判**：12 列 CSV **没有事件列**，`确认` 的现象是"按一下切页"、`select` 当前**顶层未消费**（导航页未实现，按了屏幕上不会有反应）；`J6.4/F18` 单动**不应**改变 `steer`/`throttle` | 槽位对不上 → 改 `rtl\rc\ht10a_input.v` 的 `CH_*`（本车取值由 `falcons_top.v` 的 `u_rc` 例化给出）；方向反了 → 改 `STEER_REVERSE` / `THROTTLE_REVERSE`（同样在 `u_rc` 例化处） |
| **2** | **车轮悬空、拨杆打到"手动接管"档**（油门先回中位），看四轮转向与 `tgt` vs `act` | 推油门四轮**同向**、转速随杆位变化；`tgt` 与 `act` 符号一致；LED6 亮 = 已使能 | 某个轮反向 → `INV_DIR_VEC`；实测与目标符号相反 → `ENC_INV_DIR_VEC`；一给油就报堵转 → 确认已改成 50 窗口；LED6 不亮 → 看状态栏是不是 `请回中位`/`无信号` |
| **3** | **串口 `P/I/D` 在线整定速度环** | 给固定杆位，`tgt` 稳定、`act` 跟上且不振荡；稳态误差 ≤5% | 见 `doc\参数总表与待定清单.md` 第九节第 5 条 |
| **4** | **落地低速试跑 + 保护验证** | 低速直行不跑偏；人为堵住一个轮 → ~200 ms 内停机并锁存（LED2）；**拔掉接收机** → 100 ms 内摇杆归零停车。★ **"关发射机"是另一种故障，必须分别测**：接收机可能保持旧油门，PWM 有效 ≠ 无线在线（failsafe 未实测前不能写"关遥控一定停车"，见 `doc\HT10A接线与验收.md` §4） | 停车时间不对 → 看 `TIMEOUT_US`；堵转不报 → 看 `STALL_*` 阈值 |
| **5** | 功能都正常后再 **固化到 Flash**（`-Action Program`） | 断电 → 拔下载器 → 重新上电 → 现象与 SRAM 一致 | 上电不工作 → 确认烧的是 `impl\pnr\falcons.fs` 且时间晚于最后一次改 RTL |

> ⚠ 第 2 步之前**不要让车落地**；第 4 步之前**不要给大油门**。
> ⚠ 上电后等 **约 3 秒**再动车：IMU 的零偏标定（`CALIB_TIMEOUT_MS = 3000`）要求这段时间静止，
> 标定失败不影响遥控开车，但航向角会漂。
