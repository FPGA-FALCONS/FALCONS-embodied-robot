## 成像与去畸变链路

1. 原生C采集请求UVC输出1280×720 MJPEG，核对驱动协商结果；原始JPEG字节直接写入文件，无软件裁剪或缩放。
2. 识别模型将全幅图等比例缩为640×360，上下各补140行到640×640；检测框逆变换回原始1280×720像素坐标。
3. AI页面将全幅图等比例缩为约661×372，放在816×420内容区的`(77,36)`；没有裁掉相机视野。
4. 录像保存同一渲染路径的标注摄像头与地图画面，并增加时间栏到816×448。FFmpeg中的crop用于拆分并排两路，不是裁剪相机原图。
5. RK显示、识别和录像没有整帧去畸变。生产定位通过`undistortPoints(...,P=K)`校正单点，再用同一K还原射线。
6. Windows的`undistort_check.png`才使用`getOptimalNewCameraMatrix(alpha=1)`、`initUndistortRectifyMap`与remap；输出仍同尺寸，不使用返回ROI裁剪，但new_K改变画面缩放和主点。该预览不能与原始K混用。

实机核对了部署源码SHA与本地一致，驱动报告1280×720 MJPG、crop_bounds为`(0,0,1280,720)`，
当前crop查询不受支持，标准控制未暴露zoom。上述信息不能证明相机固件内部或Windows/RK两后端的光学视野相同。
原图清单SHA核对、模型全画面框逆变换和显示内容区像素对照均通过。

## 初始安装候选与投影公式

用户确认：镜头中心离地20.6cm，相对雷达中心正前方19.6cm，无横向偏移，相对水平向下俯视20°，无可见偏航/侧倾。
原工程文档`自动导航接入方案.md`第5.3节按雷达与odom参考点重合处理；物理安装是否满足该约定仍需验证。

`calib_out/camera_mount_initial.json`保留这组初始候选及当时的旧内参，其内参源SHA属于22:25结果，
不对应当前已更新的`pinhole_calib.json`。它不是运行配置，不可跳过来源和验收检查自动加载。

车体坐标为前/左/上，相机光学坐标为右/下/前。原图像素经K、D去畸变，得到归一化坐标`xn,yn`。
设俯角为θ、光心平移为`(tx,ty,h)`，则：

```text
r_camera = [xn,yn,1]
R_base_camera = [[0,-sinθ,cosθ],[-1,0,0],[0,-cosθ,-sinθ]]
r_base = R_base_camera × r_camera
λ = -h / r_base.z
P_base = [tx,ty,h] + λ·r_base
X_map = X_car + cosψ·X_base - sinψ·Y_base
Y_map = Y_car + sinψ·X_base + cosψ·Y_base
```

本轮静态核对在车体地面求交阶段已出现纵向偏差，没有使用地图位姿变换。
去畸变与地面交点的数学闭环不能证明实际安装外参或成像模式正确。

## 已识别、未实施的定位改进

- 近地平线阈值0.15限制有效范围；降低阈值前须验证远处误差和可用量程，不直接将其改为0.03开放行驶。
- 自动检测锚点缺少画面截断/遮挡检查，`ground_verified=True`缺少逐目标接地点证据。
- 单个目标定位异常需要在逐目标范围处理，避免丢弃整帧其余目标。
- 地图边界写死±6.4m；目前协议地图为12.8m，应与地图配置约定统一维护。
- 当前`max_range_m/xy_error_m`与各项验收标记仍未满足；保持原门禁，不用翻转标记代替标定。

本轮只保存审查和测量结果，没有实施这些运动定位改动，也没有加入整帧去畸变。
