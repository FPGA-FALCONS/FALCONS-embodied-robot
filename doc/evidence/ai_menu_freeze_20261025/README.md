# AI页面菜单冻结样式修复

用户反馈进入AI模块后左侧菜单没有导航页面的冻结样式。

原控制逻辑在AI总开关开启时已经阻止切换左侧菜单；缺失在显示链路：顶层只同步导航交互态，渲染层也只允许导航/参数页采用变暗配色。

本次将AI总开关与导航交互态送入同一两级像素域同步链，渲染层按当前页面区分AI与导航，复用同一组菜单颜色：背景`0B1019`、普通文字`5A6170`、选中文字`8A7A2E`，蓝色选中带不变。返回、手动接管或主机断连导致AI关闭后，菜单恢复亮度。AI功能标签及状态栏不随左侧菜单变暗。

`UI_AI_ACTIVE_SIMULATION.png`与`UI_AI_OFF_SIMULATION.png`是实际RTL仿真预览，分别覆盖开启时冻结、关闭时恢复。预览包含示例文字，不是屏幕实拍。

`BUILD_INPUTS.json`记录本次109个构建输入，`BUILD_STATUS.json`记录同钟域时序通过：系统50.167MHz（要求50MHz）、像素49.023MHz（要求49MHz），所列时钟建立/保持违规端点均为零。生成IP跨钟域路径仍按原工程单独核对，不是全部路径签核。

新位流40727037字节，SHA256为`f1ec6631b1a20617835e664804ca426b26785205163c0c163228259d6ea78c5d`，已通过SRAM Program加载，未写Flash。`SRAM_PROGRAMMING.json`、`sram_program.txt`与`post_program_status.json`记录加载和原RK服务恢复；模型与配置未更改，控制快照及显示确认正常，检查时串口接收错误为零。启动期间记录一次自动显示重传，随后已有持续的显示确认，不把重传计为运动回执。

43项应用仿真及4张RTL页面预览通过。用户对“开启AI后左侧变暗、右侧标签保持亮度、SWA返回或SWC手动后左侧恢复”反馈“全部正常”，详见`OPERATOR_ACCEPTANCE.json`。本次仅验收菜单样式，不扩大为新的运动验收。

## 上电绿纹反馈复核

排查期间用户提到上电数秒出现绿色竖纹，随后明确补充：“问题在上一版位流中有，现在问题没有出现了。”因此按旧版本历史现象记录，未确认其根因，也未据此改动PLL、TMDS或复位链路。

`boot_menu_check_tb.v`及`boot_menu_check.txt`保留诊断：使用真实扫描与UI渲染，前两帧数值RAM保持未初始化，第三帧填入有效数字；374400个菜单像素中绿色与未知值均为零。这仅检查数字逻辑，不模拟HDMI模拟链路、接收端锁定或供电行为，不能证明旧位流绿纹的具体原因。
