# RK前进后退统一速度码30

本次仅修改RK侧应用，不改RTL、约束、位流或FPGA程序。

`motion_intents.speed_for_intent`统一要求所有前进/后退构帧使用速度码30，包括普通、定时及通过原距离标定门禁的指令。文字、ASR、AI页面及独立`semantic_nav/send_motion.py`入口共用该策略，正式后端在发送前也按同一策略重新构帧，不能由调用方的10/40覆盖。

`voice_motion.settings.drive_speed`报告实际直行速度码30；原`speed`继续作为转向/旋转的配置值。STOP、心跳、时长限制及距离标定门禁保持原样，当前板端未完成距离标定，仍拒绝距离执行。速度码30不是30m/s。

通用MOT1协议和冻结参考快照不修改，历史原始帧测试数据中的速度值不能视为应用的实际下发速度。策略版本为`zh-motion-fixed-drive30-3`。

验证使用离线构帧和内存串口替身，不发送真实前进/后退指令。源码部署、板端测试、有效配置与FPGA未改动证据见`doc/evidence/rk_drive30_20261025/`。

2026-10-25已部署到RK的`host_ea8d9394`，板端176项测试全部通过。新服务模型已就绪、控制链路正常，六条运行中API预览的前进/后退帧速度字节均为30，且均为`plan_only`、未发送运动。原配置按JSON逐项保持一致，109个FPGA构建输入与此前已加载位流一致，本次未构建或烧录FPGA。
