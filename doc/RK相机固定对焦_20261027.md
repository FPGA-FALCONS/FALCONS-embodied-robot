# RK相机运行时固定对焦

本次将Windows标定使用的固定对焦位置接入RK正式原生取帧流程。用户确认45张标定原图均关闭自动对焦并固定focus=260；参数对应1920×1080。该数值是设备对焦位置，不是镜头焦距毫米数。

RK现场已按USB身份重新识别原相机`0bda:5856 / 200901010001`。Linux控制`focus_absolute`范围0..1023、步长1，读回260；`focus_automatic_continuous`读回0。控制值合法且与本轮设置一致，不根据Windows/其他设备量程进行猜测缩放。

## 运行行为

正式相机配置为`focus:260, autofocus:false`。在每次打开设备和断线重连时：

1. 按原身份选择相机、协商现有图像模式和帧率。
2. 查询自动对焦与绝对对焦控制，检查是否可写、范围和步长是否接受目标值。
3. 先关闭自动对焦，再设置绝对对焦260，核对两项读回值。
4. 等待1秒让镜头稳定，再启动视频流并丢弃原有预热帧。
5. 每帧输出前重新核对自动对焦仍为0、绝对对焦仍为260；不匹配或ioctl失败则结束当前取帧，由既有相机故障/重连流程处理。

关闭相机不恢复自动对焦。相机掉电或其他程序更改控制后，下次打开仍执行完整设置。未设置focus的旧调用保持兼容；请求固定对焦时，OpenCV后端明确拒绝，不静默忽略锁焦。

帧元数据记录`focus_value=260`、`focus_locked=true`及`focus_verification=v4l2_control_readback_each_frame`。这表示控制寄存器读回，不证明物理画面处处清晰、镜头机械状态正确或完成几何/曝光时间标定。原48字节FVC1帧头不变。

## 影响范围

只更新RK采集代码和相机设置，不改FPGA、引脚、运动协议或模型。原雷达导航、AI四项功能、录像与缓存播报继续使用原有流程。

原RK模式为1280×720 MJPG 30fps，本轮保留该模式。1920×1080标定参数没有直接写入720p运行配置，没有按未经验证的缩放关系套用内参；外参、地面投影和时间标定通过标记保持原值。后续仍需完成成像模式/视野核对及独立验证。
