# AI 模块页面与遥控交互

按 2026-10-24 用户最终修订实现。VRA/VRB 方案已取消，物理接线与原 J6 六路映射一致。

2026-10-25 补充：**高速图像接口不是 AI 页面或总开关的准入条件**。缺少 FPGA→RK 高速数据线时，页面、CH8/SWA/SWB交互、语义运动指令和聊天/扬声器均正常使用；只在目标识别子功能提示图像链路不可用。切回语义导航或聊天会清除该错误，不遗留跨功能封锁。
语义导航与聊天需要 RK 本地模型和已有控制串口；不要求 FX2、相机或高速 USB 数据线。没有图像时不能宣称完成找物视觉验收。

## 操作

1. 在光标档选择左侧第七项“AI模块”，SWA/CH5 下拨确认进入并开启总开关。
2. CH8/select（代码为 `rc_aux_up/down`）上下选择“语义导航、目标识别、聊天机器人”，SWA 下拨确认激活。
3. SWB/CH6 下拨开始录音，上拨结束。先结束录音，再做识别与当前功能处理；最长30秒，保持下拨不会连续重录。
4. SWA 上拨返回，关闭总开关。离开 AI 页面、SWC 手动接管、S1 停止、S2 清零、急停、遥控失效或主机断连也关闭；不保留可自动恢复的 AI 运动。

进入页面、切功能或故障恢复时，若 SWB 已在下拨位置，须先上拨再下拨，避免启动时的高电平形成意外录音。
CH8 高亮只选择候选功能，SWA 确认才切换当前功能；切换会取消旧录音、识别、生成和播报。
手动接管的优先级保持原样，手动档不进行菜单交互。

## 页面与功能

子菜单文字及高亮由 FPGA 本地绘制，选择无需等待 RK3588。任务区经共享串口更新，显示总开关、当前功能/阶段、具体转写指令、目标类别及置信度、聊天回复和不可用原因。
三个功能标签采用24×24大字，分别在216×44选项区内居中；选中项与左侧菜单同为蓝底黄字，取消白色边框。动态任务区仍使用16×16字，以容纳指令与聊天文本。
语义运动期间按后端状态显示“运动指令计时中”，不会在电机指令仍计时时显示待命。该计时不等于物理动作完成回执。
左侧七项保持字号与72像素行距，文字起点由72上移至48；最后一项高亮结束于516，状态栏从540开始，中间留24像素。
原有全部界面文字、字库、数字字库和新增固定子菜单都内嵌 FPGA，不依赖 RK 的启动、网络或 UART。
只有 AI 的任意任务文本使用 RK 上的16×16 GB2312字模，以及 FPGA 的双缓冲512字缓存；没有把整套动态中文字库压入 FPGA。
不改变原数值字库位宽；未支持字符显示问号。长文本按行显示，聊天区显示前五行。

## 本地控制优先级与任务恢复

SWC/CH7 手动档在底盘硬件多路选择器中压制所有自动输出，与 RK 是否响应无关。急停、ToF 与堵转保护继续有效。
切入手动时立即进入本地制动阶段，至少200ms，并在三次新编码器窗口内确认四轮增量绝对值均不大于2；双摇杆回中后，才释放制动并允许原有手动解锁守卫接管。
计时器不能单独解锁，缺少编码器采样也不能解锁；解锁后推杆可正常驾驶，不要求持续回中。遥控失效、急停或离开手动档会清除解锁状态。
这是 FPGA 控制判据；实车停车距离及采样可靠性仍需新版位流现场验收。

| 场景 | 立即处理 | 恢复方式 |
|---|---|---|
| SWC 切手动，处于任意页面/录音/推理/播报阶段 | FPGA 撤销自动驱动并先制动；原导航暂停，AI 总开关关闭；主机收到控制后取消旧进程/播报 | 双摇杆回中、确认停稳后手柄接管 |
| 手动切回光标档 | 原导航仍暂停；AI 保持关闭 | 导航页 SWA 下拨确认继续；AI 页重新确认开启，再选择功能 |
| 原 FPGA 导航运行中 SWA 上拨 | 暂停，点表与进度保留 | SWA 下拨继续；再上拨退出交互态，返回主菜单 |
| 原导航运行中 S1/遥控失效/急停 | 本地暂停；遥控失效直接抑制底盘输出并制动 | 故障解除后明确确认继续；故障未解除时确认无效 |
| AI 页 S1 或 S2 清零 | 本地关闭 AI 并撤销运动 | 重新进入 AI；S2 按原功能清零坐标/计数，不恢复旧运动 |
| AI 录音开始 | FPGA 直接撤销旧运动；主机也优先发 STOP，再录音 | SWB 上拨结束后只执行本次识别结果 |
| SWB 保持下拨/抖动/处于中间阈值 | 两帧分类，保持当前稳定状态；一次下拨最多一段录音，最长30秒 | 先上拨再下拨开始下一次 |
| 进入 AI、切换子功能或故障恢复时 SWB 已下拨 | 不启动录音 | 必须先上拨，再下拨 |
| CH8 只改变高亮 | 当前功能不变 | SWA 下拨才切换；切换撤销旧录音/推理/语音与运动 |
| AI 页 SWA 上拨/离开页面 | 关闭总开关、撤销待执行结果，不自动返回旧导航 | 本地主菜单重新选择所需功能 |
| RK/UART 断连 | 运动桥独立500ms看门狗；主机保活超750ms则 FPGA 关闭 AI；陈旧任务文字最终隐藏 | 原有菜单、手动、相机、雷达、导航、参数页继续由 FPGA 完成 |
| 断连前 AI 曾取得运动所有权 | 保持零速，不暴露旧路线 | 在原导航页明确“开始/继续”产生新启动沿，本地归还控制，不需要 RK 或整车复位 |
| RK 恢复、迟到的 STOP/旧显示事务 | 不重开 AI、不恢复旧运动；迟到 STOP 不夺回已明确交还的本地导航 | 新的 AI 进入确认；文本需完整新事务及有效字模 |
| UART 热拔插或服务启动时尚未接线 | 只在 AI 集成启用时每秒重试原 `/dev/serial/by-id/`，仍使用独占锁，不抢占其他进程 | 重新连接后重置半包/显示缓存/协议能力；先看到 AI 关闭，再明确确认开启；不会重放任务或录音 |
| 无麦克风/ASR失败/无语音 | 显示不可用或未识别，不生成运动 | 修复后重新按 SWB 录音 |
| 无相机/无目标/视觉模型失败 | 目标识别显示不可用/空结果，不把识别当作到达或停车证明 | 相机明确配置后重进目标识别；不虚构实物结果 |
| 聊天/TTS/扬声器失败 | 显示错误，不进入运动解析器 | 修复后重新录音；切出或关闭随时取消 |

AI 任务取消后不复用旧 ASR/LLM 结果；聊天仅在同一次有效 AI 会话内保留有限历史，关闭会话清除历史。
不改变原导航的路径点算法、相机采集、雷达建图和参数整定的 FPGA 实现。

- **语义导航**：转写进入既有规则/C1b及MOT1链路。保留单次运动时长、转角与距离限值；未标定的距离仍拒绝，未接通的巡航/任务回执仍不伪造。
- **目标识别**：启用已配置的相机/YOLO worker，显示识别类别与置信度。录音可以指定四类已支持目标中的某一类；该分支不下发电机命令。未配置或未连接相机时显示不可用，不能视为已通过实物检测。
- **聊天机器人**：使用板端原版 `qwen3.5-0.8b_w8a8_rk3588.rkllm` 与既有 RKLLM 1.3.1，保留有限轮次对话。回答经实时 Kokoro 合成，由明确的 USB ALSA 设备播放。该分支不经过任务/运动解析器。

## UART 合同

仍使用同一个115200 8N1串口、同一个 `SerialPort` 所有者。原12列CSV保持完整行；只有 RK 已发来有效 UI 保活时，AI遥控快照才每100ms插在行间。RK 缺席时输出原有纯 CSV；没有第二个发送器抢串口。

AI消息使用12字节MOT1包络及CRC-16/CCITT-FALSE，但命令号与0..8运动命令分离：

| 命令 | 载荷 |
|---|---|
| 0x50 控制上报 | value低5位依次为总开关、主RC有效、手动、急停、SWB已确认，第5位为已显示的缓冲区，高字节为显示事务确认号；speed低2位为功能0/1/2，第2位为录音，第4:3位为高亮项 |
| 0x40 文本开始 | seq为事务号，value为字符数量（最多828） |
| 0x44 字模缓存 | 相同事务seq，value为16位点阵行；speed与flags第4位构成9位缓存槽，flags低4位为行号；每字按0..15完整上传，必须在字符数据之前 |
| 0x41 文本字符 | 相同事务seq，value为已有效的缓存槽0..511，speed与flags低2位合成10位地址；必须按地址递增 |
| 0x42 文本提交 | 相同事务seq及字符数，只有完整有序事务才提交 |
| 0x43 主机保活 | 维持任务区连接显示，不是运动心跳 |

所有帧仍经 `uart_command_router` 隔离ASCII调参。新增命令不会刷新运动桥的看门狗；原桥仅接受语义合法运动命令，已有未知命令看门狗回归保持通过。
任务文字和字模双缓冲，在像素消隐坐标归零时切换，并等待跨域确认后复用旧缓冲；这保证完整事务的缓冲切换，不是整帧视频同步承诺。主机等待显示事务号与缓冲号匹配才记住缓存；超时会重传，控制链路中断则丢弃缓存。
保留行位置，省去文末空白单元；每20ms最多发送12帧，约7200字节/秒，给保活与优先STOP留出串口带宽。高亮由 FPGA 本地响应，不等待任务区传输。
CRC错误、缺字、字模不全、乱序、事务号不符不提交；主机显示链路超过3秒无消息时隐藏陈旧任务区。
此确认只代表显示缓冲切换，不能当作电机 ACK、运动完成或实物停车回执。
主机物理控制租约默认0.5秒，重复序号不刷新；超时取消录音/推理/播报，并请求STOP。

`gateway.allow_motion`仍只控制FAM1任务，不能当作MOT1总开关。新应用位流本地也要求AI总开关开启且处于语义导航子功能，才允许MOT1运动。
MOT1仍无任务级完成/物理停车回执；UI与日志不把发送、计时器或串口CSV当作动作完成。
关闭AI不会自动恢复旧导航。应用启用 `LOCAL_RELEASE_EN`，只有 AI 已关闭且原导航页出现明确的新“开始/继续”沿、并满足本地安全条件，才释放语音所有权；无需 RK 或整车复位。
通用模块默认仍保留原持有规则。AI 未获得所有权时，关闭状态下的 STOP 也不能抢占原导航。
