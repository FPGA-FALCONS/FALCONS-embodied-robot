# 阶段2B：生产导航控制权与真实回执

本阶段将阶段2A的地图与事务接到整车生产顶层，仍未部署、烧录或发出实车运动指令。页面与RK运行服务整合属于后续阶段。

## 控制权与交互合同

- 巡检页面先取得零输出控制权，要求现有点控制器经历 STOP 请求及 done 低→高的实际完成握手。释放 STOP 后等待控制器空闲、done 清零，再发布目标，防止将旧完成状态当成新命令完成。
- GOTO 必须绑定当前session、定位epoch、递增task/command、已提交图层版本、速度码30、标定完成标志和本次物理SWA确认令牌。已经授权的同一任务可以继续检查点；新任务必须有新确认，不能复用旧任务授权。
- SWC手动、传感器失效、链路失效、500ms租约超时、定位重置及本地暂停都会在FPGA撤销运动输出，不等待RK。手动接管仍经过原有底盘停车/回中守卫；AI总开关和页面由交互层保留。回光标档不自动恢复巡检。
- 视觉更新使用内部暂停（CONTROL flags bit9），保留同一任务授权；操作员暂停、手动、取消、故障均消耗令牌并撤销授权。只有停稳后才能上传，只有全图校验完成后才能使用新版本。
- 巡检输出单独寄存并限制前后中心速度为±120（既有MOT1速度码30映射为30×4）；不修改原非AI导航的速度和控制流程。

## 生产连接

`inspection_application`组合独立事务接收、同步包RAM读取、命令鉴权、导航控制状态机、状态快照和串行发送。顶层复用现有雷达定位、八方向规划和点控制器；没有第二套电机接口或RK导航搜索器。实际传感器有效信号透传至巡检准入。

STATE=81h包含session/task/epoch/command/status/layer/flags/error；CAPS=80h报告协议和当前代次；POSE=82h报告epoch/sequence/32位微秒时刻/x_mm/y_mm/yaw_cdeg/valid。位姿时间按已有定位更新拍锁存，不将串口接收时刻冒充采样时刻。两端时钟的对齐与溢出处理仍由后续RK适配完成。

UART发送器默认保持原实现，生产顶层明确开启巡检选项。CSV一整行、原AI控制帧、巡检的BEGIN/DATA/END整个事务相互仲裁，事务内部不夹入CSV或旧控制帧。串口仅供低速控制和调试，不发送视频。高速端不能将两条接收字节流交错送入一个解析器，后续需独立解析及完整消息仲裁。

## 验证记录

1. 整车完整59台回归通过；随后增加生产组合实例的Python字节向量测试与新任务令牌隔离，复核应用6项、控制20项、分派7项、视觉地图14项、真实Dijkstra4项均通过。当前测试入口共60台。新增UART混流3项、状态发送3项此前均通过。
2. RK软件210项回归通过，Windows跳过10项Linux/硬件相关测试。没有把跳过项写成已通过。
3. 早期整车构建暴露并修正两项工具/逻辑问题：事务超时计数器误放复位分支；视觉RAM推断成芯片不支持的read-before-write模式。前者增加强制写阻塞超时回归，后者采用明确写优先旁路，导航写期间本来就不发布读响应。修正后的整车综合和物理约束检查通过，已进入布局布线。
4. 构建快照/输入清单位于 `build/inspection_stage2b/build_source_v4` 与 `BUILD_INPUTS_build_source_v4.json`，日志为 `build_v4.log`。该提前测量快照早于最后的新任务令牌隔离改动，不能作为提交后完整RTL的最终Fmax或可烧录凭证；后续最终构建需覆盖全部交互改动。当前不宣称整车时序收敛。

生产硬件仍使用原已加载位流；本阶段源码的真实串口、地图、底盘和现场表现尚未进行板级验收。
