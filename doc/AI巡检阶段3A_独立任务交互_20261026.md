# 阶段3A：保留原AI功能，增加巡检子页

AI模块总页仍为 **语义导航 / 目标识别 / 聊天机器人**。本阶段没有删除、替换语义导航或聊天机器人，也没有修改其模型或语音业务流程。仅在确认“目标识别”后进入新的“目标识别/视觉巡检”子页，子页标签为摄像头/雷达地图/文字清单。

子页增加本地大字标题“目标识别/视觉巡检”和“返回/暂停”，明确页面层级。标签、标题及提示字形全部存放FPGA；标签继续采用居中大字、蓝底黄字高亮，左侧菜单按原冻结样式显示。原AI总页的三个标签与原有全部非AI字库保持可用。

## 交互与协议

- CH8在总页选择原三个功能，在巡检子页只切三个视图；SWA确认不再改总功能。子页SWA返回交给RK任务状态机，运动或等待启动时同时走FPGA本地暂停路径。
- RK只有在实际停稳（或尚未取得巡检控制权）后才能请求关闭子页，且关闭请求绑定session/epoch及递增revision，旧请求不能重放。返回总页后总开关仍开启，可继续选语义导航或聊天机器人；总页返回才关闭总开关。
- 尚未建立巡检会话时，SWA返回允许本地退回总页，避免旧版RK只发原控制心跳时卡在子页。建立会话后的运行/暂停/取消由任务状态机处理。
- SWC手动保留总开关、子页与视图，屏蔽页面操作并停止录音；回光标不执行任何恢复命令。丢RC、急停、RK失联仍按既有规则关闭AI。
- 新增UI_CLOSE=7，words为session/epoch/revision/1。此消息只管理页面，不授予运动权限。
- 新增INPUT=83h八word快照：session/epoch/event_sequence/flags/axes/button_counts/user_token/vehicle_params。flags为bit0子页、bit1手动、bit2总开关、bits5:4视图、bit6录音、bit7RC有效、bit8任务页许可；bit3和其余位保留为0。axes低16位转向、高16位油门，均符号扩展；button_counts低16确认次数、高16返回次数；vehicle_params低16车宽mm、bits23:16前探格数。计数器用于避免遥控短脉冲在100ms上报中丢失，不能将累计差值全部排队执行。
- 不借用原AI控制帧保留位；原0x50控制帧合同不变。CAPS能力bit2表示支持上述子页输入。

## 验证与边界

新增独立子页RTL12项，包含退出巡检后仍能选择并确认**聊天机器人和语义导航**；生产组合实例10项包含输入快照、运动中拒绝关闭、停稳后允许关闭及拒绝旧revision。原AI控制23项、显示15项均通过，Python输入合同7项通过。

实际RTL渲染总页和巡检子页各四张画面，自动检查三个大字标签的居中、蓝底黄字、左侧冻结及状态栏间距，并人工查看子页预览。生成命令为 `python tools/preview_ai_ui.py [--inspection] --out <输出目录>`，模拟内容明确标为仿真数据，不是摄像头或实车巡检结果。

最终复核：整车完整61台RTL回归通过，RK软件211项通过执行（10项Linux/硬件相关跳过）；最后标题与本地退出改动已包含在独立快照v6中，真实Gowin整车综合通过。与拉取的共享主线比较，原 `runtime.py`、`ai_module.py`、`startup.py`、`worker.py` 业务实现字节未变。

阶段3A只完成本地交互和主机协议基础。高速图像/DDR显示与RK任务状态机整合尚未完成，不能把此阶段单独部署后声称巡检功能可用。旧快照v4布局布线仍未产出最终报告，它早于本阶段，不作为当前源码的时序凭证；最终布局布线/Fmax需要在后续整合后验证。本阶段不烧录、不替换板端正在运行的语义导航与聊天服务。
