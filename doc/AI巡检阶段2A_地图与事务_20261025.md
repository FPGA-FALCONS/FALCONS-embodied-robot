# 阶段2A：视觉地图与事务接收核心

本阶段完成可验证的FPGA地图/协议核心，尚未把巡检命令接到生产顶层的控制权和串口回执。默认 `AI_LAYER_ENABLE=0` 保留原导航路径；后续顶层接入时明确置1并连接全部端口，不将未完成的接口当成已部署功能。

## 已实现

- `nav_visual_layer`独立raw/cost双bank，总逻辑容量32KiB；后台按顺序接收4096个32位word，逐位写同步RAM并逐位计算IEEE CRC32。全量、CRC、raw包含于cost、定位代次、版本和实际停车均校验后，再等待已接受读事务排空，原子切bank。坏包不覆盖前台。
- 现有 `nav_top`共享地图读响应增加寄存器合成阶段，规划、路线/居中复核及前探共用有效地图。原雷达地图存储不被视觉写入。图层提交或AI启用状态改变都会改变合并版本并撤销旧路线/在途复核，不只修改显示或搜索。
- 正式包装层透传可选AI端口。关闭该编译选项时不实例化视觉RAM，并使用原读延迟；开启后多一拍有效数据响应，不增加组合地址链。
- `inspection_packet_rx`接收保留MOT1信封命令60/61/62，沿用既有UART二进制隔离，负载不会混入ASCII整定。每包CRC16、整事务CRC32、有限32个word和同步读RAM；事务CRC每拍处理一字节，避免整word32轮串联。
- RK `inspection.wire`提供编码、重同步/超时、图层分块、控制/状态合同。它不使用运动命令0..8，也不改冻结MOT1参考快照。

## 事务v1

一个12字节MOT1信封的原value/speed/flags四字节统一解释为payload32（大端）。BEGIN的payload为type8/count8/zero16，DATA为一个uint32，END为IEEE CRC32，覆盖BEGIN四字节及全部DATA四字节。信封序号在同一事务内相同；每个信封保留原CRC16。1..32个DATA word，禁止半事务提交。

| 类型 | words |
| --- | --- |
| HELLO=1 | session |
| CONTROL=2 | session/task/epoch/command/flags/goal_x_cell/goal_y_cell/layer_speed |
| LAYER_BEGIN=3 | session/task/epoch/command/version/full_crc32 |
| LAYER_DATA=4 | session/epoch/version/word_offset，后接最多28个数据word |
| LAYER_COMMIT=5 | session/task/epoch/command/version |
| HEARTBEAT=6 | session/task/epoch/command |
| CAPS=80h / STATE=81h / POSE=82h / INPUT=83h | 后续应用接入使用的能力、真实执行回执、位姿和物理交互 |

CONTROL flags低8位为goto=1/pause=2/cancel=3，bit8表示RK已通过全部标定/时效条件，高16位绑定物理确认令牌。layer_speed低16位为图层版本，bits23:16固定为30。目标直接发8位格坐标，避免FPGA运行期除50；RK先将用户毫米位置换算并保留显示坐标。

图层顺序为8192字节raw，再8192字节cost；x先递增，字节内低位是较小x。LAYER_DATA的数据word从图层字节按小端构造，再作为uint32由事务大端传输。图层CRC对原16384字节计算。

UART形式仅作为有界的接入/回放及低速调试路径，全图会占用数秒；同样事务可由后续高速OUT接收后提交。不得用UART传视频，不在行驶时上传半张地图。正式执行需阶段2B的控制权、停车、租约和回执接入。

## 验证与时序工作

1. 完整整车应用55台回归通过；相机翻转、语音运动、手动接管、原导航和UI均包含在原回归集。随后去除仿真源列表重复项，新增三台26项复核通过。
2. 新增事务接收8项、地图层14项、真实导航集成4项。真实集成将Python产生的完整地图写入RTL，在**零雷达命中**时使现有Dijkstra绕开仅视觉可见的墙；逐段检查路线没有穿障。关闭AI后恢复原雷达空地图直行路线。
3. Python协议6项通过，覆盖碎片/坏CRC/短包/超时、全图分块重建、小端位序、物理令牌及真实停稳标志。向量可由 `sim/gen_inspection_vectors.py` 重建，不把RTL自造数据当主机互通证据。
4. 在独立目录提前运行地图层真实Gowin综合：210 REG、93 ALU、235 LUT、16 BSRAM、0 DSP，RAM正确推断。该结果只对应地图层，不是整车资源或Fmax；尚未报告新整车时序收敛。

本阶段不烧录、不切板端服务、不发送运动指令。验证日志和综合产物位于 `build/inspection_stage2/`，不把软件/RTL结果替代实际USB、标定或地面绕行验收。
