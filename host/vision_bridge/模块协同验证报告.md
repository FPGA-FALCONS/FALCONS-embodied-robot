# 视觉观测与 FPGA 模块协同验证

日期：2026-10-18。结果：**主机适配器与离线 RTL 联合仿真通过，尚未硬件联调。**

## 实际完成

实际路径为：既有双模型真实推理 JSONL → `bridge.py` 字段/类别/状态校验 → 目标有效位、类别 ID 与 TTL → 仿真向量 → 独立 RTL 观测邮箱 → 模拟类别 LED。测试同时实例化规范 GitHub 仓库中的真实遥控守卫、底盘控制、PID 和 UART 命令解析模块，确认视觉观测不能改变手动目标或越过安全约束。

这是一条可重新运行、可以换成新训练模型 JSONL 的数据链。没有用类别猜测前进/转向命令，也没有产生串口发送或 FPGA 烧录。

## 验证覆盖

- 四类 ID、有效 `VERIFIED/target_confirmed` 与 `TRACKING/accept`。
- `VERIFY_PENDING`、`UNCERTAIN`、`TIMEOUT`、无检测、非法 JSON 的立即撤销。
- YOLO/Qwen/融合类别不一致；假布尔值、错误版本、无穷/NaN 置信度及非法框。
- 重复 `frame_id`、重复/乱序 `source_seq`、过期源时间、未来时间和单调时钟倒退。
- 300 ms 目标 TTL 在第 299 tick 有效、第 300 tick 失效；短源寿命 TTL、超长 TTL 钳制和零 TTL 拒绝。
- 视觉结果更新、冲突或失效，不改变手动目标 `left=right=1536`（测试油门 +500，沿用仓库 Q10 换算）。
- 急停使能清零并刹车；解除后必须重新回中；堵转禁止输出；遥控丢失后非中位恢复不能解锁。
- 生产自动接口接 0，因此自动模式保持无目标、不启动。
- 真实 `uart_cmd_rx` 将 `T300` 解析为内部单位 3075，但顶层目标输出未连接，不能用它宣称串口可以遥控车辆。

## 对线上工程现状的核查

本地工作分支尚未切换到线上新提交；测试直接读取线上提交已经 fetch 到本地的 Git 对象，没有覆盖队友文件。

线上 `falcons_top.v` 没有视觉接收器，自动导航三端口接 0；UART 的目标/闭环模式/开环占空比/立即回读输出悬空。**该提交还把 `tof_estop` 接成常量 0，未接 ToF 测距急停。** 本次没有恢复或改变这个差异，也没有把旧版 ToF 代码计为新版本通过项目。急停测试是注入已有通用急停输入，不是传感器测距链测试。

工作中出现的 `rtl/ai/`、`tools/ai_vision_frame.py` 等来自并发工作，已保留。本次仅新增 `host/vision_bridge/`，没有修改生产 RTL、CST 或已有遥控映射；下面的追加试验只认证其明确固定提交的候选解析器与当前安全桥协同，不认证或改写并发作者的编码器。

追加测试发现且保留两项现状：重复 wire seq 会被再次接受；超时后原始 `o_target_valid=1` 仍可保持，而 `o_link_alive=0`。测试消费者明确使用二者的逻辑与，最终有效位为 0。CRC 损坏的帧不能更新目标，合法冲突撤销帧可以清目标。候选解析器仍需板端防重放与更清楚的原始/有效目标接口，不能因为这项联仿通过就用于自动驾驶。

## 后续真正上车前还差什么

1. 为实际视频生产者提供采集时间与序号。当前 POC 图片 JSONL 不具备可信时序；本次回放采用合成时间轴，不能证明实时延迟。
2. 明确并实现实际传输协议、接收解析、CRC/帧检查、板端独立 watchdog。这个邮箱只接收归一化并行信号，不是 UART/JSON 解析器。
3. 将目标观测交给已定义的行为/规划器；类别不等于速度。自动使能、限速、遥控接管和急停优先权要在顶层有明确连接。
4. 与队友确认线上 ToF 回退的原因，再决定恢复方式和完整安全回归。
5. RK3588/RKNN/RKLLM 实际部署、摄像头异步链、真实串口与车辆测试。

本目录提供的软件/仿真交付可继续扩展；目前不能宣称“视觉已控制 FPGA 实车”。
